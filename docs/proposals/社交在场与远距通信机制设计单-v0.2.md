# 社交在场、空间距离与异步通信机制设计单 v0.2

- **状态：** 完整审查稿／待产品负责人确认
- **权威基线：** 根目录《设计总纲.md》v0.3
- **前序提案：**《社交在场与远距通信机制提案-v0.1.md》
- **性质：** 已与权威总纲的核心循环、人物知识、关系三问、统一时间、行动留痕和 M1 范围进行冲突审查的完善稿；仍是提案，不替代权威总纲。
- **范围约束：** M1 仍为“一县、七人、十日、一汛”。不扩展为全国地图、完整驿递系统或全员实时位置模拟。

## 0. 审查结论

本机制与总纲整体一致，尤其强化 P-01 人物优先、P-03 关系具有方向性、P-06 人物知识不全局共享、P-07 时间由行动驱动、P-09 结果可追溯、P-11 统一人物内核、P-16 四段式互动判定、P-17 一切留痕和 P-18 单一权威源。

审查后必须修正六个风险：

1. “同场”不等于“必然能交谈”。还要检查场景可达性、人物日程、忙碌状态、身份阻拦与交谈意愿。
2. “异地联系”不是一个按钮，而是发起、运输、送达、阅读、处理、回复和回程组成的异步事件链。
3. 时间、费用、关系变化和认知更新必须由确定性规则结算；AI 只能在规则结算后叙述，不能凭文本改变业务事实。
4. “未回复”不等于“拒绝”，“送达”不等于“阅读”，“阅读”不等于“相信”。
5. M1 不启用复杂截信、伪造、密码、全国路线和通信网络模拟；只保留必要扩展点。
6. 必须分开记录人物真实位置、玩家所知位置、联系渠道是否可用、对方是否愿意接触、对方是否已收到消息。

## 1. 目标与非目标

### 1.1 目标

- 现场人物可被即时询问，但不保证愿意说、敢说或说真话。
- 同县不同地点的人需要寻找、前往、候见或托人联系。
- 远方熟人只能通过世界允许的渠道联系；消息需要时间抵达，对方也需要时间处理。
- 玩家权衡速度、费用、保密性、可信度、正式性和机会成本。
- 玩家获得的信息有来源、有时间、有可信度，而不是全知叙事。
- 社交动作可以改变人物关系、债、知情状态、社会传闻和后续行动可能性，并留下事件记录。

### 1.2 非目标

M1 不做全国地图、全体 NPC 实时坐标、逐站驿程仿真、完整清代邮驿考据、复杂截信与反间谍玩法、所有 NPC 每日自动通信或繁琐的信件管理模拟。不得把每次交谈拆成高频计时器，也不得用单一好感值决定能否联系、是否回复或消息真假。

## 2. 统一联系判定流程

所有“联系某人”的意图都经过同一确定性流程。

1. **识别目标。** 人名有歧义时先消歧，不得随机选人。
2. **检查位置知识。** 分开判断目标的真实位置、玩家已知的位置及来源/时间/可信度。内部真实位置不能自动泄漏给玩家。
3. **确定动作是否存在。** 同场可交谈；同县不同场景可打听、寻访、登门或托人；异地可书信、托可信中间人、适用的正式公文或亲自前往。
4. **检查能否执行。** 检查时间、费用、渠道、身份权限、物件、路线、承运者与当前阻断事件。
5. **检查意愿与风险。** 沿用总纲四问：动作是否存在、是否可执行、对方是否愿意/敢于、实际影响是什么。不得把四问合并成“关系不够”。
6. **预览后确认。** 展示预计耗时或区间、费用、时限影响、延误风险、信息暴露和可能失败结果。预计时间不是承诺。
7. **确定性结算。** 规则层生成世界事件、资源变化、消息状态、认知更新与留痕；AI 仅根据结算结果生成叙事。

若预览后、提交前世界状态发生变化，必须重新校验。

## 3. 位置、在场与可接触性

### 3.1 位置层级

概念层级为：地域 → 行政区域 → 聚落/县城 → 场所 → 具体场景实例。M1 只需县衙、河工现场、粮商铺面、居所、城门/驿路等少量离散地点节点，不需要自由行走地图。

### 3.2 状态必须分离

建议至少分开维护：

- 权威世界中的实际位置；
- 停留、途中、临时外出等移动状态；
- 可接触、忙碌、休息、受阻、拒绝等可用状态；
- 玩家所知位置、信息来源、获知时间与可信度；
- 人物日程或预计出现时段；
- 玩家是否有权进入该场所或接触此人。

位置、可见性、场所准入和交谈意愿是不同判定。名录中存在人物不代表此刻可交谈。

### 3.3 M1 简化

- 核心七人使用少量离散地点与预设日程。
- 背景人物可以作为传闻或通信对象，不要求全部具备逐时位置。
- 人物移动由具体事件触发，如前往河工现场、奉差离县或回府休息。
- 位置未知时允许玩家打听，但不得为便利直接提供精确位置。
- 玩家前往后若发现目标已离开，应按真实状态处理，并给出有依据的后续线索。

## 4. 通信渠道与成本

### 4.1 不采用无依据的固定天数表

耗时由地点/路线、等待承运者、渠道速度、天气或事件阻断、优先级和世界时间尺度共同决定。M1 可以用简化耗时参数，但必须标记为游戏参数，不得冒充史实。

预计总耗时可拆为：等待承运者 + 运输时间 + 收件方处理时间 +（若要求回复）回复运输时间。玩家只需看到可读的预计时间区间与主要不确定因素。

### 4.2 渠道矩阵

| 渠道 | 适用范围 | 优势 | 成本与限制 | M1 |
|---|---|---|---|---|
| 同场交谈 | 同场且可接触 | 即时、可追问、可观察 | 对方可能不愿说；旁人可能影响表达 | 必做 |
| 县内寻访/登门 | 同县不同场所 | 可当面核实 | 寻找、路程、候见；可能扑空 | 必做 |
| 普通信件 | 有可用收递路径的异地对象 | 可传递具体内容、留下记录 | 慢；内容可能过时；送达不等于阅读 | 最小闭环 |
| 托共同熟人转达 | 有可用中间人 | 引荐、改善接触机会 | 依赖中间人；可能延误、改述或泄露 | 简化版候选 |
| 差役/商旅捎带 | 有合适承运者与路线 | 利用既有行程 | 发出时机不稳定；费用或人情成本 | 后续 |
| 正式公文 | 符合制度与身份的公务事项 | 有正式流程与程序记录 | 不可用于绕过权限的私人联络 | 复用既有公务流程 |
| 亲自前往 | 玩家可离开当前地点 | 直接核验与会面 | 高时间/资源成本，当前事务继续推进 | M1 暂不扩展离县旅行 |

### 4.3 失败策略

M1 优先实现可解释的目标不在、延迟、无回复、过期和退回。遗失、截获、伪造等高随机风险后置。若未来加入，必须追溯触发条件与证据，不得用不可解释的随机吞信推动关键剧情。

### 4.4 私人通信与正式公文分离

私人书信不能自动获得官府公文的优先级、法律效力或权限；正式公文也不能因为玩家认识收件人就绕过层级、程序与授权。渠道决定传播方式，不自动授予所谈事项的法定权限。

## 5. 异步消息状态机

### 5.1 建议状态

草拟 → 已提交/待发出 → 途中 → 已送达 → 已阅（有规则证据时）→ 等待回复（仅在要求回复时）→ 回复途中 → 完成。

异常终态包括退回、过期、明确失败。遗失、截获等状态暂留后续阶段，不要求 M1 启用。

### 5.2 状态语义

- 送达不等于阅读。
- 阅读不等于理解。
- 理解不等于相信。
- 未回复不等于拒绝。
- 回复已写不等于回复已送达。
- 消息失效不代表相关客观事实失效，只表示该通信尝试不能按原目标完成。

### 5.3 最小数据契约（概念）

每条通信至少需要：唯一消息 ID、发送者、接收者、渠道、目的、发起世界时间、发出地点、目的地点、内容引用、当前状态、预计送达区间、真实送达/阅读时间、是否要求回复、回复截止时间、父消息 ID、关联事件 ID、参数版本。

这是概念契约，不要求照抄为代码。必须复用项目已有的世界时间、事件与状态类型；不得为通信模块另造时间轴。消息主体保存当前状态与关键时间戳，详细状态变化进入统一事件日志，避免多个权威副本。

## 6. 信息如何进入人物认知

通信必须连接总纲四层认知：

1. 客观状态：实际发生了什么。
2. 人物认知：人物亲历、收到、听说或推断了什么。
3. 玩家认知：玩家已获知哪些信息及其来源。
4. 社会传闻：哪些内容在关系网络中传播、何时传播、传播到谁。

每条认知记录应区分信息主张、来源类型、来源人物/事件、信息对应的事件时间、接收者获知时间、可信等级和有效性状态。

**核心规则：消息传递的是某人在某时刻表达的内容，不是自动把内容写入客观事实。** NPC 收信后可以误解、怀疑或不相信；玩家收到转述也不等于知道原话。

### 6.1 过时信息

若河工状况在信件途中变化，信件仍保留写信时的内容。接收者需要判断其是否仍适用。不得把旧消息悄悄改写成最新事实。

### 6.2 中间人转述

原始发言、转述内容、转述时间与接收者分开记录。M1 可用少量预设失真模板，不必实现复杂自由传播网络。

### 6.3 玩家可见性

界面不得显示玩家无依据知道的真实投递节点、收件人是否读信或 NPC 私下回复意图。可显示预计送达、尚无回信、有人称昨日见过他等有来源支撑的状态。

## 7. 统一时间与事件结算

### 7.1 一个权威时钟

所有行动和通信复用总纲的世界时间。通信不得创建独立计时器，不得让动画或现实秒数决定投递。

### 7.2 事件类型建议

概念事件包括：通信创建、发出、送达、阅读（仅有证据时）、回复创建、退回/过期、人物位置变化、人物可接触状态变化、信息获知。实施时必须复用项目既有事件命名和记录格式。

### 7.3 顺序与幂等

- 每次行动/通信有唯一 ID 与稳定命令 ID。
- 同一命令重复提交不得重复扣费、创建多封信或重复改变关系。
- 送达事件必须检查当前状态；已退回或失效的消息不能再次送达。
- 世界时间跨过多个事件节点时，按确定性顺序结算；相同初始状态与事件序列得到相同结果。
- 若送达与人物调任、离场或事项截止相撞，必须有明确事件排序规则，不得依赖异步执行的偶然顺序。
- 预计送达与实际送达分开保存，估计值不得作为真实事实。

### 7.4 与既有时钟的关系

等待回信可能错过河工节点；寻访会占用行动时间；消息送到时事件状态可能已改变；紧急渠道不能无代价暂停其他时钟。不得另造一套独立倒计时系统。

## 8. 关系、人情与留痕

每次联系可能让目标知道玩家正在打听、让中间人知晓双方关系、让旁观者看到会面或送信，或形成债、书信证据与传闻。但这些后果不能自动全部发生，必须按场合、参与者、可见性与具体行为结算。

关系不能简单等同于通信速度。关系可能影响渠道可用性、是否愿意帮忙找人、是否优先处理、是否提供真实信息、是否承担转交风险、是否解释延误；距离、路线、身份权限与承运条件仍是独立约束。

不能因为玩家点了“交谈”就让全县所有人都知道。关系计算沿用总纲多维关系和三问模型，不新增万能好感值。

## 9. M1 最小实现

### 必须有

1. 核心七人使用有限地点节点与日程。
2. 同场可接触时提供直接交谈入口。
3. 同县不同场所必须先寻访、前往或候见，并消耗既有行动时间。
4. 基本书信可发出、进入途中、送达；发出不能直接让收件人知情。
5. 收件人只有在消息送达后，才能依据消息内容改变认知；是否回复由人物状态与规则决定。
6. 玩家能查看消息状态、发送时间、预计送达区间、已知结果和信息来源。
7. 时间推进时县域治理事件继续结算。
8. 关键状态变化进入统一事件记录，并有幂等保护。
9. AI 叙事不能让未收到信的人引用信中内容。

### 明确不做

全国人物位置服务、真实道路网络、逐站驿程、多级公文全流程、复杂截信泄密伪造密码、所有背景 NPC 的实时日程和自动通信、复杂信件编辑器。

### M2+ 候选

多渠道投递、可信中间人、可解释延误/退回、正式公文链路、保密与证据真实性、跨县旅行和更大范围空间网络。进入 M2+ 前，必须先验证 M1 的“在场—行动—时间—知情—反馈”闭环可玩且可读。

## 10. UI 可读性

人物交互面板优先显示：
- **所在情况：** 就在现场 / 据说在县城东街 / 昨日离县 / 位置未明；
- **可采取动作：** 交谈 / 前往寻访 / 写信 / 托人递话；
- **代价预览：** 约半个时段 / 预计 2–4 日 / 需费用或人情；
- **消息状态：** 已送达 / 途中 / 尚无回信 / 仅为转述；
- **来源与时间：** 来源于谁、何时获知、信息对应何时。

避免将 NPC 真实坐标当作玩家已知信息；混淆预计与实际时间；把新信、未读、紧急和失败塞进同一个红点；把无回信暗示为关系破裂；让所有渠道只差一个耗时数字而没有策略差异。

## 11. 验收用例

### 同场接触
- A1：目标同场、可接触且有空，交谈入口出现。
- A2：目标正在处理紧急公务，提供等待或改约，而不是伪装成不可见。
- A3：目标拒绝交谈时，只展示玩家有依据知道的原因。
- A4：旁人在场时可提示私密话题的暴露风险，但不默认旁人必然听清。

### 寻访
- B1：目标在同县另一地点，必须先寻访/前往/托人。
- B2：位置消息过期导致扑空时，按真实状态处理并给出合理后续线索。
- B3：位置未知时不得直接展示精确地址；打听结果有时间与来源。

### 书信
- C1：发信只创建消息和运输事件，不直接写入收件人知识。
- C2：送达后先记录收到；阅读、理解和相信分开处理。
- C3：不回复时保持等待/无回复，不自动判定拒绝。
- C4：回复是独立消息，有自己的送达过程。
- C5：事项在信件抵达前已过期，保留原信并标记过时，不修改内容。
- C6：同一命令重放，不重复扣费、生成消息或改变关系。

### 世界与官场规则
- D1：等待回信时，河工期限与其他事件继续推进。
- D2：正式公文经过权限和程序检查，私人关系不能绕过审批。
- D3：转述与原始发言分开保存。
- D4：叙事模型尝试让未收到信的人引用信中内容时，规则层拒绝该状态变化。
- D5：若后续支持远行，玩家离开时县务不会暂停。

### 可读性
- E1：玩家能在 3 秒内区分同场可谈、同县需找、异地需通信。
- E2：预计耗时、已发生耗时与实际送达时间不会混淆。
- E3：玩家能分辨亲历、原信、转述和传闻。
- E4：延迟/失败有可解释原因；若原因未知，就明确标注未知。

## 12. 风险与防护

| 风险 | 后果 | 防护 |
|---|---|---|
| 混淆真实位置、可接触性和玩家所知位置 | NPC 或玩家全知、错误交谈 | 独立状态与认知记录 |
| 发信等同送达 | 破坏信息差与时序 | 异步状态机 |
| 通信另设时间轴 | 事件顺序冲突、期限失真 | 复用统一世界时钟 |
| 过度模拟物流 | M1 失焦、界面繁琐 | 离散节点与少量渠道 |
| 延迟完全随机 | 玩家感到系统刁难 | 先做可解释确定性规则 |
| 所有消息都必须回复 | NPC 机械、消息量爆炸 | 回复请求可选，按人物目标处理 |
| 关系决定一切 | 关系变成万能数值 | 分离关系、空间、渠道与权限 |
| AI 自行编造通信状态 | 业务事实不一致 | 规则先结算、AI 后叙述 |
| UI 暴露 NPC 真实位置/认知 | 信息差失效 | 只渲染玩家有依据知道的状态 |
| 重复处理消息 | 重复扣费、重复记忆 | 唯一 ID、幂等键、状态校验 |

## 13. 待裁决项与建议默认值

| 决策 | 建议默认值 | 理由 | 影响 M1 |
|---|---|---|---|
| 时间粒度 | 复用总纲既有时段/世界时间 | 避免双时钟 | 是 |
| 同场交谈耗时 | 复用现有“问/请/托”等动词成本；纯观察是否耗时另测 | 保持行动一致 | 是 |
| 县内寻访成本 | 先用离散时段，不做逐分钟路径 | 易读、可测 | 是 |
| M1 远距渠道 | 一种普通书信，耗时用明确标记的游戏参数 | 验证闭环而非物流 | 是 |
| 熟人捎信 | 第二渠道候选，复杂度过高则延后 | 控制范围 | 是 |
| 失败处理 | 先做扑空、延迟、无回复、过期；遗失/截获后置 | 可解释 | 是 |
| 位置可见性 | 只显示有来源支撑的位置知识 | 维护信息差 | 是 |
| NPC 主动写信 | M1 不做广泛自动通信，仅允许少量预设事件 | 控制消息量 | 是 |
| 关系与送达速度 | 不直接加速运输；影响渠道、处理意愿和回复意愿 | 分离物理距离与关系 | 是 |
| 历史渠道细节 | 未选定基准时期前不硬编码史实参数 | 避免年代混用 | 是 |

## 14. 建议纳入总纲的摘要（待批准）

> **社交在场与通信原则：** 人物接触受场景、位置、日程、接触权限和意愿约束。玩家与人物同场且可接触时可直接交谈；同地不同场景需寻访、前往或托人联系；异地沟通必须使用世界允许的异步渠道。发出消息不等于送达、阅读、理解或相信。消息传播、人物认知与世界时间统一由确定性规则结算并留痕；AI 叙事不得直接改变未发生的投递、认知或位置状态。玩家只看到有来源支撑的位置信息。M1 仅验证同场交谈、县内寻访与基本书信闭环，不扩展为全国通信网络。

纳入总纲前还需确认：
1. 是否把“人物位置知识”列为四层认知的明确子项；
2. 是否将通信事件纳入统一事件日志与幂等契约；
3. 是否把同场交谈耗时映射到现有动词表；
4. 是否将“未送达不得知情”加入 M1 验收。
