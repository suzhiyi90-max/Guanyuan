# 官制史实核验台账

## v0.1 · 设计提案配套审查材料

- **状态：** 初始核验台账，非最终历史定论
- **关联提案：** `docs/proposals/官场生涯与品级体验设计提案-v0.4.md`
- **权威设计基线：** 根目录 `设计总纲.md` v0.3
- **用途：** 在玩法规则生产前，拆分历史断言、记录证据质量、标出适用范围与未决问题。
- **注意：** 本表是首轮桌面核查结果，不替代逐条查阅会典、则例、档案原文和完整学术研究。凡标记“部分支持／待核”的项目，不得直接硬编码为历史规则。

## 1. 状态定义

| 状态 | 含义 | 可否作为硬规则 |
|---|---|---|
| 已有较强支持 | 已找到与断言直接相关的制度文本或学术资料入口，且大方向一致 | 仅限来源实际支持的范围，仍须绑定时期与情境 |
| 部分支持 | 核心方向有来源，但措辞过宽、存在例外或缺少适用范围 | 否；先收窄断言 |
| 待核 | 当前来源不足以证明完整断言，或只有二手概述 | 否 |
| 游戏假设 | 为玩法需要人为设定 | 可以作为游戏规则，但必须显式标记为虚构参数 |

## 4. 进入游戏规则前的最低门槛

一条历史断言只有同时满足以下条件，才能成为硬规则：

- [ ] 断言已拆分为单一、可证伪的句子。
- [ ] 已有可定位的来源，不仅是书名或泛链接。
- [ ] 已记录适用时期、地域、职位类别和制度版本。
- [ ] 已查明关键例外或明确标记“例外尚未穷尽”。
- [ ] 已区分制度文本、实际执行、学术解释与游戏抽象。
- [ ] 已明确它究竟影响权限、经济、文本、概率还是纯背景。
- [ ] 若是数值，已确认单位、计算方式和适用范围。
- [ ] 若来源互相冲突，已记录争议并避免在规则中伪装成确定事实。

## 5. 推荐执行顺序

1. **先选规则基准期**，否则所有制度数据都会存在不可比问题。
2. **先核 M1 直接使用的事实**：知县职位、河工权限、钱粮账目、上级批复、文书流转与考语来源。
3. 再核后续可能扩展的品级、缺分、考成、密折、养廉银、丁忧与选官制度。
4. 对尚未核实的细节采用游戏参数，不冒充历史事实；对无必要影响 M1 的事实暂不建模。
5. 每次规则变更都记录所依据的事实 ID，方便复核与回滚。

**当前结论：** 本台账只确认部分制度方向有可靠资料入口；多项具体品级、金额、权限、选任与收入主张仍需逐条核验。不得把“待核”误读为“错误”，也不得把“有研究入口”误读为“已经证实”。
