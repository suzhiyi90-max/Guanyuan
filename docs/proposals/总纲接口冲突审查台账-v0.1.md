# 总纲接口冲突审查台账：世界时间、行动动词、事件记录与人物认知 v0.1

- **状态：** 第一轮静态设计审查完成；裁决建议待产品负责人确认
- **权威基线：** 根目录《设计总纲.md》v0.3（main）
- **关联提案：**《社交在场、空间距离与异步通信机制设计单 v0.2》
- **审查性质：** 文档层交叉核对；未检查运行时代码，未进行游戏内验收

## 0. 总结结论

第一轮未发现必须推翻总纲核心原则的根本冲突，但发现四类需要收敛的问题：

1. **规则定义分散：** 世界时间、行动耗时、NPC 日程、期限与夜间结算分布在时间章、动词表、执行结算和因果记录中。
2. **概念粒度不统一：** “时段”“行动点”“行动耗时”“世界事件发生时间”并未被明确定义为同一时间模型中的不同量。
3. **留痕与事件记录的边界不够明确：** 动词表的“留痕”、人物记忆、因果记录、消息状态历史都可能记录同一行为的不同侧面，但总纲尚未明确哪个是权威事实、哪个是派生视图。
4. **认知模型存在字段层与语义层混用：** `knows`、`believes`、四层信息视角、NPC 记忆证据化、传闻网络都在描述相关问题，但并非完全相同的对象；若直接把通信提案的数据字段叠加上去，会造成重复记录。

**建议裁决：** 暂不把通信提案中的字段清单原样并入总纲。先确认四类权威抽象及其引用关系，再把通信设计改成对既有抽象的扩展，而不是新建并行系统。

## 2. 四个领域的详细审查与建议

### 2.1 世界时间：需要补的是“单位关系与结算顺序”，不是第二个时钟

总纲现有规则已经规定：
- 一天分晨、午、暮、夜四段，每段有行动点；
- 行动结束结算；
- 夜间结算睡眠、疲劳、次日行动点、到期承诺/债务与世界变化；
- 关键事件可以主动暂停并弹窗；
- NPC 在玩家休息时仍然推进；
- 关键行动记录必须幂等且多项状态一致提交。

需要补清的边界：
1. **行动点不应被默认等同于世界时间单位。** 行动点是玩家当日可支配资源；“耗时”是世界时钟推进量，两者可有关联，但应明确换算规则。
2. **四时段是日程/呈现分段还是精确时钟刻度，需要明确。** 若行动可能跨时段或消息在时段中途送达，就需要稳定的事件排序键，而不能只比较“晨/午/暮/夜”。
3. **关键事件暂停只暂停玩家决策流程，不应隐式冻结世界。** 总纲的“主动暂停并弹窗”与“世界不会等玩家无限期”之间需要明确：暂停 UI 不推进真实时间，但玩家选择耗时行动或等待时，世界按规则继续。
4. **期限、承诺到期、通信预计送达都应引用同一世界时间。** 预计送达是预测值，实际送达必须由事件结算产生。
5. **同一时间点多个事件的先后顺序要确定。** 至少需定义：行动提交/消耗、行动结果、地点变更、消息送达、截止事件、夜间结算之间的排序原则。不能依赖异步任务偶然先后。

建议将上述作为“世界时间与事件排序契约”的小节或术语补充；具体换算数值先保持为待验证游戏参数。

### 2.2 行动动词：冻结八动词与动作原语的职责要分清

总纲同时存在三种层级：
- 第 3.4 节通用动作原语：询问、探查、请求、承诺、交易、委托、推荐、劝说、施压、保护、奖赏、拒绝、追责；
- 第 4.5 节第一阶段冻结八个社交动词：问、查、托、请、压、保、赏、荐；
- 第 8 章结构化行政行动意图：目标、方式、执行人、资源、权限、期限、约束、验收与监督。

三者目前没有明说“通用原语目录”和“第一阶段可玩动作目录”的关系。通信提案中的“写信”“寻访”“托人递话”又属于不同层级：
- “问/请求/委托”更接近行为目的；
- “当面/书信/中间人/正式公文”更接近渠道；
- “寻访/候见/前往”可能是独立的行动流程，包含位置搜索与时间成本。

建议不把每种渠道直接加入八个冻结动词。先将每次交互统一表达为：
**动作意图 + 目标对象 + 渠道/场景 + 条件/成本 + 四段式判定 + 结果事件**。
其中渠道可限制可用动作，但不能取代权限、意愿与结果判定。M1 是否新增“寻访”作为独立可执行动作，应在范围表中单独裁决。

### 2.3 事件记录：事件日志、业务对象与展示日志不是三套事实

总纲的“统一因果记录”应作为权威历史。通信设计可拥有一个消息业务对象，以便 UI 显示当前状态，但必须明确：
- **命令 ID / 幂等键：** 标识一次玩家提交，重放不得重复扣费、推进时间或创建副作用。
- **消息 ID：** 标识一封信或一条通信业务对象。
- **事件 ID：** 标识一次不可重复的已发生事实，例如“信件送达”。
- **关联 ID：** 将消息、行动、人物认知变化和后续结果关联起来，不替代上述标识。
- **当前状态：** 从创建与状态变更事件得出的当前投影；不能成为另一份独立历史。
- **UI 通知/日志：** 展示层派生结果，不拥有业务写入权。

建议通信事件至少能回答“谁在何时做了什么、依据什么、改变了哪些状态、谁因此知道了什么”。但不应要求所有事件都复制一份完整人物认知；认知变化通过关联事件产生，并写入其权威记录。

### 2.4 人物认知：必须分清事实、主张、认知状态与传播事件

总纲已有四层信息视角，建议继续保留，不新增第五层。

需明确四种不同对象：
1. **客观事实/世界状态：** 规则引擎中的实际状态。
2. **信息主张：** 某人在某时某地表达或传递的内容，可能真实、错误、过时或有意误导。
3. **人物认知状态：** 某人已知、相信、怀疑、误解或拒绝相信的内容，并有来源、时间与可信度。
4. **传播/获知事件：** 某人通过亲历、阅读、听说、转述或推断接触信息的具体过程。

“送达”只表示消息到达约定接收端；“阅读”需要规则证据；“理解/相信”不是通信状态的自然后继，而是人物认知判定。玩家看到的传闻也不应自动成为客观事实或所有 NPC 的共同知识。

建议 `knows` 与 `believes` 暂作为概念字段保留，待实现数据模型时再确定具体结构；不要在总纲中同时维护多套互相重叠的字段清单。通信提案所需的来源、信息对应时间、获知时间、可信度等属性应复用既有人物记忆/认知契约，并以消息或事件 ID 作为来源引用。

## 3. 建议写入权威总纲的最小摘要（待批准）

以下是候选文本，不是已批准修改：

> **统一时间与事件：** 全部玩家行动、NPC 日程、承诺期限、事件截止与异步通信均使用同一权威世界时间。行动点是玩家可支配资源，不自动等同于时间单位。预计时间与实际发生时间分开记录；事件在同一时间点发生冲突时按确定性规则排序。关键事件暂停只暂停玩家决策界面，不得暗中创建独立时间轴。所有状态变更进入统一追加式事件记录，并具备幂等与一致性约束。
>
> **动作与渠道：** 通用动作原语、第一阶段可玩动词和通信渠道属于不同层级。新渠道不自动成为新动作，也不绕过四段式互动判定、权限检查或资源/时间成本。每个动作最终必须转化为可追溯的规则结果。
>
> **认知与传播：** 客观事实、信息主张、人物认知、玩家认知与社会传闻相互关联但不可混同。通信、观察或转述只产生有来源的获知过程；送达不等于阅读，阅读不等于理解，理解不等于相信。人物认知变化必须引用来源与时间，不能由叙事文本直接写入。
>
> **唯一事实源：** 统一事件日志是历史事实的权威来源；业务对象可以保存当前状态投影，展示日志和通知从权威数据派生，不得形成第二套业务事实。
