# 品级、职位与权力的距离

## 官场生涯体验设计提案（v0.4 · 完善审查稿）

- **版本：** v0.4-review
- **状态：** 增量提案，待产品负责人裁决；不是已批准设计
- **权威基线：** 仓库根目录 `设计总纲.md` v0.3
- **本文件性质：** 对 v0.3-E1 提案进行结构修订、范围收敛、制度风险标注与可验证化；不修改权威总纲
- **首个验证场景：** 一县、七人、十日、一汛；黄河河工治理
- **核心命题：** 升官不只是获得更多权力，而是信息来源、核验成本、行动边界、责任半径和被记录方式一起变化。

> **重要边界**：本文中的清代制度是设计参照，不意味着游戏必须严格复刻某一具体年份。未绑定时期、地域、官缺或制度出处的数值，一律不得作为史实规则。M1 只实现首个验证场景真正需要的部分。

## 0. 本次修订说明

v0.3-E1 提出了有价值的“权力距离”模型和“一案一卷”复用思路，但同时存在四类问题：

1. 将品级、职务、组织层级、信息距离和生涯阶段放在同一条阶梯上，容易导致错误映射。
2. 将清中前期制度骨架与晚清官场实践混用，部分具体权限、收入和程序被写成统一事实。
3. 把大量长期系统放进 M1，名义上仍是一县一汛，实际范围却扩张为完整官场模拟。
4. 以“高层更盲”“每级一个说真话的人”等强表达作为设计原则时，容易把有用隐喻变成生硬规则。

v0.4 将内容分成四种状态：

| 标记 | 含义 | 允许用途 |
|---|---|---|
| **[总纲已定]** | 已明确写入 `设计总纲.md` 的原则或范围 | 作为当前设计约束 |
| **[提案]** | 本文提出的新设计方向 | 可讨论，不可当作已批准事实 |
| **[待考]** | 历史证据不足、适用范围不明或来源需补齐 | 不可直接硬编码 |
| **[待测]** | 玩法、成本或可读性需要原型验证 | 必须通过验收标准验证 |

## 1. 核心设计：职位改变玩家与事实的关系

### 1.1 核心循环保持不变

**[总纲已定]** 听人说话 → 判断真假 → 决定托谁 → 承担结果 → 被人记账。

本提案只为这个循环增加一组可配置变量：玩家从什么渠道获得信息、以什么成本验证信息、能对谁下达什么命令、行动结果由谁记录。

### 1.2 不再把 D1–D5 当作官阶

D1–D5 是**信息与治理模式**，不是官阶，也不是固定职务表。它描述某一职位在特定事务中的典型工作方式。一个人物可能因事务不同而混合多种模式。

| 模式 | 名称 | 默认输入 | 典型核验 | 典型行动 | 主要风险 |
|---|---|---|---|---|---|
| D1 | 现场核验 | 当事人、现场、实物、原始账 | 亲查、询问、对账、复验 | 当面命令、签押、派差 | 样本有限、时间不足、现场被布置 |
| D2 | 汇报审查 | 下级详文、账册、口报 | 抽查、交叉比对、退回补证 | 批、驳、查、委 | 下级修饰、幕友过滤、口径不一 |
| D3 | 跨辖区比较 | 多地册报、成例、统计 | 比较异常、核对口径、派员复核 | 核、驳、咨、参、调度 | 指标被优化、不同地区不可直接比较 |
| D4 | 远程统筹 | 多渠道报告、人事评价、专项呈报 | 召见、巡查、密报或独立复核（按时期与权限） | 任用、协调、请示、问责 | 代理人垄断信息、责任层层转移 |
| D5 | 中枢议决 | 汇总文书、奏报、议覆、政治情势 | 多源印证、追问、召对、复核程序 | 议决、批答、用人、定政策 | 摘要丢失细节、政治表达压过事实 |

**禁止硬绑定：** 不得写成“某品级必然属于某 D 级”。职位、事务、授权、时代与具体情势共同决定当前模式。

### 1.3 信息距离不是强制失明

高层默认更多依赖报告与代理人，但仍可在规则允许时亲自调查、召见、巡查或派员核验。差异体现在成本与覆盖面，而不是系统随意禁用功能。

- 直接核验：成本较高，覆盖范围较小，可能暴露调查意图。
- 委托核验：成本较低或覆盖较广，但受委托人能力、忠诚、利益和执行偏差影响。
- 多源交叉：更可靠，但消耗时间、经费和政治资本，也可能引发部门冲突。
- 不核验：推进较快，但错误可能在后续考核、案卷或人物关系中暴露。

**[待测] 验收问题：** 玩家能否解释“我为什么不知道”“我还能如何查”“继续查的代价是什么”，而不是只感到选项被锁。

### 1.4 权力至少包含五个彼此独立的维度

1. **法定权限**：制度允许做什么。
2. **实际控制力**：现实中能否调动人、钱、文书与执行资源。
3. **信息可见性**：能看到什么、信息有多新、能否核验。
4. **责任范围**：失败会追到谁、追溯多久、是否连带上级或下属。
5. **政治与关系成本**：行动会得罪谁、消耗谁的信任、影响何种后续机会。

品级只可作为这些变量的部分背景，不能替代这些变量。

## 2. 统一官场领域模型

### 2.1 六种实体必须分开

| 实体 | 回答的问题 | 最低字段建议 |
|---|---|---|
| Person 人物 | 谁？知道什么？想要什么？ | 身份、动机、知识、关系、能力、风险、当前状态 |
| Rank 品级 | 名义上的官阶是什么？ | 品级、适用时期、制度来源、是否存在加衔差异 |
| Position 职位 | 实际担任什么职务？ | 职名、辖区、职责、编制属性、所属组织 |
| Appointment 任职状态 | 如何取得这个职位？ | 候补、委署、署理、实授、调补等；起止时间与依据 |
| Authority 权限 | 能做什么、需谁批准？ | 行为、对象、范围、限额、前置条件、审批者、来源、有效期 |
| InformationMode 信息模式 | 当前如何获取与核验信息？ | 输入渠道、核验手段、时效、覆盖面、成本、失真风险 |

另设 `OfficeContext` 或等价上下文承载时代、地域、制度版本与当前事件；不要把时代规则散落在职位描述文字里。

### 2.2 关系必须支持多对多

- 一个人可以有正式职务、兼衔、临时差遣和历史任职记录。
- 一个职位可由不同任职状态的人暂时承担，但权限与责任不必完全相同。
- 同一品级可能对应不同职位；同一职位也可能因时代、辖区或兼衔而存在差异。
- 一个行为的权限判断必须读取当前任命、授权来源、事务类型、辖区与有效时间，而不是只查品级。

### 2.3 权限决策的最小格式

```json
{
  "action": "approve_expenditure",
  "subject": "county_works_fund",
  "scope": "county_works_case_001",
  "limit": { "amount": 50, "unit": "tael", "status": "unverified_game_parameter" },
  "preconditions": ["budget_available", "ledger_recorded"],
  "approval_required": "superior_office_if_over_limit",
  "effective_context": { "period": "fictional_period_A", "jurisdiction": "county_001" },
  "source_class": "gameplay_parameter",
  "validation_status": "needs_review"
}
```

示例中的 50 两只是展示字段设计的占位值，不代表史实。任何限额在进入规则引擎前都必须注明来源、适用情境和验证状态。

## 3. 品级与生涯路径：分层而非一条直线

### 3.1 不把 T0–T8 当作正式官阶

T0–T8 是**体验章节／内容包标签**，不是正式官制，也不是必经的升迁路径。京官与外官可能在相近品级下承担完全不同的职责，职业路径也可能分流、停滞、中断或回归。

| 内容包 | 体验主题 | 可出现的典型角色 | 本提案定位 |
|---|---|---|---|
| T0 | 入仕前与候补 | 候补者、幕友、教读 | 长线背景；不进入 M1 必做范围 |
| T1 | 佐杂与基层执行 | 典史、巡检、县丞、主簿等 | 可作为县级 NPC／执行角色，不预设每县齐备 |
| T2 | 县级治理 | 知县及县衙协作人物 | **M1 唯一可玩主位** |
| T3 | 府级审查 | 知府、知州、同知等 | 后续验证汇报审查模式 |
| T4 | 省级专业治理 | 道员、布政使、按察使等 | 后续验证跨辖区比较与专项审查 |
| T5 | 督抚统筹 | 巡抚、总督等 | 后续验证远程统筹与人事责任 |
| T6 | 京官分支 | 部院司官、科道、翰林等 | 横向职业路径，不是一个统一层级 |
| T7 | 中枢决策 | 大学士、军机大臣等（按所选时代配置） | 高成本长线内容 |
| T8 | 权势终局状态 | 权臣、首辅等叙事类型 | **叙事终局标签，不是正式品级** |

本表是内容规划，不构成历史升迁顺序。每个具体职位须独立核验品级、时期、职责与任用规则。

### 3.2 任职状态独立建模

建议以状态集合表达，而不是用一条无例外的线性状态机：

- **候选／候补**：有资格或已列入候补序列，但未必掌握实缺。
- **委署／署理**：临时承担部分或全部职务；权限范围、责任与任期需按规则确定。
- **实授**：正式任命；不代表拥有该职位所有可能的特别授权。
- **调补／升迁**：新的任职事件，需记录来源、时间与交接。
- **停职待查／处分／开复**：影响权限、收入、名誉与职位状态的独立事件。
- **丁忧／告病／回避／致仕**：不同性质的中断或退出状态，不能简单等同。

具体制度需按所选历史时期配置。候补、委署、署理等词在历史文书中的使用可能因时期和情境而异；上线前须做术语与规则核对。

### 3.3 缺分：作为职位环境参数，而不是人物性格

“冲、繁、疲、难”可以启发职位压力设计，但不能直接被翻译成“肥缺／清缺”或固定收入等级。

| 维度 | 设计抽象 | 可影响的玩法 | 不应自动推出 |
|---|---|---|---|
| 冲 | 交通、往来与差务压力 | 消息流量、接待成本、事务插队 | 收入必高、升迁必快 |
| 繁 | 案牍与行政工作量 | 时段占用、委托需求、遗漏风险 | 玩家必然疲劳或政绩差 |
| 疲 | 财赋征收与地方承受压力 | 欠征、垫赔、民力冲突 | 民众必然抗税或官员必然贪腐 |
| 难 | 治安、纠纷或治理难度 | 调查风险、协作需求、执行阻力 | 当地人群天生“刁悍” |

缺分组合、等级和名称必须绑定具体制度时期与地方官缺资料。玩法参数只从经过审查的具体职位实例导出，不将四字作为跨时代普遍公式。

## 4. 职位体验卡模板

每张职位体验卡都必须回答以下十项，缺项应标为未知，不得用想象补成事实：

1. 职位、品级与适用时期。
2. 任命与任职状态。
3. 法定职责及明确不具备的权限。
4. 直接控制的资源与需要上级批准的事项。
5. 默认信息来源与可用核验渠道。
6. 日常时钟：哪些事务会挤占玩家时间。
7. 典型人物关系与利益冲突。
8. 一个能落地的核心两难。
9. 失败后果、申辩／补救途径与后续记录。
10. 历史依据、设计推断、虚构参数和待核事项。

### 4.1 M1 知县体验卡（范围冻结草案）

- **主场景**：黄河河工治理；十日内应对一汛。
- **玩家目标**：在有限钱粮、劳力、时间与授权内，做出可解释、可追溯的治理决策。
- **可玩机制**：接印时继承一份前任遗留账目；查看现场与账册；比较人物陈述；选择亲查或委托；形成河工方案；执行中出现偏差；记录结果与责任。
- **核心资源**：河工预算、可用劳力、时间、可信情报、关系／政治成本。
- **允许出现的官场关系**：县内执行人员、幕友或书吏、地方协作者、上级来文／批复。具体角色数受总纲七人配置约束。
- **本阶段不做完整玩法**：科举模拟、候补排队、捐纳、完整刑名审转、秋审、完整大计、跨省人事棋局、京官独立生涯、军机票拟、完整丁忧状态机。
- **允许作为背景提及**：未来升迁机会、上级考语、历史遗留亏空、外部势力和制度压力；但不可因此要求新地图或完整新系统。

**M1 成功标准**：玩家能指出一项关键事实的证据与不确定性，说明选择该执行者的理由，看到执行偏差如何发生，并理解结果如何影响人物关系、账目和考语。

### 4.2 后续职位卡的最小差异原则

每新增一个职位／模式，必须说明它改变了哪一项核心体验：

- 新的可见信息？
- 新的核验方法？
- 新的法定权限或审批链？
- 新的责任归属？
- 新的时间尺度或关系网络？

如果以上均没有变化，只是换称呼、文案或数值，则不构成一个新的可玩职位，应作为内容变体而非新系统。

## 5. 关键系统的玩法化规则

### 5.1 文书不是换皮界面，而是证据与行动载体

文书至少有以下字段：文书类型、撰写者、签发者、收件者、创建时间、有效时间、所依据的事实、未陈述的事实、附件、流转记录、保密范围、是否可质疑、后续处理结果。

文书可能失真，但失真要有可解释的来源：撰写者不知道、故意隐瞒、受上游口径限制、复制旧模板、数字口径不同，或传递时丢失附件。禁止把所有文书默认视为谎言。

**验收要求：** 玩家能查看一份文书的出处、版本与关键依据；同一案件的文书相互矛盾时，系统能展示差异，而不是只用叙述告诉玩家“似乎有问题”。

### 5.2 “一案一卷”改为事实图谱复用

每个案件建立一个不可被叙事文本覆盖的事实层：

- **客观状态**：世界当前实际发生了什么。
- **证据**：物证、账目、证词、现场观察及其可靠性。
- **人物认知**：每个人知道、相信、误解、怀疑或隐瞒什么。
- **文书版本**：不同人物在不同时间提交的说法。
- **行动与权限**：谁能做什么，谁授权，谁执行。
- **结果与责任**：状态变化、资源变化、关系变化和记录归属。

不同层级的内容应从同一事实图谱生成不同视角，不得为制造戏剧冲突而随意改变客观事实。玩家可以发现新事实，也可以因证据不足而保持不确定。

### 5.3 “每级一个说真话的人”改为“每阶段有可核验的信任渠道”

重要阶段应提供具体人物渠道，使玩家有机会建立信任、追问和交叉验证；但任何人物都不保证永远说真话。人物可能诚实但认知有限，也可能因恐惧、利益冲突、记忆偏差或自我欺骗而误导玩家。

信任值不能直接等于真话概率。应分开记录关系亲疏、信息能力、利益冲突、当前风险和对事实的实际认知。

### 5.4 考成与“被记账”

考语不应只根据最终成败自动生成。至少要记录：

- 玩家当时可获得的信息。
- 当时的权限与可用资源。
- 玩家实际采取的行动与未采取的行动。
- 执行者的能力、动机与偏差。
- 结果是否可归因于玩家、执行者、环境或制度约束。
- 哪些人有权评价，评价者掌握哪些证据。

M1 只需要一次由真实行动生成的阶段性考语，不模拟完整三年考核。历史考核的周期、范围和分类必须按具体时期核验。

### 5.5 京—外关系与经济

“京官靠外官、外官受京官制约”可以作为研究方向，但不能写成所有人物都参与同一套馈赠循环。

经济数据必须拆分：

- 正式俸禄与法定给付。
- 养廉银等特定制度性给付（适用职位、地区、时期须核实）。
- 办公经费与公费。
- 个人支出、幕友束脩和差旅成本。
- 礼俗性馈赠、非正式收入与违法索取（法律／社会性质必须分开）。

系统不得把贪腐设为必然最优策略。若玩家选择制度外收入，应呈现关系依赖、被揭发风险、账目痕迹、道德与政治后果，不将其包装成无代价的资源按钮。

## 6. 史实治理：任何历史规则都要能追溯

### 6.1 证据等级

| 等级 | 定义 | 规则用途 |
|---|---|---|
| H1 一手制度文本 | 会典、则例、律例、档案原件或可靠影印 | 可支撑特定时期的制度规则；仍需解释适用范围 |
| H2 同时代记录 | 日记、书信、判牍、奏折、地方志等 | 支撑具体实践、个案或当事人认知，不自动代表全国惯例 |
| H3 学术研究 | 有注释的专著、同行评审论文、学术机构研究 | 可支撑解释、统计与制度演变；记录研究范围 |
| H4 二手概述 | 百科、新闻、普及文章 | 只作检索入口或背景提示，不单独支撑关键硬规则 |
| G 游戏假设 | 为玩法补全的虚构规则或参数 | 必须明确标记为游戏设计，不得伪装史实 |

旧版 A/B/C/D 可信度标签不再单独承担全部含义：来源可靠度、历史适用范围和游戏用途是三个不同维度，应分别记录。

### 6.2 每条史实的登记格式

| 字段 | 说明 |
|---|---|
| `factId` | 稳定唯一标识 |
| `claim` | 一条可被证伪的具体断言，不写成一段综合结论 |
| `sourceType` / `sourceTitle` | 一手文本、同时代记录、学术研究或二手概述；完整题名 |
| `locator` | 卷、篇、页码、档号、章节或稳定链接 |
| `period` | 起止时期；未知则明确未知 |
| `jurisdiction` | 全国、特定省份、特定官缺或个案 |
| `confidence` | 高／中／低，并说明理由 |
| `exceptions` | 已知例外或争议 |
| `gameUse` | 直接规则／参数参考／文本背景／不用于规则 |
| `status` | 已核／待复核／存在争议／已弃用 |

### 6.3 本提案中必须保持“待核”的历史断言

以下项目不得直接变成硬规则，除非补齐明确来源与适用范围：

1. “京官无养廉银”及其推导出的收入结构。
2. 知县、知府、督抚养廉银的统一数值区间。
3. “佐杂多由贡监、捐纳出身”“进士、举人通常不授某职”等概括。
4. 某类官员普遍从陋规中分润的说法。
5. 密折或专折奏事资格与具体品级之间的固定映射。
6. 某一具体金额、人数或支出阈值对应的法定审批权限。
7. “每三年考核一次”对所有官员与所有时期均成立的表述。
8. 丁忧、在任守制、夺情、起复的统一时间线。
9. 巡抚、总督、布政使、按察使等官职的品级、兼衔与实际权责在不同阶段的变化。
10. 缺分、缺等、出息与升迁机会之间的必然关系。

### 6.4 历史时代方案

建议不要以“清中前期制度 + 晚清腐败质感”作为无差别混合规则。可采用以下治理方式：

- **规则基准期**：后续由产品负责人选择一个较窄的制度窗口，作为权限、官制与流程规则的主要依据。
- **跨期内容**：只有在明确标记时期差异、且玩法确有价值时才引入；不能仅因更戏剧化而移植。
- **架空处理**：如果为玩法改变历史规则，登记为 G 游戏假设，并在设定中统一说明，不伪称真实制度。
- **时间不确定**：暂时用中性抽象实现，不硬编码历史断言，等待史料核验后再定。

在规则基准期尚未裁决前，具体历史金额、权限阈值和官职映射均不进入生产规则。

## 7. 数据与实现约束

### 7.1 职位数据不直接承载全部规则

职位配置只描述稳定的职位信息与引用关系。权限、经济、任职状态和信息模式分别由独立规则表提供，并通过时期与上下文绑定。

建议的数据分层：

- `position_catalog`：职位名称、职责、所属组织、常见品级与来源。
- `rank_catalog`：品级及适用时期。
- `appointment_events`：任命、署理、调补、停职、复职等时间事件。
- `authority_rules`：行为权限、对象、范围、审批链、有效期与来源。
- `historical_facts`：史实断言及证据状态。
- `economy_rules`：俸禄、制度性给付、经费、个人成本及其适用范围。
- `information_profiles`：信息渠道、时效、核验方式、成本与风险。
- `case_facts`：案件事实、证据、人物认知、文书版本与行动后果。

### 7.2 禁止事项

- 不允许用 `rank === '正七品'` 直接推导完整权限。
- 不允许将演示阈值默认为史实；参数缺少 `sourceClass` 或 `validationStatus` 时不能进入正式数据。
- 不允许把“关系好”直接映射为“更诚实”。
- 不允许在文书文本中维护与世界状态不一致的第二份事实。
- 不允许为每个品级复制一套规则引擎；新职位优先通过数据、内容与界面配置表达。
- 若新职位确实需要改变引擎，必须说明新增规则抽象及其对既有 M1 的影响。

### 7.3 内容量估算必须先实测

旧版“30 个案卷 × 5 级 = 150 个可玩片段”只可视为粗略假设。跨层级复用仍需编写不同人物视角、文书、权限判断、反馈和测试用例，不能将片段数等同于低成本产能。

先做一个河工案卷的事实图谱，再制作县级视角和一个上级审查视角；记录新增内容工时、规则改动数、可复用比例和缺陷数，之后再估算规模。

## 8. 分阶段路线与验收

| 阶段 | 范围 | 不在本阶段承诺的内容 | 验收目标 |
|---|---|---|---|
| M0 | 术语表、事实登记模板、规则来源字段、M1 范围冻结 | 完整官制数据库 | 设计数据能区分史实、推断与游戏参数 |
| M1 | 一县、七人、十日、一汛；知县视角；河工案卷；现场／文书双渠道；委托、执行偏差、结果记账 | 完整升迁、刑名审转、京官线、完整考成 | 核心循环成立，玩家理解证据、权限、执行偏差和后果 |
| M1.x | 同一案卷增加一个上级审查的纸面／可玩原型 | 新地图、完整府级模拟 | 验证信息距离是否带来新的判断，而非只增加阅读量 |
| M2 | 一个府级职位与一个京官视角的最小对照 | 全部 T3–T6 内容 | 验证职位／权限／信息模式分离是否可扩展 |
| M3 | 选定规则基准期后，加入经核验的考成、钱粮或人事机制 | 未核实的历史权限与收入硬编码 | 验证长期制度是否可追溯、可解释 |
| M4 | 视原型结果决定是否开发更高层级、终局和影子线 | 默认承诺军机／权臣完整路线 | 验证高层仍有具体人物、可核实事实与有意义的责任选择 |

### 8.1 M1 验收清单

- [ ] 玩家可以在至少两种来源之间发现一处真实矛盾。
- [ ] 玩家可以查看该矛盾涉及的来源、时间与证据，而非只看结论文本。
- [ ] 玩家可以选择亲自核验或委托核验，并理解成本差异。
- [ ] 委托行动受权限、资源和执行者能力约束。
- [ ] 执行结果可出现有因果依据的偏差，而非随机惩罚。
- [ ] 结果会影响至少一项世界状态、人物关系或资源账目。
- [ ] 阶段考语引用实际行动和证据，不只依据成功／失败。
- [ ] 玩家能说明自己为何做出关键决定，以及当时仍有哪些未知。
- [ ] 首场景不依赖完整刑名、京察、大计、捐纳或跨省系统。
- [ ] 所有历史性硬规则都能追溯到经过审查的来源；其余明确标为游戏假设。

### 8.2 新增层级的通过条件

新增层级只有在同时满足以下条件时才进入开发：

1. 有至少一个 M1 无法提供的独特决策问题。
2. 独特性来自权限、信息、责任或组织关系，而非只靠文案包装。
3. 有可复用的事实图谱与文书数据结构。
4. 历史规则与游戏假设已分开标记。
5. 有可完成的最小场景与明确验收条件。
6. 成本评估覆盖内容、界面、规则、测试与维护，而非只估文本数量。

## 9. 风险与反模式

| 风险 | 错误做法 | 防护措施 |
|---|---|---|
| 高层失焦 | 把玩家变成只看报表的管理员 | 每个决策落到具体人物、事实与后果 |
| 强制失明 | 高官禁止直接核验 | 允许核验，但按权限、成本与覆盖面约束 |
| 阶梯混乱 | 品级、职位、体验包和信息模式共用一个等级字段 | 分开建模并以任命／上下文关联 |
| 历史拼贴 | 为戏剧性跨时期拼接规则 | 选择规则基准期；跨期内容明确标注 |
| 数字伪史 | 演示阈值进入正式权限表 | 来源与验证状态为必填字段 |
| 贪腐爽点化 | 非法收入是无代价的高收益选项 | 呈现依赖、风险、证据、后续追责与道德后果 |
| 人物工具化 | 角色只为提供真话或背锅 | 每个人物有独立认知、动机、能力与风险 |
| 文书疲劳 | 大量长文本替代可交互核验 | 先突出差异、出处、关键数字和可操作疑点 |
| 范围膨胀 | M1 同时建设完整仕途、刑名与京官系统 | 首场景验收优先；长期机制仅作背景或占位 |
| 过度复用 | 认为同一案件换五套措辞即可成为五套玩法 | 复用事实图谱，重做决策、权限、责任和反馈差异 |
