## 1. 本轮结论

总纲已经包含本机制所需的主要原则。本轮不建议增加新的顶层系统，而建议用少量契约补齐四种边界：

1. 世界时间的**时间刻度、行动点、事件排序**分别是什么。
2. 通用动作原语、第一阶段冻结八动词、联系渠道分别处于哪一层。
3. 统一因果记录与业务对象当前状态之间的权威关系。
4. 客观事实、信息主张、人物认知、玩家认知和传闻之间如何关联，而不重复造一套记忆字段。

建议采用“先补术语与引用、再修通信提案”的路线。若一个候选改动不能减少歧义或防止规则冲突，就不写入总纲。

## 3. 候选最小补丁（待审批）

下列文本是建议放入总纲的候选补丁。为了避免过度修改，建议新增一个短小的“跨系统契约”小节，或将各句并入现有对应章节；**不建议把通信提案全文搬进总纲**。

### 3.1 时间与结算契约（建议放在第 9 章）

> 全部行动、NPC 日程、期限与异步事件共享唯一权威世界时间。行动点是玩家可支配资源，不应在未定义换算关系前与时间单位视为同义。预计发生时间与实际发生时间分开记录。行动、移动、送达、截止与夜间结算在同一时间节点冲突时，按确定性顺序结算，不依赖异步执行的偶然先后。关键事件弹窗暂停玩家决策界面，不得暗中创建独立时间轴。

**需注意：** 这段话不能单独解决时段和行动点的数值换算。总纲必须在后续数值设计中明确：某动作消耗一个行动点、一个时段，或跨越多个时段，三者究竟如何关联。该数值关系暂不擅自指定。

### 3.2 动作与渠道契约（建议放在第 3.4 或第 4.5 节）

> 通用动作原语、第一阶段可玩动词与执行渠道是不同层级。渠道（如同场交谈、登门、书信或托人转达）不自动构成新动作，也不得绕过四段式互动判定、权限检查、时间与资源成本。只有当某流程具有独立前置条件、结算结果与可验收闭环，并获范围审批后，才将其列为新的可执行动作。

### 3.3 事件历史契约（建议补在第 10.5 节）

> 统一因果记录是权威历史。业务对象可以保存便于界面查询的当前状态，但当前状态应由权威事件历史一致更新或重建，不得形成第二份独立历史。命令幂等键用于防止同一提交重复产生副作用；业务对象 ID 用于识别对象；事件 ID 用于识别单次发生的事实。展示日志和通知由权威状态派生。

### 3.4 信息主张与认知契约（建议补在第 3.2 节或第 15.4 节）

> 客观事实、信息主张、人物认知、玩家认知与社会传闻不可混同。消息或转述记录某人在特定时间表达/传递了什么，不自动证明内容为真。获知事件必须保留来源与时间；人物是否理解、相信、怀疑或据此行动，由人物认知与行为规则决定。四层信息视角不因增加传播渠道而扩展为第五层。

## 4. 不建议写入总纲的内容

以下内容应留在通信设计单或参数表，不宜进入权威总纲正文：
- 消息状态机的全部状态枚举、消息对象完整字段、具体消息 UI；
- 每一种渠道的固定耗时、费用、延误概率与失败概率；
- 详细地点节点清单、核心人物逐日位置表；
- C1–E4 全部验收用例；
- 后续阶段的截信、伪造、密码、全国驿路模拟；
- 未经验证的数值或未经史实核验的古代通信速度说法。

原因：总纲应保存跨系统不变量和范围边界，具体模块规则与可调参数留在模块设计单，避免权威文档变成无法维护的重复百科。

## 6. 修改顺序与验收门

1. **先裁决术语：** T-01/T-02、A-01、E-01、K-01。没有证据的字段与数值保持未决。
2. **再做总纲最小增量修订：** 仅合入已裁决的不变量；保留 v0.3 原文与版本变更记录。
3. **回修通信提案：** 将消息状态机、渠道矩阵、M1 用例明确映射到总纲契约；移除重复定义。
4. **只读检查代码：** 搜索时间、动作、事件、人物记忆相关的真实类型/接口，记录文件路径、符号和调用链。代码检查之前不得声称实现冲突已确认。
5. **实现与游戏验收另开阶段：** 先基于确认契约写验收用例，再按批准范围施工。

## 7. 当前结论

- 这是一份按章节定位的修改建议，不是对权威总纲的直接修改。
- 当前不建议将 PR #1 合并为正式规则。
