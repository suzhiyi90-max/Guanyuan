# 社交在场与远距通信机制提案 v0.1

> 状态：**提议中，待确认**。本文件是独立提案，不代表已写入根目录权威文档《设计总纲.md》，也不授权直接进入 M1 实装。
>
> 设计目标：让“和谁交谈”不仅是打开角色菜单，而是受人物所在地点、是否在场、关系、身份与现实通信条件约束的世界行动。玩家可以直接利用眼前的人际现场获取信息，也必须为远方的人付出时间、资源与机会成本。

## 1. 核心规则

**先判断是否在场，再决定通信方式；通信方式决定时间成本、信息时效与风险。**

1. **同场可接触**：目标人物与玩家处于同一具体场景，且没有隔离、忙碌、拒绝接触等阻断条件时，可以直接发起交谈。通常不产生跨地点旅行成本，但仍可消耗交谈、观察或办事所需的行动时间。
2. **同地不同场景**：目标人物在同一县城/地点，但不在当前现场。玩家需要打听去向、前往其所在处、等待其出现，或托人递话；按路程、门禁、作息和对方公务状态计算时间。
3. **异地人物**：目标人物在另一个县、府、省或更远地点时，不能直接开启即时面对面对话。玩家必须选择当时世界可用的通信/接触方式，例如书信、差役递送、商旅捎信、熟人转达、正式公文、亲自前往等。各方式的耗时、费用、可传递内容、可追踪性、保密性和可靠性不同。
4. **通信是异步过程**：发出消息不等于对方已经收到或回复。消息需要经历投递、送达、阅读、回复、回程等阶段；对方的地点、行程、态度与权限会影响结果。
5. **不得瞬移式获取信息**：玩家不能因为认识某人，就无成本地获得远方人物的当前情报。即使关系很好，也只能改善可用渠道、回应概率、传递速度或信息质量，不能凭空消除物理距离。
6. **世界按行动推进**：通信、等待、旅行和当面交谈都通过统一的时间/行动结算进入世界状态；不另建一套脱离主时间系统的计时器。

## 2. 位置与在场判定

建议把“人物位置”建模为有明确粒度的状态，而不是单一城市字符串。

- **地点层级**：区域/省 → 府/州 → 县 → 具体场所 → 场景实例。M1 只需实现县域与少量具体场所，不要求先做全国地图。
- **位置状态**：确定在场、预计在场、正在途中、位置未知、暂不可接触。
- **场景共在**：只有同一场景实例且双方均可接触，才可直接交谈。仅仅同属一个县，不算同场。
- **可见不等于可交谈**：距离、身份礼制、差役阻拦、正在审案/议事、睡眠、疾病、冲突关系等，可以阻止或改变交谈入口。
- **位置可信度**：玩家亲眼见到、可靠人证、近期传闻、过期记录要区分。不能把“听说他在北京”直接当作实时定位。
- **离场更新**：人物移动、外出办差、调任、休假、被拘、出差等事件应更新其位置或可接触状态；不允许 UI 与权威世界状态各自维护互相矛盾的位置。

## 3. 通信渠道与代价

下表是设计方向，不是已核验的清代制度定论；具体渠道、速度与限制需结合时代设定核验。

| 渠道 | 典型用途 | 时间成本 | 费用/资源 | 信息特点与限制 |
|---|---|---|---|---|
| 当面交谈 | 现场问询、观察反应、临时商议 | 同场最低；需计入行动耗时 | 通常低 | 可追问、可观察神态，但受现场旁人影响 |
| 同地寻访 | 找人、登门、候见 | 寻找与往返耗时 | 交通、人情或礼物成本可选 | 可能扑空；对方可能避而不见 |
| 托熟人转达 | 依靠共同关系搭桥 | 交托、转达、等待回应 | 人情债、信任消耗或费用 | 取决于中间人的可靠性；可能泄露内容 |
| 普通信件 | 远距离私人联络 | 单程投递＋对方处理＋回复回程 | 纸笔、邮递/脚力或托带成本 | 可留存证据；存在延误、遗失、截获风险 |
| 商旅/差役捎带 | 依赖恰好经过的人员 | 取决于出发时机与路线 | 费用或人情 | 可能便宜，但到达时间不稳定 |
| 正式公文/公事渠道 | 官府事务、上行下达、正式请示 | 依制度、路线、优先级计算 | 行政资源与流程成本 | 适用范围受身份、职权、事项性质限制；不应自动等同私人通信 |
| 亲自前往 | 紧急、机密或高价值会面 | 旅行、住宿、等候与返程 | 高额费用、差旅与机会成本 | 可直接核实情况，但玩家离开当前岗位会产生治理后果 |

**禁止把以上方式简化成只有一个“等待 X 天”的按钮。** 至少要让玩家知道所选方式的大致耗时、成本、风险和可能的结果；精确数值可以在玩法测试后校准。

## 4. 时间、日程与异步消息状态

每条通信记录建议有以下字段：

- messageId：唯一消息标识。
- senderId / recipientId：发件人与收件人。
- channel：面对面、寻访、熟人转达、书信、差役/商旅捎带、正式公文、亲访等。
- createdAt：发起时的世界时间。
- originLocation / destinationLocation：发出与目的地。
- estimatedDeliveryAt：预计送达时间，可为空或区间。
- deliveredAt / readAt / repliedAt / replyDeliveredAt：真实事件时间；未发生时不得伪造。
- status：草拟、已发出、途中、已送达、已阅、待回复、回复途中、已完成、遗失、截获、退回、失效。
- contentSensitivity：普通、私密、机密等游戏语义标签。
- reliability / interceptionRisk：由渠道与世界状态计算，不由 UI 自行决定。
- relatedEventIds：关联的公务、人物关系、任务或证据事件。

时间结算应采用事件驱动：消息发出时登记投递事件；时间推进到相关节点时，依据路线、世界事件与人物状态结算送达；收件人处理消息后才可能生成回复事件。重复结算不得重复投递、重复扣费或生成多份回复。

## 5. 信息获取与证据质量

社交不只是“对话文本”，还会影响玩家能知道什么、何时知道、可信到什么程度。

- **现场信息**：可观察语气、神情、周围人的反应及场景线索；但旁人在场可能让人物有所保留。
- **书信信息**：适合传递明确内容、留下可引用记录；不能天然证明发件人身份或内容未被篡改。
- **中间人转述**：可能压缩、误解、添油加醋或选择性隐瞒；需要保留“原话/转述/传闻”的证据来源差别。
- **延迟信息**：消息描述的是发出时或写信时的情况，不应默认等于送达时的现状。人物位置、职务、案情可能在通信途中变化。
- **玩家推断**：推断必须和人物亲口陈述、文书记录、第三方传闻分层保存，不能因叙事表达流畅而把推断升级成事实。
- **关系影响**：信任、亲疏、利益冲突、身份差距影响对方是否接见、是否回复、是否如实回答；不应让高好感度自动解锁全知信息。

## 6. 与官场模拟的耦合

- **在场的人是有限资源**：玩家若想向某人问询，需要考虑其是否正在办公、是否有旁人在场、是否适合谈论该事项。
- **地点有机会成本**：玩家亲自去找远方熟人时，当前县域事务仍可能推进；不能暂停整个世界等待玩家旅行。
- **身份决定渠道权限**：普通私人书信、官府公文和越级请示应有不同规则。不得仅因玩家认识上级就允许其绕过正式程序。
- **关系网络不是即时通讯软件**：熟人网络可以提供引荐、转信和打听路径，但每条路径都有耗时、可信度和风险。
- **紧急事务**：可以存在加急渠道，但必须支付更高成本或承担额外制度风险；不应把所有通信统一成瞬间送达。
- **M1 范围约束**：M1 仍然只做“一县、七人、十日、一汛”。建议先实现同场交谈、县内寻访、普通书信/差人捎信的最小闭环；跨府省地图、复杂驿递网、全国官员实时位置和完整旅行模拟放入后续阶段。

## 7. 最小验收场景

1. 玩家与目标人物在同一场景且可接触：直接出现交谈选项，不要求先选择通信渠道。
2. 目标人物在同县另一场所：交谈前必须寻访、前往或托人递话，并产生相应时间成本；如果对方已离开，系统不能仍按在场处理。
3. 目标人物远在外地：不能即时面对面交谈；必须选择可用的远距渠道或亲自前往。
4. 玩家发出书信：消息状态变为“途中”，而不是立刻显示“对方已知悉”。
5. 世界时间推进到预计送达点：系统根据人物位置与路线事件结算，送达时间与实际状态有据可查。
6. 对方回复：回复需独立生成并经过回程，不得与原信同刻自动送达。
7. 通信途中目标人物调任、出差或位置变更：消息可延迟、转交、退回或失效，具体结果按规则结算。
8. 同一消息事件被重复处理：不重复扣费、不重复生成对话或回复。
9. 中间人转述：UI 清楚区分“某人转述”与“目标人物亲口说过”。
10. 玩家亲自远行时，原地点的公务与人物状态继续依世界时间规则推进。

## 8. 需要确认的设计决策

以下保持待确认，不视为已定案：

1. **世界时间粒度**：内部使用小时、半日还是日？UI 可以按更粗粒度展示，但计算粒度必须统一。
2. **M1 最小通信渠道**：建议限定同场交谈、县内寻访、普通书信、托差人/熟人捎信；是否纳入亲自离县？
3. **通信失败是否可见**：建议让玩家看见“未送达/延误/退回”等可解释状态，而非随机吞掉消息。
4. **位置精度**：玩家是否始终知道熟人所在县？建议按关系与证据逐步获知，不提供全地图实时定位。
5. **消息隐私**：是否允许截获、拆阅、泄密？建议后续阶段再做，M1 先只保留结构字段，不启用复杂间谍系统。
6. **是否允许玩家在场景中并行发起多条消息**：建议允许，但费用、投递事件与回复必须独立记账。
7. **通信耗时数值**：暂不写死具体“江苏到北京几天”等数值，待确定时代、道路、季节、渠道和游戏时间压缩比例后再校准。
