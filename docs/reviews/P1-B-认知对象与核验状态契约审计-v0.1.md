- 审计对象：总纲 3.1–3.2、3.5、14.3、15.2、15.4、附录 B.1/B.6；人物分类与社会关系规范 8.1–8.3、10；PR #74 ADJ-014/021/022。
- 性质：领域契约审计与建议，不是 schema 批准，不修改总纲/代码/存档。
- 结论：**核心原则已明确，但对象边界和状态迁移仍不闭合。当前最大问题不是字段数量不足，而是“来源说法、来源可信程度、观察者相信程度、观察者核验状态、客观真伪”没有被完整分轴。**

## 一、现有权威规则与冲突点

| 来源 | 已有规则 | 审计问题 |
|---|---|---|
| 总纲 3.1 | `knows` 旧字段含事实 ID、来源、可信度、获知时间；另有 `believes` | v0.4 遗留字段未完全从正式示例清除，容易继续把“知道”和“相信”合并 |

## 二、建议的认知对象分层

以下是审计建议的逻辑边界，不要求建立同名数据库表，也不代表字段已批准。

| 对象 | 回答的问题 | 建议最小语义 | 不得混同 |
|---|---|---|---|
| Fact | 世界中实际发生/成立的事实是什么？ | 由权威规则/事件账本确认；有来源事件、有效时间 | 不等于任何人物已经知道 |
| Claim | 某个来源具体声称了什么？ | 命题内容、提出者、提出时间、指向事实/对象、原始表述版本 | 不等于客观真相 |
| Evidence | 哪些材料支持、反驳或限定某个 Claim/Fact？ | 材料 ID、来源、取得方式、关联命题、支持/反驳/中性作用、保管/真伪状态 | 不等于核验结论 |
| SourceAssessment | 来源为何这样说、来源本身是否可靠？ | 来源立场/利益/知识位置，与其可靠性评价分开 | 不等于玩家相信程度 |
| Exposure | 某观察者通过什么路径接触到什么对象？ | observer、objectRef、channel、occurredAt、accessReason、visibility | 不自动代表阅读、理解或相信 |
| Comprehension | 观察者是否理解内容、理解到何种程度？ | observer、objectRef、状态、依据、时间 | 不自动代表相信 |
| Belief | 观察者目前对某命题持何立场、信念强度如何？ | observer、claimRef、stance（支持/反对/悬置/不知）、confidence、basisRefs、有效期 | 不等于客观真伪或官方核验 |
| Verification | 观察者/制度主体基于哪些证据得出何种核验结论？ | verifier、claimRef、status、evidenceRefs、方法、时间、范围、结论版本 | 不等于来源可靠性或个人信念 |
| Memory | 观察者保留了哪些记忆摘要？ | 来源事件/Claim/Evidence/Exposure 引用、压缩/衰减/失真记录 | 不能作为原始证据或新事实 |
| Rumor/Transmission | 某说法如何在主体间传播、变形？ | 原始 Claim、每跳传播事件、发送/接收、渠道、延迟、变体、保密级 | 不得覆盖原始 Claim 或自动确认为事实 |

## 三、必须拆开的五条轴

1. **客观真伪（Truth）：** 由世界规则/权威事件确定；可以是未知、已成立、已否定或范围受限。不能由玩家相信程度决定。
2. **来源立场（Source Stance）：** 来源是支持、反对、回避、误述还是有意欺骗；这是对来源表达/动机的描述，不等于可靠性。
3. **来源可靠性（Source Reliability）：** 来源在该领域/该类信息上的能力、接近事实程度、利益冲突、过往准确性；不应使用“确知/相信/听说”来同时表达来源身份与可靠性。
4. **观察者信念（Belief）：** 玩家或 NPC 当前相信/不信/悬置什么，依据哪些材料，置信程度如何。
5. **核验状态（Verification）：** 某一观察者或制度程序已做了哪些核验、得到什么范围的结论。核验状态是调查进度/结论，不是事实真伪的替代字段。

另需单独记录 **信息接触链**：接触、送达、阅读、理解、相信、核验、行动是不同过程。远距通信的送达/阅读状态不得直接更新 Belief 或 Verification。

## 四、14.3 四档状态审计

现有四档描述存在两个结构问题：

- “已核实 / 听说 / 推测 / 存疑”不是同一维度的互斥等级：已核实/存疑偏核验结论，听说偏信息来源/获取方式，推测偏认知形成方式。
- “只降不升，除非新证据”同时要求状态只能下降和允许凭新证据上升，但没有定义哪些证据有效、何时可以恢复、谁有资格核验、如何保留旧结论。

建议将四档作为**玩家情报台账的展示分组/粗粒度核验标签**，而不是通用底层状态枚举。底层需允许至少以下情形分别存在：

- 尚未核验；
- 正在核验/证据不足；
- 当前证据支持；
- 当前证据反驳；
- 证据冲突/无法判断；
- 已核验但范围有限；
- 旧结论被新证据修订。

最终展示标签可继续沿用四档，但映射必须有清晰规则，且不覆盖证据与历史。

## 五、状态迁移建议

| 事件 | Exposure | Belief | Verification | 必须保留的证据/历史 |
|---|---|---|---|---|
| 听闻一条传闻 | 产生 told/rumor 接触 | 默认不自动相信；可保持未知或形成初步立场 | 不自动核验 | 传播来源、转述链、接触时间 |
| 阅读正式文书 | 产生 document 接触/阅读记录 | 可形成相信、怀疑或悬置 | 不自动成为已核实 | 文书版本、签押/来源、阅读者 |
| 亲眼观察 | 产生 observed 接触 | 可形成基于观察的 Belief | 只对可直接观察范围提供证据 | 观察者、地点、时间、视野/条件 |
| 获得支持性证据 | 新增 Evidence | 允许提高/降低/维持信念，取决于证据指向 | 可推进核验 | Evidence 来源、真伪、关联命题 |
| 获得反证 | 新增 Evidence | 允许反转/降低信念 | 允许撤销或修订旧核验结论 | 保留旧结论与修订原因 |
| 发现伪造/误传 | 新增反证/来源评估 | 修订相关 Belief | 将原核验结论标为撤销/修订，不删除历史 | 伪造者/传播者、原始版本、纠正传播 |
| 多来源互相矛盾 | 分别记录接触 | 允许同时保留不同立场 | 标为证据冲突/范围未定 | 每个来源独立引用，不做简单平均 |
| 记忆衰减/失真 | 不删除既有接触事实 | 记忆可弱化，不得自动改写原始 Belief 历史 | 不改变权威核验记录 | Memory 版本与来源引用 |

不得把“出现一份新证据”简单定义为自动升级。证据必须先验证来源、相关性、真实性、时间范围与反证关系，再由核验规则决定是否更新。

## 六、关键反例测试

| ID | 输入/情境 | 必须成立的结果 |
|---|---|---|
| COG-01 | 玩家听到粮商说“县衙欠我三百两” | 记录来源 Claim/Exposure；不得自动创建客观债务 Fact |
| COG-02 | 玩家收到正式欠据 | 记录文书接触和 Evidence；不因“正式文书”自动认定真实有效 |
| COG-03 | 书办说法与账册冲突 | 两条 Claim 并存；分别评估来源与证据，不覆盖任何一方 |
| COG-04 | 玩家相信错误传闻 | Belief 可为错误；Fact 不变；AI 叙事按玩家认知过滤 |
| COG-05 | 后续出现强反证 | Belief/Verification 可修订；旧状态和旧证据仍可追溯 |
| COG-06 | 来源利益冲突明显但所述事实正确 | 来源可靠性可低、Claim 仍可能为真；不能把来源不可靠等同命题为假 |
| COG-07 | 可靠来源在其专业范围外发言 | 对不同领域的可靠性不可无条件继承 |
| COG-08 | 消息送达但未阅读 | 只有送达/接收状态；不产生阅读、理解或相信 |
| COG-09 | 阅读但不理解 | Exposure/阅读已发生；Comprehension 不得标为已理解；Belief 不自动改变 |
| COG-10 | 理解但不相信 | 理解状态成立；Belief 可为反对/悬置 |
| COG-11 | 同一 Claim 经两条渠道传播 | 传播事件各自有链路；原始 Claim 不重复、不被覆盖 |
| COG-12 | 一条传闻多次转述且失真 | 每次传播可追溯父级版本；失真不回写原始事实 |
| COG-13 | 同一证据重复导入/重复引用 | 幂等，不重复提升核验状态或生成重复事实 |
| COG-14 | 新证据只证明部分时间/地点 | 核验结论必须限定范围，不外推到全部时期/区域 |

## 七、审计裁定与下一步

| 检查项 | 结论 |
|---|---|
| 客观事实与观察者认知分离 | **原则通过**，对象引用和实现契约未闭合 |
| Exposure 与阅读/理解/相信分离 | **不通过**：附录 B.6 示例混合字段 |
| Claim/Evidence/Belief/Memory/Rumor 对象边界 | **部分通过**：3.5 有概念，字段关联与版本语义缺失 |
| 来源立场与来源可靠性 | **不通过**：尚无独立、稳定的语义定义 |
| 玩家核验状态与来源可靠性 | **不通过**：14.3 名称和三档描述容易混用 |
| 核验升级/降级/反证/历史 | **不通过**：14.3 “只降不升”规则不完整 |
| AI 可见上下文边界 | **原则通过**：需将引用与权限过滤纳入测试 |
| 当前 M1 是否需立即实现完整认知系统 | **否**：先做现有情报台账与事件引用的契约审查，不扩建完整社会认知系统 |

**建议裁决：** 先将 14.3 四档明确为 UI/玩家情报台账展示标签；底层拆分 Claim、Evidence、Exposure、Comprehension、Belief、Verification、SourceAssessment 与 Rumor/Transmission 的语义；来源立场和来源可靠性分离；允许新证据触发升级、降级或维持，但每次变更必须记录证据依据、范围、时间和旧结论，不允许覆盖历史。

**当前结果：P1-B 审计完成，规则/schema 裁决未完成，代码施工不启动。**
