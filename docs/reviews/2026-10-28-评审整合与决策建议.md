# 双评审对照与整合决策

- **评审 A：** `docs/reviews/2026-10-28-设计评审-v0.2.md`（本项目内，544 行设计单评审）
- **评审 B：** `设计评审与优化建议-v0.3.md`（外部评审，586 行）
- **本文性质：** 不对两份评审做复述，只做**裁决**：哪里一致（可信）、哪里冲突（谁对）、哪里互补（合并）、哪里都不够（补强）。
- **一句话结论：** 两份评审在"砍范围、做可读性、先纸面验证"三点上高度一致——**这种独立收敛的共识，基本可以当作事实接受**；分歧集中在时间粒度、输入方式、AI 分工三处，本文给出裁决。

## 二、十二条共识（两份都指向同一结论，可直接执行）

1. **砍范围**：第一阶段不做仕途全流程、不做人物卡美术链、不做全量自然语言命令。
2. **核心循环必须先能一句话说完**，说不出来就是没收敛。
3. **加一个外部时钟**：没有"催命的东西"，时间只是资源条。B 的"三重时钟"（汛期/考成/人情）可直接用。
4. **可追溯 ≠ 可读**。必须有解释装置：三行日志、因果分解面板、情报台账。
5. **拒绝单一好感度**，但必须给替代品——玩家要的是判断依据，不是数字。
6. **越权不是红叉，是内容**：失败提示要精确到缺哪一项（额度/程序/资格/地域），并给合法绕法。
7. **失败要做成内容**：失败阶梯 + 革职后换线（幕友/乡绅），抑制读档冲动。
8. **AI 不能写业务状态**；上下文必须按"该人物可知"过滤，这是防泄密唯一可靠办法。
9. **成本必须分层**：模板承担大部分文本，小模型做解析，大模型只做关键对话。
10. **先纸面，后代码**：在写第一行业务代码前，用纸面原型验证"信息差是否有趣"。
11. **人物卡/美术是生产期问题**，不是验证期问题。
12. **两份文档必须合并**，否则治理规则自己就破产了。

## 三、五处分歧与裁决

### 分歧 1｜时间：连续时间 vs 四时段

**A 主张**：保留连续时间，用"期限冲突 + 时间预算界面 + 事件打断"解决等待感。
**B 主张**：改为晨/午/暮/夜四时段，行动即结算，关键事件暂停。

**裁决：采纳 B。**

理由：
- 连续时间与 LLM 延迟天然冲突——玩家读文本时世界在跑，产生"错过焦虑"；这是体验问题，不是技术问题。
- 四时段可测、可存档、可回放，且适合移动端碎片时间。
- A 的"期限冲突"不是时间粒度问题，是**压力设计**问题，两者可以并存。

**落地方式（融合）**：
- 一天四时段，每段 1–3 个行动点（由身体状态决定）。
- 行动结束即结算；关键事件**主动暂停并弹窗**，不流过去。
- 夜间结算产出"这一夜世界发生了什么"三行摘要——用这个保留"世界在走"的连续感。
- 硬期限挂在**日**上，不挂在时辰上（汛期第 25 日、考成第 20 日、欠款第 15 日）。

### 分歧 2｜输入：自由输入是主入口还是加速器

**A 主张**：默认话术树，自由输入作为增强，但必须有"我理解为……"的解析回显。
**B 主张**：结构化命令为主，自然语言**只用于和 NPC 对话**，不用于对系统下令。

**裁决：采纳 B 的分工，保留 A 的回显。**

理由：B 的四条理由（不可发现、慢、贵、难测）都是产品级硬伤；A 的"回显"是缓解不可发现性的关键，但不解决根本问题。

**落地方式**：
```
主入口：[选动作] 支取 → [选对象] 河工银 → [填条件] 300两/三日/主簿监督
        → [预览] 合法；需县丞副署；将生成委任状 → [确认]
旁路：  任意步骤可直接打字，系统立刻解析为"最接近的动作"并回显确认
对话：  与 NPC 交谈时用完全自然语言（这是 AI 的主战场，也是卖点所在）
```
**一句话：自然语言用于"跟人说话"，不用于"对系统下令"。**

### 分歧 3｜时代：架空+明清骨架 vs 架空晚清

**A 主张**：三选项对比，推荐架空+明清制度骨架。
**B 主张**：架空晚清州县，以清代制度为底本。

**裁决：采纳 B（架空晚清），但加一条边界。**

理由：晚清吏治材料最丰富（杜凤治日记、幕府、陋规、亏空、保固），制度最成熟也最腐朽，戏剧张力最大；且设计单 7.7 已经引用杜凤治日记，实际早就默认了清代。

**边界**：把时间锚定在**"近代冲击到来之前的封闭州县"**（架空年号，不涉洋务、教案、外患）。理由：一旦引入近代性，复杂度会指数上升，且容易触碰历史敏感区。

### 分歧 4｜P0 规模：5 人 vs 7 人

**A 主张**：1 场景 / 5 人物 / 3 期限 / 话术树。
**B 主张**：一县、七人、十日、一汛。

**裁决：采纳 B（7 人）。**

理由：5 人测不出"信息差"的复杂度。要制造"三个说法互相矛盾"，至少需要：县令（玩家）、县丞（有利益）、河工专家（有专业但无权限）、粮商（掌握资源）、士绅（有影响力）、主簿（掌握账目）、工程执行者（掌握一线）。**7 人是产生"罗生门"的最小配置。**

### 分歧 5｜AI 定位：多视角翻译 vs 证据化+模板优先

**A 主张**：AI 只做"同一事实的多视角翻译"（同一事件，三个人的说法不同）。
**B 主张**：记忆证据化（事实 ID + 来源 + 可信度 + 保密级），L1 模板承担 80% 文本，L3 只做关键对话。

**裁决：不冲突，是三层，合并。**

```
事实层（规则引擎）：一条权威事实 {事件, 时间, 知情者, 保密级}
  ↓
模板层（L1，零成本）：同一事实生成 N 个"视角版本"——主簿的推责版、粮商的利益版、传闻的失真版
  ↓
模型层（L3，按需）：把某个视角版本"说得像人话"，带上人物的语气、口头禅、情绪
```
**关键判断：A 的"多视角"是内容策略（模板层就能做），B 的"证据化"是数据架构（规则层）。两者不在同一层，所以都要。**

## 四、对评审 B 的四点补强

B 已经很强，以下四点我认为它给了方向但没给够落地：

### 补强 1｜债的戏剧性来自"见证人"，不是债本身

B 的 Debt 结构里有 `witnesses` 和 `public`，但没给传播规则。没有传播，债就只是"另一种货币"。

**建议补三条规则：**
- **传播触发**：见证人会以概率主动传播（概率 = f 关系亲密度、利益冲突、酒醉/失言）。每传播一次，witnesses +1。
- **公开阈值**：witnesses ≥ 3 或涉及第三方利益时，`public` 转真，成为政治风险（可被参、被要挟）。
- **死亡/调任转移**：债按亲疏部分转移给子侄门生——这是"长期人生"的实体化，也是本作最独特的长尾。

**一句话：债的价值不在"欠多少"，而在"谁知道了"。**

### 补强 2｜挪用公帑如果没有"审计节奏"，玩家一定全挪

B 提了"亏空挂账"和"保固期"，但没写"谁在什么时候查"。玩家很快会发现最优解就是挪用（因为工程要办成）。

**建议明确三个审计触发点，并让每个都可被玩家影响：**

| 审计 | 触发 | 玩家可做的事 | 后果 |
|---|---|---|---|
| **离任审计** | 调任/革职时 | 做平账目、找替罪、求上司压下来 | 亏空暴露 → 赔补/参劾 |
| **考成审计** | 三年一考 | 提前补账、用政绩抵、走关系 | 考语降等 |
| **被参** | 政敌发动 | 反查对方、找靠山、以功抵罪 | 交部议处 |

**关键：让"做账"成为一个可玩的动作**（耗时、有风险、需要人配合），而不是一个隐藏的判定。

### 补强 3｜"行状"应该做成可分享的传播资产

B 说行状"玩家会截图分享"，但没往产品化推一步。

**建议**：
- 行状自动生成**两种形态**：游戏内一页（阅读用）、可导出的长图（分享用，带水印与二维码）。
- 每章结束自动生成"这十日行状"，玩家可编辑一句"自评"。
- 行状是 **AI 最该发力的地方**：有真实事实基础、有情感、可缓存、可复用——比对话更值得花 token。

**这是零成本获客：玩家分享的不是战绩，是自己写的一段历史。**

### 补强 4｜M0 纸面原型需要一个可执行的试玩脚本

B 说"3 局真人试玩（同事即可）"，但没说主持人怎么带。

**建议补一个 30 分钟纸面脚本：**
1. **0–5 min**：给玩家一页"你是新任县令"背景 + 一份堤身渗水的呈文（三人说法不一）。
2. **5–20 min**：玩家可"问"任意人物（主持人扮演，照人设卡回答，允许说谎）。
3. **20–28 min**：玩家做一次委托（选人、定预算、定期限），主持人按公式掷骰给出五档结果之一。
4. **28–30 min**：主持人问三个问题——"你觉得谁在骗你""你为什么没办成""你还想玩吗"。

**判据：H1 成立 = 玩家在第 15 分钟前主动去核账/交叉验证，而不是直接下命令。**

## 五、评审 A 中建议保留的四点（B 未覆盖）

1. **疲劳影响"信息质量"而非"行动点"**
   B 的方案是"疲劳→次日行动点减少"（数量惩罚）。建议升级：疲劳时 NPC 的微表情提示失真、账册比对会"看漏"一行。这样疲劳变成**风险偏好**（可以硬撑，但第二天容易被人骗），而不是体力条。
   *理由：本作主题是"信息差"，让身体状态作用于信息质量，比作用于行动数量更贴合主题，也更高级。*

2. **LOD 三层模拟与升降级条件**
   B 提了"7 核心 + 20–30 背景 + 离线结算"，但没写"玩家靠近时如何升级、离开后如何降级"。缺这条会出现"玩家一进村，NPC 行为突变"的穿帮。
   建议：`L0 背景统计层（人口/经济/舆情，按日聚合）→ L1 事件驱动层（重要人物按日程与目标推进）→ L2 全模拟层（玩家所在场景，逐行动结算）`，并明确升级触发（进入场景/建立关系/事件关联）与降级时的状态压缩规则。

3. **文档治理的具体丢失清单**
   B 指出两份文档分叉，但没说丢了什么。逐行对比结果：详细版独有的《17.5 叙事一致性测试》《18.2 决策状态》《18.4 变更工作流》，以及 3.4 的"四段式互动判定"（动作是否存在/能否执行/对方是否愿意/实际影响），在 canonical 版中全部消失。
   **这四块必须补回**，尤其"四段式判定"应升为独立原则——它比现有 14 条原则里的一半都更实用。

4. **症状 → 调查动作的完整映射**
   B 给了公式和五档结果，但"玩家看到什么"只有一句"料少了 15%"。A 的症状表可直接并入：

| 衰减类型 | 可见症状 | 调查动作 |
|---|---|---|
| 能力不足 | 进度慢，报告却乐观 | 现场查看、换人 |
| 协调不畅 | 两份报告口径不一 | 交叉比对、召见 |
| 资源损耗 | 账实不符、损耗异常 | 查账、盘库 |
| 信息过滤 | 坏消息总晚三天 | 安插眼线、私访 |
| 利益抵抗 | 表面答应，节点卡住 | 施压、给好处、找靠山 |

## 六、合并后的 6 周执行包

```
第 1 周｜决策冻结
  拍板 5 件事：时代（架空晚清·封闭州县）/ 关系（三问+人情簿）/ 时间（四时段）
             / 输入（结构化+对话NL）/ 范围（一县七人十日一汛）
  合并两份文档为单一权威源，补回丢失的四块内容

第 2 周｜纸面原型
  7 张人设卡（A4）+ 1 份河工账册 + 30 张事件卡 + 30 分钟试玩脚本
  目标：验证 H1（信息差是否有趣）

第 3 周｜纸面试玩 3 局
  判据：≥2 局玩家在第 15 分钟前主动核账；≥2 局能说出"谁在骗我"
  不达标 → 改设计，不写代码

第 4 周｜技术 Spike（只在纸面通过后做）
  ① 意图解析准确率 ② 交互 P95 延迟 ③ 记忆召回率 ④ 单小时成本 ⑤ 无 AI 可通关

第 5–6 周｜M1 骨架
  四时段循环 + 一次委托 + 五档结果 + 因果分解面板 + 情报台账 + 三行日志
  目标：能连续玩 25 分钟不卡住
```

## 七、如果只做五件事

1. **纸面原型先跑 3 局**，验证"信息差是否有趣"。这是唯一能低成本否证整个项目的方式。
2. **把"债"做成有见证人、会传播、会被翻出来的账**，而不是另一种货币。
3. **加三重时钟**（汛期/考成/人情），让时间有催命感。
4. **上三件解释装置**（三行日志 / 因果分解面板 / 情报台账），解决"可追溯但看不懂"。
5. **用"行状"替代人物卡**，零美术成本换成就感与传播。
