# 变更影响矩阵 v0.2

- 状态：治理索引；用于追踪变更，不独立批准规则。
- 权威源：以 `main` 上已批准的《设计总纲》v0.16 和正式规范为准。候选提案、审计意见、实现现状不得自动升级为产品规则。
- 使用方式：变更前登记受影响章节/模块/参数/测试；变更后逐项记录“已同步”或“不受影响及理由”。矩阵中的待审计项必须保留为待审计。
- 范围纪律：当前 M1 原型不等于完整官场人生，更不等于完整非官场人生。本轮只完善现有功能治理，不开展完整 AI 世界/事件锚点/批量内容生产架构。

## 状态轴（必须分开记录）

| 轴 | 可用状态示例 | 回答的问题 | 不得替代 |
|---|---|---|---|
| 产品裁决 | 候选 / 已讨论 / 已批准 / 已废止 | 产品决定采用什么规则？ | 史实是否可信 |
| 历史置信度 | 未核 / 有来源待复核 / 多源支持 / 存在争议 / 不适用 | 历史陈述证据有多可靠？ | 产品是否决定采用 |
| 参数验证 | 未设 / 待校准 / 已测试 / 已冻结 / 不适用 | 数值参数是否经过验证？ | 规则是否批准 |
| 实现状态 | 未排期 / 设计中 / 开发中 / 已实现 / 已回滚 | 代码做到哪一步？ | 验收是否通过 |
| 验收状态 | 未验 / 失败 / 部分通过 / 通过 | 交付是否满足门槛？ | 产品裁决或史实置信度 |

## 每次变更的强制检查

- [ ] 唯一规则 ID、权威定义位置和产品裁决状态明确。
- [ ] 直接/间接模块及受影响章节逐项核对。
- [ ] 参数、史料、示例、人物/职位/文书表和测试逐项核对。
- [ ] 产品裁决、历史置信度、参数验证、实现状态、验收状态分开记录。
- [ ] 重复提交、拒绝、重试、同刻事件、跨日、随机复现和回放一致性已检查。
- [ ] 相关但未修改的章节已注明不受影响的理由。
- [ ] 明确候选、已批准、进入 main、已实现、已验收的区别。
