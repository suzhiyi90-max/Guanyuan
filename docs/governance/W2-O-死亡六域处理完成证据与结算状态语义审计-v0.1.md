# W2-O 死亡六域处理完成证据与结算状态语义审计 v0.1

状态：审计裁决草案；基线为 `work/w2-n-goal-status-history`。
范围：只审计 W2-F 至 W2-N 的现有死亡连续性模型；本切片不改领域运行代码。

## 1. 核心裁决

不得仅凭 `DeathRecord.estateSettlements` 中六条记录齐全、`status = settled` 或一个汇总布尔值，认定死亡后的六域处理已经完成。

W2-F 的 `validateDeathSettlementReferences` 只证明死亡事件和结算事件引用/时间可追溯。它不证明具体领域事项已全部盘点，也不证明每一项均有合法处置。

因此，后续协调器必须建立在领域级完整范围证明和逐项处置证明之上。协调器只能汇总证据，不得替代领域规则。

## 2. settled 的语义

建议将死亡记录中的领域状态 `settled` 明确定义为：

> 对该死者、该死亡事件及已声明的领域范围，所有已知适用事项均已完成领域规定的死亡后审查和处置，且每项处置均有可验证来源。它不代表所有相关债务已清偿、资产已变现、关系已消失或社会影响已终止。

必须严格区分：
- 死亡后领域处理完成（estate settlement domain settled）；
- 原始债务已清偿（Debt.status = settled）；
- 资产所有权已转移；
- 组织、关系、目标等事实已终止或转承。

任一底层义务仍未作出明确处理决定时，该死亡领域不得标为 settled；允许其他领域独立完成。

## 3. 现有六域覆盖审计

### office
现有 `validateDeathOfficeAppointmentClosure` 校验死者任职区间在死亡时关闭；W2-H 授权主体死亡门禁阻止死者在死亡后行使授权，并保留其生前授予他人的授权。
缺口：尚无一份与死亡事件绑定的任职域范围清单/完整性声明，也没有统一证明该人所有任职与授权记录均已纳入审查。
后续要求：范围声明覆盖 appointments 与 authorizations；逐项结果区分死亡关闭、历史已结束、他人持有的授权继续有效、需要撤销/审查等合法结果。不得默认撤销所有授权或自动补任。

### debt
现有 `validateDebtPartySuccessions` 校验明确的债权/债务承接及份额；原始 Debt 保持不变，承接不等于清偿。
缺口：没有对死者作为 creditor/debtor 的完整债务范围盘点，也没有对“无承接记录、仍待处理”的债务作显式结论。只传入部分 Debt 列表即可通过逐条校验，不能证明债务域完整。
后续要求：范围声明必须分别盘点死者作为 creditor 和 debtor 的所有债务角色；每一项必须有明确的承接、继续未决、争议或其他经制度规则允许的处置。未决事项不得被静默视为完成。不得从亲属、资产继承或组织关系推断责任承担。

### asset
现有 W2-J `EstateAssetInventory`、完整性覆盖和 `isEstateAssetInventoryReadyForSettlement` 已提供较完整的单域模式。
保留边界：complete 只是对调用方资产全集的清点声明，不证明现实中不存在未登记资产；只有 complete、无验证问题、所有 deceased 项 transferred、所有 other 项 excluded 且无 undetermined 项，才达到该模型的结算准备度。
后续要求：协调器直接消费该准备度结果及对应 inventory 证据，不复制资产权属推导逻辑。

### membership
现有 `validateMembershipDeathContinuity` 扫描传入的成员记录，要求死者死亡时仍有效的 Membership 由死亡事件关闭；W2-K 允许显式建立同组织内的新成员资格。
缺口：没有声明传入 memberships 已覆盖该人物在适用组织中的完整成员资格集合。遗漏一条成员记录无法由逐条验证发现。
后续要求：建立与死亡事件绑定的成员范围清单/完整性声明；每条成员资格都必须可追溯到关闭、死亡前已结束或经明确事件承接的新成员资格。不得复制死者角色/义务。

### relation
现有 `validateRelationDeathContinuity` 对传入的所有关系逐端点检查死亡处置，保留有向、多重关系；允许一方死亡后保留关系，另一方之后死亡时再独立处置。
缺口：缺少该人物关系全集的范围证明；若调用方漏传一条关系，校验器无法发现。
后续要求：关系范围声明必须覆盖所有与死者相连的 Relation ID；逐条保留或终止，并保留双方分别死亡时的时间顺序。不得从关系类型推断法律后果。

### goal
W2-M 要求死者未竟 active Goal 显式处置；W2-N 要求普通终态 Goal 有唯一状态转换记录，并与死亡处置分离。
缺口：验证器只能校验传入的 goals；缺少人物目标集合的完整性声明，无法发现漏传的 Goal。
后续要求：目标范围声明覆盖死者所有 NPC Goal；每项目标必须为死亡处置、死亡前已形成的普通终态转换，或其他明确允许的历史状态。PlayerGoal 不纳入 NPC Goal 盘点。

## 4. 统一证据结构的设计要求

后续可设计统一的 `DeathSettlementDomainInventory` / `DeathSettlementDomainEvidence` 概念，但不得把六域压成无类型的字符串列表或布尔值。

至少应具备：
- deceased、deathEvent、domain；
- inventoryEvent / reviewEvent 及其事件时点；
- 被盘点事项的稳定 ID 集合；
- 完整性声明及其来源；
- 每项处置的领域类型、处置事件和领域证据引用；
- 明确区分 empty-but-reviewed（范围为空且有依据）与 missing/unknown（未证明完整）；
- 可审计的校验错误，且验证只读。

统一层只检查身份、死亡事件、范围声明、证据引用、事件时间和领域覆盖关系；每种事项是否合法处置仍由对应领域验证器裁决。

不得用空数组自动推导“该领域没有事项”。必须有来源事件支撑的空范围声明。

## 5. 结算协调器的准入门槛

在以下条件全部满足前，不得实现或调用六域结算协调器：
1. 六个领域各自有可验证的完整范围声明；
2. 六个领域逐项处置均可追溯，且未决/争议事项不会被误判为 settled；
3. 空范围有显式来源事件；
4. 领域证据引用与死亡事件、人物和事件时点一致；
5. 同一事项不能被重复计入或跨领域误分类；
6. 资产准备度、债务承接、任职/授权、成员、关系、目标的语义保持各自独立；
7. settled 与底层债务清偿、资产转移、关系终止等状态严格区分；
8. 失败校验不得产生部分写入，不得自动修改任何领域记录。

## 6. 本审计切片不做

- 不修改 `Person`、`DeathRecord`、`EstateSettlementRef` 类型；
- 不新增六域协调器或自动结算器；
- 不自动将 pending 改为 settled；
- 不推断法定继承、亲属义务、债务承接、职位继任或关系法律效果；
- 不接 W3 Event Ledger、AI 写入、存档迁移、G1 runtime 或 UI。

## 7. 下一步建议

按“先有完整范围证明，再接汇总协调器”的顺序施工。建议下一切片先建立可复用的范围声明基础类型和校验契约，并选取债务域作为首个试点，因为它最容易暴露“无承接记录并不等于无需处理”的语义缺口。债务试点通过后，再逐域接入 office、membership、relation、goal；asset 复用 W2-J 已有 inventory。
