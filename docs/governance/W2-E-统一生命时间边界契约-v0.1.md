# W2-E 统一生命时间边界契约 v0.1

状态：W2-E 施工契约；依据 v0.16《设计总纲》及《世界生命与自由人生模拟系统设计规范》。
基线：W2-D `work/w2-d-life-stage-facts`。

## 1. 目标

统一人物出生、死亡时点对所有事件型生命记录的约束，避免人物历史、身体/心理 hook、身体/心理状态事实和人生阶段各自实现不同的时间边界。

本切片只定义记录时点是否合法，不计算寿命、衰老、疾病或死亡概率。

## 2. 时间边界裁决

- 已知出生时点：生命事实不得严格早于出生时点；出生时点本身允许记录。
- 已知死亡时点：普通生命事实不得严格晚于死亡时点；死亡时点本身允许记录。
- 出生或死亡为 unknown、not-generated、n/a 时，不推测、不补造边界。
- 事实时点无效时，由对应领域校验器报告时间无效；共享边界函数不重复承担时间格式校验。
- 不以 archiveState 替代 lifeState；归档不等于死亡。

## 3. 统一覆盖范围

同一共享边界函数接入：
1. LifeHistoryEntry；
2. LifeDomainHook（body / mind）；
3. LifeStateFact（body / mind）；
4. LifeStageFact（各独立生活轨道）。

各领域保留自己的 issue code，便于调用方定位记录类型；比较逻辑只维护一份。

## 4. 不变量

- 事实仍须引用存在的来源事件，且事件时间与事实时间一致。
- 共享时间边界不代替事件存在性、来源时间、scope、visibility、supersedes 等领域校验。
- 历史追加失败必须返回原集合，不得部分写入。
- 死亡时点及之前的历史保留；人物死亡不删除档案。
- 未知出生/死亡不产生虚构边界。
- 不因阶段名称推断婚姻、官职、亲属、功名或身体状态。

## 5. 明确不做

不实现出生率、寿命分布、死亡风险、衰老曲线、疾病/治疗效果、自然时间推进、六域身后结算执行器、W3 Event Ledger、AI 候选写入、存档迁移、G1 runtime 或 UI。

## 6. 验收

- 共享边界函数覆盖严格早于出生、出生时点、生命期间、死亡时点、严格晚于死亡。
- unknown / not-generated / n/a 不补造边界。
- 四类生命记录校验器均接入共享函数。
- 各领域保留独立 issue code；非法记录拒绝。
- W1-A 至 W2-D 全回归、专项测试、生产构建、Playwright Smoke 与截图归档全部通过。
