## 4. 若将来批准，正确的合并方式

不得把 PR #2 整包合并。建议按以下顺序：

1. 从最新 main 建新分支，重新应用**已批准的单条裁决**，不 cherry-pick 整个 PR #2。
2. 每条改动在总纲中写明规则 ID、原条款、替代关系、迁移影响（20.3）。
3. 同步更新附录 A/B、规则目录、依赖矩阵、变更影响矩阵与验收判据。
4. 只改正式总纲中已批准的条款；候选说明、状态行、历史记录不进入正文。
5. 合并前重跑静态检查：ID 唯一、无循环依赖、参数无冲突、JSON 示例有效、场景可唯一推演。
