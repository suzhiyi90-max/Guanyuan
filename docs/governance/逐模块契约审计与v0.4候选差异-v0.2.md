## 一、审查方法

每个模块按十个字段检查：

1. 当前规则（main 正文怎么写）
2. 规则 ID（规则目录中的登记）
3. 输入/输出
4. 上下游（依赖方向）
5. 唯一权威（同一语义只能有一个定义处）
6. 章节/示例
7. 重复/遗漏/循环/越权写
8. M0 场景（A–H 中哪个能暴露问题）
9. 修订建议（指向 ADJ）
10. 是否需产品负责人裁决

判定口径：

- **重复**：同一语义在两处以上定义，且措辞可推出不同结果。
- **遗漏**：正文有原则，但没有字段、流程、失败路径或验收条件。
- **循环**：模块 A 直接读 B 的权威状态，B 又直接读 A，形成双向写依赖。
- **越权写**：下游模块（视图/行状/AI/文书）直接改变权威状态。

## 三、跨模块问题

### 3.1 依赖环与解耦

| 潜在环 | 表现 | 解耦方式 |
|---|---|---|
| 社交 ↔ 认知 | 社交产生 Claim，认知过滤社交 | 社交只发事件；认知只读事件，不反写社交状态 |
| 委托 ↔ 经济 | 预算改任务，任务完成改余额 | 用 `reservation` 对象；任务/账目各自订阅事件 |
| 权限 ↔ 文书 | 文书证明权限，权限签发文书 | 职位权限为主；文书是证据，不授予权限 |
| 考语 ↔ 关系 | 关系改考语，考语改关系 | 考语只读事件/证据；关系变化另发事件 |
| 导演 ↔ 事件 | 导演读事件又插事件 | 只排未来 `triggerAt`，不回写当前段 |
| 行状 ↔ 事实 | 行状被编辑后成事实 | 行状只投影；更正发事件 |
| AI ↔ 状态 | 模型输出被当命令 | 模型只出候选意图；命令总线校验后提交 |

### 3.2 越权写清单

| 下游 | 不应写 | 应做什么 |
|---|---|---|
| UI | 时间、任务、余额、Belief | 提交命令/读视图 |
| 行状/人物卡 | Fact、Belief | 读已提交事件，生成投影 |
| 文书 | 权限、任务完成 | 作为证据/凭证被引用 |
| AI | 世界状态、资源、时间 | 生成表达/候选意图 |
| 事件导演 | 当前段已结算事件 | 排未来事件 |
| 索引/矩阵 | 规则语义 | 只登记 ID/位置/影响 |

### 3.3 唯一权威缺口

| 语义 | 当前多处 | 建议唯一位置 |
|---|---|---|
| 时间单位/成本 | 9.1、4.5、20.2、附录 A | 9.1（成本表可放附录 A，但语义只在 9.1） |

| 考语 | 7.2、17.3、D-009 | 7.2 |
| 事件顺序 | 9.3、10.5、13.2 | 10.5（9.3/13.2 只引用） |
