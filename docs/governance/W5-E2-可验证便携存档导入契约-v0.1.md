# W5-E2 可验证便携存档导入契约 v0.1

## 1. 施工定位

- 基线：W5-E1 可验证便携存档导出，分支 `work/w5-e1-portable-save-export`，验收 SHA `89be7150b0698e74d27b8e96322a48bfe7d3ddce`。
- 本片在 E1 的 `guanyuan.portable-save` v1 envelope 上增加本机导入；不改变事件账本、EventSchema、Reducer、SavePackage 格式或既有世界事实。
- 本片只导入当前应用支持的 preview runtime schema 与 portable format v1；不做历史版本迁移、upcaster、合并、覆盖或云同步。
- 施工分支从 E1 验收 SHA 派生；PR base 为 E1 分支，保持 Draft/Open，不合并，不改 main。
- 先冻结本契约，再施工代码。不得把导入动作混入 E1 导出实现后直接开写。

## 2. 导入输入与信任边界

导入输入只能来自用户主动选择的本地 JSON 文件。文件内容、文件名、MIME、时间戳、WorldId、checksum 与 package chain 全部视为不可信数据。

支持的 envelope 必须严格满足 E1 格式：

- `format === 'guanyuan.portable-save'`。
- `formatVersion === 1`；未知版本立即拒绝。
- 顶层字段严格限定为 `format / formatVersion / exportedAt / worldId / streamHead / packageChain / envelopeChecksum`，不得静默接纳未知字段。
- `exportedAt` 仅为传输元数据，不参与世界事实，不作为可信时间排序依据。
- envelope checksum 必须按 E1 的 canonical JSON 规则重算并匹配。
- envelope 的 WorldId 与 package chain、snapshot、streamHead 必须完全一致。
- package chain 必须是 Full 根包及不超过现有 128 节点上限的合法 Incremental 后继链；不得接受孤立 Incremental 包。
- JSON 必须完整解析；拒绝无效 JSON、非 JSON 值、异常结构、循环/超深链、未知字段、非法游标与超出解析资源预算的输入。
- 导入大小上限与导出端必须共用一个常量；本片暂定 128 MiB。E1 导出端同步执行相同上限，超限不得生成一个本应用无法再次导入的包。

**重要：** checksum 只证明内容与摘要一致，不证明作者身份、文件来源或未被恶意重算。导入后仍必须由本地可信 Registry / Reducer 完整验证，不能把 checksum 当签名或信任凭证。

## 3. 验证顺序与提交前门禁

导入服务按以下顺序执行，任何一步失败都不得写入仓储：

1. 检查文件大小与读取结果；读取异常明确返回，不改变当前运行时。
2. 严格解析 JSON；拒绝格式错误、重复键或非普通 JSON 对象。
3. 校验 envelope 顶层字段、format、formatVersion、exportedAt、WorldId 与 streamHead 形状。
4. 重算 envelope checksum；不匹配返回 `envelope-checksum-failed`。
5. 校验 package chain 外形、根包类型、链深、WorldId / schemaVersion 一致性、base 连续性与游标锚点。
6. 使用当前冻结的 PreviewRuntime Registry、schema、initialState 与纯 Reducer 调用 `validateSavePackageChain`，完整验证每一层 package checksum、事件范围、AI validation receipts、从 genesis 的 replay、snapshot/materialized 一致性。
7. 核对 envelope.streamHead、chain snapshot.streamHead、chain streamRange.toInclusive 三者完全一致（event cursor 同时核对 seq 与 eventId）。
8. 在写入前查询本机 WorldId 冲突；已有世界一律返回 `world-exists`，包括内容相同的重复导入，不做覆盖或合并。
9. 通过专用仓储原子导入接口提交整条 package chain；提交成功后才返回 `imported`。

不允许：
- 仅验证 envelope checksum 就落盘。
- 仅验证叶子 Incremental 包而跳过 base chain。
- 仅验证 snapshot 后跳过 genesis replay。
- 把导入数据直接 cast 成运行时 session。
- 以当前内存 session、React projection 或旧 `guanyuan.save.v1` 为导入依据。
- 失败后静默新建世界、忽略坏包、回退到 snapshot 或写入部分链。

## 4. 仓储原子性：必须补齐整链导入端口

现有 `SaveRepository.commitWorld` 适用于本机已有链的增量提交：IndexedDB adapter 只写入本次 package 节点，并要求 base 节点已存在。它不能直接接纳另一设备导出的完整嵌套链。因此本片必须新增专用端口，例如：

```ts
importWorld(input: {
  worldId: WorldId
  packageChain: SavePackageChain
  streamHead: StreamCursor
  savedAt: string
}): Promise<SaveRepositoryResult<StoredWorldSave>>
```

语义必须冻结：

- 只允许导入到不存在的 WorldId；不接受 expectedHead 覆盖路径。
- IndexedDB adapter 在**同一个 readwrite transaction** 中完成：确认 worlds 中该 WorldId 不存在、按 Full 根包到 Incremental 叶子顺序展开完整 chain、写入全部 package rows、写入唯一 world latest pointer。
- Incremental 的 basePackageKey 必须指向同一事务中已写入的前驱节点；每个 package key 由既有 `worldId::checksum` 规则生成。
- 写入前检查 chain 中 WorldId、checksum、游标、节点数、重复 key 与 base 顺序；domain validator 仍由调用方完成，adapter 不替代领域验证。
- 任一写入、索引、配额或 transaction 错误必须整体 abort；不得留下 world pointer、孤儿 package node 或部分链。
- 并发双导入同一 WorldId 时，最多一个成功；另一个以 `save-repository-world-exists` 或等价冲突返回。
- 若已有同 WorldId 损坏记录，也不得覆盖修复；返回明确冲突/损坏错误，交由独立恢复工具处理。
- 新增 fake repository / IndexedDB adapter 测试，证明 Full-only 与多段 Incremental chain 可从空仓储导入，随后 `loadWorld` / `listWorlds` 可见；失败事务后 worlds 与 packages 均无残留。
- `SaveRepositoryIssue` 增加明确的 world-exists 语义，不把它折叠成 storage-error。

## 5. 当前会话与人生切换语义

导入是“把一段已验证人生加入本机档案”，不是“替换当前人生”。

- 导入前后，当前 `runtimeRef`、React GameState、EventLedger、WorldId、时段、玩家事实、待保存队列均保持不变。
- 导入成功只新增一条本机世界档案；不自动发布 session、不自动切换、不重置当前世界。
- 导入完成后，UI 可以打开“选择要接续的人生”启动门，但必须提供“返回当前人生”取消路径。
- 只有玩家在选择门中明确选择某个 WorldId，才调用既有 `restorePreviewRuntimeSession`；只有完整恢复成功才一次性替换当前 session。
- 选择另一世界恢复失败时，当前 session 不得被部分覆盖；返回当前人生仍可继续。
- 如果当前应用架构无法在不丢失 active session 的前提下打开/取消选择门，则本片先完成“导入入库＋当前人生不变”，切换体验另立子片；不得用 `window.location.reload` 或强制重启伪装为无损切换。
- 导入后刷新启动时，现有 `restoreSingleSavedRuntimeWorld` 多档选择规则继续生效；不得按最近时间、导入时间或列表顺序自动选档。

## 6. UI 与用户确认

在现有 SaveFolio 内 additive 增加“导入便携存档”入口，不新增一级导航、OverlayId、存储 key 或独立事实状态。

流程：
1. 用户主动选择本地 JSON 文件。
2. 完成解析与完整验证后，展示导入预览：文件名、人生 WorldId 安全短标识、当前世界日/时段（由已验证 replay 投影得出）、事件 head、导出时间（明确标为文件元数据）。
3. 用户二次确认“导入到本机”；文件选择或预览本身不得写入。
4. 提交完成后提示“便携存档已导入本机”，明确“当前人生未切换、未覆盖任何已有档案”。
5. 冲突、格式错误、版本不支持、checksum 错误、chain/replay 错误、仓储不可用、配额不足均显示可理解原因；失败不得显示成功态。
6. 支持取消、重新选择文件；取消不得更改本机档案或当前会话。

文案不得称作云备份、云同步、来源认证或安全签名。

## 7. 错误语义

至少区分：

- `file-too-large`
- `file-read-failed`
- `json-invalid`
- `envelope-invalid`
- `format-unsupported`
- `envelope-checksum-failed`
- `world-mismatch`
- `schema-unsupported`
- `chain-corrupt`
- `checksum-failed`
- `world-exists`
- `storage-error`
- `storage-quota-exceeded`
- `storage-conflict`

不得 catch 后返回空包、空人生或成功结果。

## 8. 测试矩阵

### Envelope / Parser
- E1 Full-only 与多段 Incremental 导出文件可导入。
- 无效 JSON、重复键、顶层未知字段、缺字段、未知 formatVersion、非法 exportedAt、非法 WorldId、非法 streamHead 均拒绝。
- envelope checksum 单字段篡改、package 内容篡改、streamHead 篡改均拒绝。
- 超过 128 MiB 文件拒绝；边界值与 E1 导出端同口径。
- 恶意深层对象、超深 chain、循环 base、重复 package key 拒绝。

### Domain Validation
- package schema 不支持拒绝。
- Full 根包缺失、Incremental base 缺失、跨世界、断链、错序、eventId anchor 不匹配拒绝。
- package checksum、AI receipt、事件 schema、replay、snapshot 不一致拒绝。
- 从 genesis 完整验证成功；不得只验证 snapshot 或叶子节点。

### Repository Atomicity
- 空仓储导入 Full-only 成功。
- 空仓储导入 Full→Incremental→Incremental 成功，随后完整 load 与 list 摘要一致。
- 同 WorldId 已存在时拒绝，原 world pointer / package bytes 不变。
- 同 WorldId 并发双导入，只有一个成功。
- 中途模拟 quota / put / transaction abort，worlds 与 packages 均无部分写入。
- 成功导入后每个 package 节点的 basePackageKey 均可追溯至同 WorldId 前驱。

### Runtime / UI
- 导入成功前后当前 session、ledger head、state、WorldId 与 pending save queue 引用/值保持不变。
- 预览和取消不写仓储。
- 导入成功不自动切换；明确选择后恢复成功才切换。
- 目标世界恢复失败时原 active session 仍可继续。
- 390px / 1024px / 1440px 无横向溢出，键盘与焦点流程可用，文件错误提示可读。
- E1 导出、W1—W5-D3 回归、Review index、Patch whitespace、Production build、Playwright Smoke、双 CI 同 SHA 全绿与双侧截图归档。

## 9. 本片不做与后续边界

- 不做覆盖、合并、WorldId 重映射、旧 v1 migration、schema upcaster、压缩格式、云端传输、自动同步、档案删除。
- 不导入 narrative settings、API keys、secrets、缓存、设备标识或凭据。
- 不修改 EventLedger append/replay、Reducer、事件 schema、业务数值、时段成本与玩家事实。
- 导入只写 SaveRepository；恢复仍复用可信 runtime restore 内核。
- 档案删除与多档位管理另立 W5-E3 契约，沿用 expected-head CAS 与级联清理，不与导入混片。

## 10. 验收门槛

1. 契约先冻结；实现范围与上述边界一致。
2. E1 导出与 E2 导入共享格式、canonical checksum、128 MiB 上限；E1 导出的合法文件必须能被 E2 导入。
3. 只有完整验证的 Full + Incremental chain 能提交。
4. 导入整链入库具备单事务原子性；冲突不覆盖。
5. 当前 active session 不被导入副作用改变；切换需用户明确选择。
6. Full-only / 多段 Incremental / 所有负向用例均有专项测试。
7. Review index、Patch whitespace、Production build、Playwright Smoke、Push/PR 同 SHA 双 CI 全绿、双侧截图归档通过。
8. PR 保持 Draft/Open，不合并；不修改 main。
