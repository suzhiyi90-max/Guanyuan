# W2-L 人物关系生命周期与死亡连续性契约 v0.1

状态：W2-L 施工契约；基线为 work/w2-k-membership-death-continuity。

## 1. 审计结论

W1-C 的 Relation 是有向、多重、开放类型码的客观关系边；RelationClaim 是人物主张，RelationEvidence 是主张证据。三者分离应保持不变。

现有关系生命周期只有 active / dormant / severed 与 validFrom / validTo，结构校验不解析事件存在性和时间顺序，也没有定义人物死亡时关系边应如何处理。不得把 W2-K 的 Membership 规则直接套用到 Relation：成员资格是人物参与组织的区间，关系边可能是亲属、师生、同年、仇怨、政治同盟等不同性质的事实。

## 2. 核心裁决

1. 人物死亡不自动删除关系，也不自动结束所有关系。
2. 关系类型码继续开放；本切片不建立封闭关系类型清单，也不根据类型名称推断法律效果。
3. 对死亡时仍有效的关系边，必须显式记录该端点死亡后的关系事实处置：
   - preserved：保留该关系事实的历史连续性；不表示死者仍能行动、回应或履行义务。
   - ended：该关系事实在死亡事件时终止，关系边必须以死亡事件结束并标记 severed。
4. 已在死亡前结束的关系边保留原结束事件，不再要求死亡处置。
5. 若关系事实在死亡后仍有有效区间，必须有 preserved 记录；不能静默跨过死亡时点。
6. 若一条关系边两端先后死亡，允许先保留、后终止；终止事件之后不再接受后续端点处置。
7. RelationClaim、RelationEvidence 不得直接改变客观关系或替代死亡处置记录。
8. 验证只读，不改写关系、人物、幸存者心理状态或遗产结算状态。

## 3. 数据契约

RelationDeathDisposition 包含 id、relation、deceased、deathEvent、outcome。
outcome 仅为 preserved 或 ended。

处置必须引用真实关系边、关系端点、唯一死者、其 DeathRecord 和一致的死亡事件时点。关系起点必须早于死亡。关系终点事件（如存在）必须可解析且晚于起点。

ended 必须满足 Relation.lifecycle.validTo === deathEvent 且 status === severed。
preserved 表示该死亡时点不终止关系，不得将该死亡事件作为关系终点；关系可由另一个严格晚于死亡时点的事件在后续独立终止，并在该后续终止时标记 severed。不得把后续 severed 状态反向解释为死亡时点已经 ended。

## 4. 明确不做事项

- 不从亲属、配偶、师生、同年、同乡或派系关系推断继承、婚姻终止、债务承接、宽恕、恩怨消除或法律责任。
- 不自动把双向关系合并成一条边；不把有向关系改成对称关系。
- 不自动改变幸存者的情绪、记忆、目标、知识或行动。
- 不推断继任者，不创建新关系，不转移财产、债务、职位、组织成员资格或私人义务。
- 不允许主张或证据直接写入客观关系。
- 不接 W3 Event Ledger、AI 写入、存档迁移、G1 runtime 或 UI。

## 5. 验收门槛

- 关系死亡处置必须有唯一 ID，且每个关系/死者端点最多一条。
- 关系与死者、事件引用、事件时点必须完整且一致。
- 死亡前结束的关系保留历史；死亡时仍有效的关系必须显式处置。
- preserved 与 ended 的生命周期约束正确。
- 双端先后死亡时，保留后终止可表达；终止后不得再增加端点处置。
- 有向、多重关系和开放关系类型不受破坏。
- 关系主张、证据与客观关系仍然隔离。
- W1-A 至 W2-K 回归、W2-L 专项测试、Review index、Patch whitespace、Production build、Playwright Smoke 与截图归档全部通过。
