# W5-E3 本机人生档案管理与安全删除契约 v0.1

## 1. 施工定位

- 基线：W5-E2C 本机人生档案目录与手动恢复，验收提交 `39723c0f295627a000dc5b4cb181688760fc7a52`，分支 `work/w5-e2c-local-save-library`。
- 本片目标：在现有只读档案目录上补齐可控的多档案管理能力，第一优先级为**安全删除非当前人生档案**，并完善列表排序、状态反馈与并发保护。
- 本片不修改 EventLedger、Reducer、SavePackage 格式、checksum 规则、世界事实或恢复内核。
- 先冻结契约，再施工。代码施工必须从 E2C 验收分支派生；PR base 指向 E2C 分支，保持 Draft/Open，不合并，不改 main。
- 当前 `SaveRepository.deleteWorld(worldId, expectedHead)` 已存在，并已具备 expected-head CAS 与按 WorldId 级联删除 package rows 的实现。本片先审计并补强其边界，不得重复造一个并行删除端口。

## 2. 已有能力与本片缺口

### 已有能力（不得重复实现）

- `SaveRepository.listWorlds()` 返回索引摘要，不加载完整 package chain。
- `SaveRepository.deleteWorld(worldId, expectedHead)` 在同一 IndexedDB readwrite transaction 中读取 WorldRow、核对 streamHead、删除 WorldRow，并按 packageStore 的 `worldId` 索引删除该人生的全部 package rows。
- 删除时 expectedHead 不匹配返回 `save-repository-head-conflict`；档案不存在返回 `success(false)`。
- E2C UI 已展示 WorldId 短标识、保存时间、Full/Incremental 类型、streamHead 序号与 checksum 摘要；恢复仍走完整验链与 genesis replay。

### 本片需要补齐

- 档案目录应以明确、稳定、可重复的规则排序，默认最近保存优先。
- 每个非当前人生档案提供删除入口；当前正在运行的人生不得删除。
- 删除必须有明确二次确认，确认内容必须指向具体 WorldId，不能误触即删。
- 删除前处理本机保存队列与列表陈旧问题；删除时使用最新读到的 streamHead 作为 CAS 版本。
- 删除成功后刷新目录；失败时保留条目并给出可理解错误，不能显示成功。
- IndexedDB 级联删除必须验证：world pointer 与该 WorldId 的所有 package rows 同事务消失；其他 WorldId 的数据不受影响。
- 需要对保存、导入、恢复、删除并发进行契约测试。

## 3. 档案目录语义

1. 档案列表是索引投影，不是可信档案内容；不得把列表摘要直接恢复为 Runtime Session。
2. 列表读取必须等待当前应用已排队的持久化写入稳定后再读取，延续 E2C 的 persistence queue fence。
3. **排序的唯一权威层为 `SaveRepository.listWorlds()`**：仓储返回前完成排序；UI、启动选择列表、导入后刷新和删除后刷新不得各自实现不同排序，也不得二次重排。
4. 排序规则固定为：
   - `savedAt` 降序（最近保存优先）；
   - 时间相同则 `worldId` 按稳定字典序升序。
5. `savedAt` 必须是可往返规范化的 ISO 8601 时间字符串（`Date.parse` 有限且 `new Date(savedAt).toISOString() === savedAt`）；无效时间的索引行不得伪装为有效日期。若仓储返回结构损坏，应显示目录错误，不静默过滤后宣称列表完整。
6. 仓储必须在返回摘要前校验 WorldRow 的完整结构：worldId、latestPackageKey、packageKind、checksum 格式、savedAt 与完整 StreamCursor（event cursor 必须包含 eventId；genesis cursor 必须严格为 seq=0）；缺任一项或字段互相矛盾均返回 `save-repository-record-corrupt`。删除流程不得把损坏记录当成空档案。
7. 显示字段只使用仓储摘要：WorldId 安全短标识、保存时间、package 类型、事件流序号、checksum 摘要。不得从不可信元数据推断人物姓名、剧情结果或世界日。
8. 空列表、加载中、刷新失败、目录损坏、删除中、删除成功与删除失败状态必须互斥且可读。
9. 刷新失败时保留上次成功读取的列表，但必须明确标记该列表为旧数据，禁止对旧条目直接执行删除；重新读取成功后才允许操作。

## 4. 删除授权与当前人生保护

1. **禁止删除当前活动人生**：以 `runtimeRef.current.worldId` 为准，不以 React 组件缓存、列表位置或用户点击时的旧状态为准。
2. 删除入口对当前活动 WorldId 显示不可用状态，并说明“当前正在接续的人生不能删除”。不提供绕过按钮。
3. 在调用仓储删除前，协调器必须再次读取当前 runtime WorldId；任何等待期间若活动人生已变化，必须重新判定。
4. 恢复正在进行时，不允许启动删除。删除正在进行时，不允许启动另一项删除、对同一档案恢复或对同一 WorldId 导入。
5. 对非活动档案删除前，等待当前已排队保存操作稳定；等待期间若该档案成为活动人生，取消删除。
6. 仅允许删除索引中已成功读取、结构有效且带有有效 streamHead 的档案。不得用缺失或伪造 cursor 替代 expectedHead。
7. 本片不提供“删除全部”“清空所有人生”“批量删除”入口。

## 5. 二次确认与交互

1. 用户点击删除后先进入确认态，不写仓储、不改当前 session、不删除任何 package row。
2. 确认界面明确显示该人生的 WorldId 安全短标识，并写明不可撤销、只删除本机该档案、不影响当前正在接续的人生。
3. 用户必须再次点击明确的“确认删除此档案”；取消、Escape（若交互可关闭）与关闭确认层均为零写入。
4. 确认操作应防止重复提交；同一 WorldId 同时最多一个删除请求。
5. 确认前刷新/重读该 WorldId 最新摘要，不能直接沿用打开确认层时的陈旧 streamHead。
6. 最终仍以 `deleteWorld(worldId, expectedHead)` 的事务内 CAS 为并发裁决权威；UI 预读不能代替 CAS。
7. 成功后关闭确认层并刷新列表；若当前列表已空，显示空状态。
8. 删除失败必须保留档案条目（除非刷新证明已被其他合法操作删除），并区分至少以下情况：
   - head 冲突：档案在确认期间发生新保存，提示刷新后重新操作；
   - 档案不存在：刷新目录，不显示删除成功的误导信息；
   - 仓储不可用/事务失败/配额或存储错误：提示失败，保留可重试路径；
   - 结构损坏：不提供普通删除入口，提示档案索引异常，交由恢复工具处理。
9. 不使用浏览器原生 `confirm()`；沿用现有纸面确认/模态交互规范，提供焦点管理、键盘操作、Esc 取消（仅确认层，不得影响进行中的事务）与减少动效适配。

## 6. 仓储原子性与级联删除

1. 复用既有 `deleteWorld(worldId, expectedHead)`。若审计发现实现缺陷，先补充契约测试，再对既有实现做最小修复。
2. 删除事务必须同时覆盖 `worlds` 与 `packages` 两个 object stores。
3. 事务内读取并规范化 WorldRow；不存在返回 `success(false)`；结构损坏返回明确 rejected，不得将损坏记录当成空档案。
4. 事务内重新校验 WorldRow 结构与 StreamCursor；event cursor 必须比较 kind、seq、eventId，genesis cursor 必须严格为 kind=genesis、seq=0。结构损坏返回 `save-repository-record-corrupt` 并 abort；有效 cursor 不匹配必须 abort，返回 `save-repository-head-conflict`。
5. 通过 packageStore 的 `worldId` 索引删除该 WorldId 的所有 package rows，包括 Full 根包和所有 Incremental 节点；不得只删 latest pointer 或叶子节点。
6. 任一删除请求失败、事务 abort 或索引操作异常，world row 与 package rows 必须整体回滚，不允许半删除。
7. 其他 WorldId 的 world row 与 package rows 字节级保持不变。
8. 删除完成后再次 `loadWorld` 必须返回 null，`listWorlds` 不得再列出该 WorldId；不得遗留该 WorldId 的 package rows。
9. 并发保存若先于删除提交，expectedHead 必须冲突并保留新版本；删除若先提交，后续旧 head 保存必须因 world/head 冲突而失败。不得出现删除后复活的陈旧 world pointer。
10. `importWorld` 与 `deleteWorld` 均对 `worlds`、`packages` 两个 object stores 开启 readwrite transaction；同 WorldId 竞争由 IndexedDB 对重叠 object stores 的事务串行化及 worlds 主键唯一约束裁决。导入不得先在事务外写入 package rows，也不得在删除提交后使用旧缓存补写 world pointer。
11. IndexedDB 事务中所有请求必须在事务活跃期内调度；不得跨非 IndexedDB await 保持事务。

## 7. 导入、恢复与删除并发规则

- 同 WorldId 导入与删除不能形成“删除先行、旧导入后写入”的意外复活。导入只允许不存在的 WorldId，删除事务与导入事务通过同一 worlds 主键唯一约束串行裁决；最终状态必须对应某一个完整事务顺序。
- 正在恢复的 WorldId 不可删除；恢复前后继续使用 E2C 的 runtime identity guard，防止恢复结果覆盖新行动。
- 当前活动 WorldId 不可删除，即使列表摘要在更早时刻显示为非活动。
- 删除等待 persistence queue 时，必须持续追踪 queue identity；不能只等待最初捕获的 Promise 后误认为队列稳定。
- 多档案列表刷新、导入成功刷新、恢复成功后活动标记刷新、删除成功刷新必须使用同一排序与状态口径。

## 8. 测试矩阵

### Repository / IndexedDB

- 删除 Full-only 世界：world row 与 package rows 均清除。
- 删除 Full→Incremental→多段 Incremental 世界：整条链全部清除。
- 两个 WorldId 并存：删除一个后另一个的 pointer、package rows、load 与 list 均不变。
- stale expectedHead 拒绝，原档案与链保持完整。
- event cursor 的 eventId 不一致即拒绝。
- 不存在 WorldId 返回 false，不产生副作用。
- 模拟中途 cursor.delete / transaction abort：两个 stores 整体回滚。
- 删除与 commitWorld 并发：按事务提交顺序得到完整且可解释的结果，不产生半链、孤儿节点或陈旧复活。
- 删除与 importWorld 同 WorldId 并发：验证两个操作确实使用覆盖相同 stores 的 readwrite transaction；只允许事务序列化后的合法最终状态，不得部分混合。
- WorldRow 的 streamHead 缺 eventId、eventId 类型错误、非法 genesis seq、savedAt 非规范 ISO、checksum 非法、latestPackageKey 缺失等损坏样本，list/delete 均明确拒绝且不误报不存在。
- 结构损坏的 WorldRow 不得被普通删除流程误判为成功。
- 既有 E1/E2 导入导出、W5-D 全链回归继续通过。

### Runtime / Coordinator

- 活动 WorldId 删除入口禁用；即使绕过 UI 直接调用协调器也必须拒绝。
- 等待 persistence queue 时新行动/新写入进入队列，删除必须等待稳定。
- 等待期间 WorldId 成为活动人生，删除取消。
- 正在恢复时删除被拒绝；删除期间恢复被拒绝或串行等待。
- 删除非活动人生不改变 runtimeRef、React GameState、EventLedger、当前 WorldId 与 pending save queue。
- 删除失败不改变活动人生；删除成功只影响目标 WorldId。

### UI / Accessibility

- 390px / 1024px / 1440px 列表无横向溢出。
- 最近保存优先；相同时间稳定排序。
- 当前人生明确标识且不可删除。
- 删除入口、确认层、取消、确认、处理中、成功、失败、刷新与空状态全覆盖。
- 键盘可操作；焦点进入确认层并在取消/完成后合理归还；减少动效设置生效。
- 连续双击确认不重复提交。
- 旧列表刷新失败后不允许用陈旧 head 删除。

- Review index、Patch whitespace、TypeScript、Production build、Playwright Smoke。

## 9. 本片明确不做

- 不做云同步、远端备份、跨设备合并、账户绑定。
- 不做旧 `guanyuan.save.v1` 迁移、schema upcaster、历史包转换。
- 不做档案重命名、人物封面编辑、标签、收藏、手动槽位编号或排序拖拽。
- 不做批量删除、清空全部、回收站、撤销删除、删除后恢复工具。
- 不删除 narrative settings、secrets、API keys、缓存或设备数据。
- 不修改世界事实、事件账本、时段成本、人物关系、AI 候选或游戏业务规则。
- 不允许删除当前活动人生。

## 10. 验收裁决原则

- 任何 UI 状态都不能替代 runtime 当前身份检查与 IndexedDB expected-head CAS。
- 用户取消必须零写入；删除失败必须保留完整档案；删除成功必须清除目标 WorldId 的全部 package chain。
- 不得以“列表消失”代替验证底层 package rows 已清理。
- 若原子删除、并发安全或活动人生保护任一项不能证明，本片不得签收。
