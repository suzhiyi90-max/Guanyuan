# W5-D3 启动恢复与运行时重建契约 v0.1

## 1. 施工基线与范围

- 基线：W5-D2 `work/w5-d2-runtime-save-package-orchestration`，验收 SHA `b5a717c515bae66681c15f0172c0058cd2eb9f7f`。
- 本片负责从 SaveRepository 读取已保存世界，验证完整 SavePackageChain，并构造新的 PreviewRuntimeSession。
- 恢复服务是纯编排边界：调用方只能在收到 `restored` 后替换当前 session；任何拒绝结果不得改变既有活动 session。
- 不读取、迁移、覆盖或删除旧 `guanyuan.save.v1`；不把快照当成独立事实源。

## 2. 恢复顺序（不可调换）

1. 通过 SaveRepository.loadWorld 读取指定 WorldId；仓储错误原样上抛为 rejected，缺档返回 missing。
2. 校验 StoredWorldSave 与 package chain 的 WorldId 一致。
3. 校验 schemaVersion 与当前 Preview Runtime schema 一致；未知版本拒绝，不做猜测迁移。
4. 使用当前冻结 Registry、初始状态和确定性 reducer 调用 `validateSavePackageChain`，验证每一层 checksum、base 链、事件区间、AI receipt、重放和 snapshot 一致性。
5. 按 base → leaf 顺序拼接事件；事件数必须等于最终 cursor.seq。
6. 从 genesis 再执行完整 runtime projection replay；结果 cursor、applied 数必须与存档头一致。
7. 由已验证事件重建 EventLedger 与幂等索引。重复请求键、语义冲突、序号/ID 不连续必须拒绝；AI receipt 与 candidate fact 必须重新执行可信摘要校验。
8. 从已验证 AI fact 与 receipt 重建可持久化的 validated CandidateLog；未验证的 pending/rejected 模型候选不是世界事实，不跨会话恢复。
9. 从历史 player-command-N 请求 ID 恢复 requestSequence，防止恢复后自动请求 ID 与历史碰撞。
10. 构造全新的不可变 PreviewRuntimeSession；仅将该结果交给上层原子发布。

## 3. 多存档启动选择

- 存档数量为 0：返回 missing，由上层按新世界流程处理。
- 存档数量为 1：允许自动恢复唯一存档。
- 存档数量大于 1：返回 selection-required 和存档摘要；禁止按数组顺序或最近写入时间擅自选择另一段人生。
- 指定 WorldId 的恢复必须再次校验存档与链内 WorldId，不能信任列表摘要。

## 4. 检查点与重放

- 当前 Full package 从 genesis 保存完整事件流；Incremental package 以已验证 base 为锚点。
- 当前格式不丢弃 genesis 事件，因此恢复必须完整重放事件流；snapshot 是经重放校验后的派生检查点，不允许跳过事件链验证。
- 未来若引入真正截断历史的 checkpoint，必须另立 schema/migration 契约，明确 checkpoint 前事件的审计保留与 AI receipt 依赖，不能在本片隐式优化。
- 本片不接受只凭 snapshot.materialized 直接创建运行时状态。

## 5. 原子性与失败语义

- 恢复过程只在局部变量中创建 Registry、Ledger、Projection、CandidateLog。
- 任一阶段失败均返回 rejected，不返回半成品 session；调用方活动 session 保持引用与状态不变。
- missing 与 storage error/corrupt/schema mismatch/replay failure 明确区分，损坏存档不得伪装为空档。
- 旧 v1 key 永远不作为 D3 的 fallback。

## 6. 验收门槛

- 缺档、Full、Full + 多段 Incremental、指定 WorldId 不匹配、schema 不兼容、checksum 损坏、base 缺失/损坏、事件序号或 ID 不连续、AI digest/receipt 无效、幂等键冲突、重放失败、仓储错误均有契约测试。
- 成功恢复后可继续 append；requestSequence 不碰撞；CandidateLog 只恢复已验证且已提交的 AI fact。
- 恢复失败不得改变原活动 session。
- W1—W5-D2 回归、D3 专项、Review index、Patch whitespace、Production build、Playwright Smoke、双侧截图归档通过。
- Push/PR CI 必须针对同一最新 SHA 全绿；PR 保持 Draft/Open，不合并。
