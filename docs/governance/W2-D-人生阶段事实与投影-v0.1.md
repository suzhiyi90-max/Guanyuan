# W2-D 人生阶段事实与投影 v0.1

状态：W2-D 施工契约；遵循 v0.16《设计总纲》与《世界生命、全人物状态与自由人生模拟系统设计规范》。
基线：W2-C `work/w2-c-body-mind-state`。

## 1. 目标

为 Person 增加可追溯、可追加的人生阶段事实。阶段用于描述人物在不同生活轨道中的当前处境，不是任务脚本、年龄段枚举或人生必经路线。

## 2. 阶段模型

- 每条事实绑定 Person、开放式 track、开放式 code、来源 EventId、WorldTime、Visibility 与 supersedes。
- track 表示可并行的生活轨道，例如 education、career、family、livelihood；这些只是可用示例，不是封闭枚举。
- 同一人物可同时处于多个 track；每个 track 同一时点只有一条当前事实。
- stage code 由时代规则、事件与内容配置解释；本切片不冻结具体阶段目录。
- detail 使用 Field 语义；unknown、not-generated、n/a 不互相替代。

## 3. 形成与变更

- 根事实 supersedes 必须显式为 n/a；unknown / not-generated 不表示确认不存在前序阶段。
- 阶段变更必须引用同一人物、同一 track 的前序事实，且时间严格递增。
- 每条前序事实最多被替代一次；历史只追加，不覆盖。
- 当前阶段由未被替代的事实投影；追加失败返回原集合。
- 每条事实的 sourceEvent 必须存在且时间与事实时点一致。

## 4. 与年龄、身体及人生路径的边界

- 年龄仍由 W2-B CalendarAdapter 派生，不持久化年龄副本。
- 不根据年龄自动推断阶段；不设通用成年、婚育、入仕、致仕或养老年龄门槛。
- 阶段不是强制顺序；可跳过、并行、反复进入或长期停留，具体合法性由后续时代制度/规则决定。
- 阶段标签不直接改变能力、权限、身体、经济、关系或日程。
- 不因阶段名称推断婚姻、亲属、官职、功名或其他客观事实；这些必须由各自领域事实支持。

## 5. 生命周期与信息边界

- 死亡时点及之前的阶段事实可保留；严格晚于死亡时点的普通阶段更新拒绝。
- Visibility 独立校验；阶段事实不会自动广播给玩家或其他人物。
- 阶段事实不是人物认知，不等于玩家已知，也不能由 AI 叙事直接写入。
- 不接 W3 Event Ledger、AI 候选写入、存档迁移、G1 运行时或 UI。

## 6. 验收门槛

1. 同人物多 track 可并行，单 track 根记录唯一。
2. 阶段变更必须显式 supersedes 且时间严格递增。
3. 来源事件存在、事件时间一致、可见性合法。
4. 跨人物/跨 track 替代、重复替代、重复根、空 track/code、死后更新均拒绝。
5. 追加不可变；失败保留原集合；当前投影正确。
6. W1-A 至 W2-C 全部回归、生产构建、Playwright Smoke 与截图归档通过。

## 7. 明确不做

不实现年龄门槛、时代婚育政策、成年礼、科举资格、任官资格、退休/致仕规则、衰老曲线、疾病/寿命模型、人口模拟、事件账本或任何 UI。
