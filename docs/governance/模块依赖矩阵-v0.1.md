# 模块依赖矩阵 v0.2

- 状态：治理索引；本文件不是新增领域规则，也不代表矩阵列出的模块均已实现。
- 权威源：产品规则以 `main` 上已批准的《设计总纲》及其正式规范为准；本矩阵只标注责任边界、依赖方向、待补契约和施工状态。
- 设计基线：v0.16。M1 当前仍是单县、七名关键人物样本、十日、一场河工汛情的验证范围；七人不是世界人口或人物类型上限。
- 架构边界：官场人生与非官场人生共用人物、生命、时间、家庭、关系、认知、地理、经济及事件底座；职业路径只在身份、权限、行动集、制度机会和结果上分化。此项是设计方向，不授权本轮扩建完整自由人生玩法。
- AI 边界：本轮仅维护现有 AI 输入/输出与规则校验边界；不启动 AI 世界运营者、事件锚点或批量内容生成架构设计。

## 状态标记

| 标记 | 含义 |
|---|---|
| A | 总纲/正式规范已有明确原则或规则 |
| C | 规则方向已有，但对象字段、边界或结算契约仍待 P1 裁定 |
| M1 | 当前原型范围内需要验证，不代表完整系统 |
| FUTURE | 属于后续完整人生模拟范围，本轮不施工 |

## 依赖与边界规则

1. 依赖方向为：基础身份/权限/时间契约 → 领域命令与规则 → 原子状态/事件提交 → 认知与只读投影 → UI/AI 表达。领域模块之间通过契约交互，不允许形成循环写入。
2. MOD-COMMAND 是业务提交边界；MOD-EVENT 是被动追加式账本。前者负责校验和事务，后者负责记录和重放，不能把二者合并成相互调用的循环。
3. 当前总纲未批准通用 `worldVersion` CAS。若某具体实现需要并发版本校验，必须在对应命令契约中说明适用范围、冲突语义和兼容性，不得从治理矩阵推定为全局规则。
4. 时间使用四时段与已批准的行动成本口径；“每日行动点”不得作为并行计量单位。
5. v0.16 的模拟层级术语统一按 L0 近场、L1 关系圈、L2 区域圈、L3 远域使用。不得与 v0.9 旧三层模拟含义或 AI 成本等级共用同一套未限定的 L0–L3 名称；旧文档清理前，相关引用标记为术语债。
6. 认知至少区分：客观事实、来源立场、来源可靠性、玩家/人物接触、理解、相信/立场、核验状态及其证据历史。具体对象 schema 和升级/降级规则仍由 P1 契约审计裁定，本矩阵不自行定值。
7. 官场与非官场路径共享人物和世界底座。MOD-CAREER 只负责仕途制度，不是所有人物的默认人生主线；教育、家庭、组织、经济等模块不因玩家是否为官而消失。
8. 本轮只校准矩阵与施工治理，不启动完整自由人生、全量事件库、AI 世界运营者、事件锚点或内容批量生产系统。
9. M1 的七名关键人物、单县、十日、一场河工汛情是当前验证夹具；不得反推为完整系统的数据模型上限。
