## 2. 发现等级

### P0 — 候选稿已修复/统一的结构冲突

1. 时间双计：候选稿删除“每日行动点”，统一四时段为唯一时间单位；普通耗时动作默认 1 时段，委托执行时长与发起成本分离。
2. 事件顺序：候选稿在 10.5 明确固定结算阶段、稳定排序键、原子提交和未来事件排程。
3. 认知语义：候选稿区分 Fact、Claim、Evidence、Exposure、Belief、Memory、Rumor，并将四档情报改为玩家核验状态。
4. AI 写入边界：候选稿明确模型只生成表达/候选意图，只有规则引擎验证并提交的事件才能改变世界状态。

以上是“候选稿已处理”，不是 main 已更新或用户已批准。

### P1 — 已识别但不应擅自扩大本轮改动

1. 考语模型命名冲突：D-009 的“四维”与第 7.2 节的多个生成因素不一致。候选稿保留现有内容并登记为待裁决，不在无依据情况下改写业务模型。
2. 历史基准期：默认背景写“架空晚清”，部分制度材料可能跨时期。必须为硬规则补充适用时期、地域、职位和来源定位。
3. 河工银具体额度：300/2000 两、雇募 50 人、调派 20 人等阈值仍需标记为史实核验或游戏参数，不得仅因正文出现就当作已确认。
4. 四档情报更新规则：“只降不升，除非出现新证据”容易误解为有新证据时状态如何变更。统一契约允许新证据触发上调或下调，并保留状态历史；具体判定阈值待纸面验证。
5. 人物示例：附录 B.1 的书吏角色和高工程能力容易被误读为核心人物配置。候选稿明确为示例占位，后续仍需核对七人名单与能力分配。
