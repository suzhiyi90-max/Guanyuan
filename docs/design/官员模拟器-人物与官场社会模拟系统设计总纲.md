# 官员模拟器｜人物与官场社会模拟系统设计总纲

文档版本： v0.2
状态： 持续维护的设计基线；已纳入新增决策，仍有明确待决项
文档性质： 核心系统设计基线；本文件为唯一权威设计源
适用范围： 人物模拟、社会关系、官僚组织、权力与权限、人才获取、行动时间、行政执行
首个验证场景： 县令主持黄河河工治理
项目原则：以人为核心，以社交为核心玩法；人物、关系、权力、时间、事件与叙事共用统一世界状态。避免每种玩法各自膨胀为独立子系统；以完整人物内核组合出多样互动。确定性规则负责真实结果，AI 负责意图理解、人物表达与沉浸式叙事。

---

## 一、项目定位

### 1.1 核心设计理念

本项目是一款以人物关系、社会互动、官场治理和长期人生选择为核心的中国古代官员模拟游戏。

玩家扮演一名具有明确身份、职权和现实限制的官员，从地方治理逐步进入更复杂的官僚体系与社会网络。

游戏的核心不是直接点击行政按钮完成任务，而是让玩家通过理解人物、建立关系、组织人员、获取资源、行使权力和承担后果，推动自己希望实现的目标。

例如，玩家决定治理黄河河工时，不能直接选择“治理成功”。玩家需要：

1. 了解水患、河工进度、财政状况和地方利益。
2. 识别具备专业能力的人物与掌握实际资源的人物。
3. 通过交谈、调查、协商、委托和正式命令组织行动。
4. 在法定权限内调配人员、资金和资源。
5. 面对执行衰减、利益阻力、信息失真和突发事件。
6. 根据实际结果承担政绩、声望、政治风险与长期后果。

核心体验：玩家不是直接操纵世界，而是通过人与制度影响世界。

### 1.2 设计目标

- 人物具有独立动机、能力、知识和行为历史。
- 人际关系具有方向、基础和具体利益，不是单一好感度。
- 官僚组织具有明确的职位、职责、权限与责任。
- 人才可以通过科举、举荐、聘用、培养等路径进入玩家的工作网络。
- 自由输入允许玩家表达复杂意图，但执行过程受到权限、资源和现实条件约束。
- 世界时间根据实际行动推进，人物和社会不会因玩家停止操作而完全静止。
- 行政结果能够追溯到人物行为、资源变化、制度条件与实际行动。
- 玩家可以选择勤政、社交、休息、享乐或其他合法行动，不被预设的道德评价强制限制。

### 1.3 非目标

第一阶段不追求完整模拟整个王朝的所有人物、所有官制和所有历史事件。

不将人物简化为固定的忠奸标签，不将所有问题简化为数值检定，也不以大规模随机生成替代人物关系和因果模拟。

## 二、核心设计原则

以下原则建议作为后续各子系统的共同约束。

### P-01：人物优先

人物的动机、能力、知识、关系与当前状态共同决定其行为。不能因为剧情需要就强迫人物作出违背自身条件的决定。

### P-02：人物与职位分离

人物是具有独立属性和历史的个体；职位是制度授予的岗位。人物的能力、关系和身份不会自动等同于职位权限。

### P-03：关系具有方向性

甲对乙的信任不等于乙对甲的信任。恩情、亏欠、依赖、恐惧、利益和政治支持分别记录，不合并成一个好感值。

### P-04：权力可验证

任何具有实际影响的行政命令，都必须经过权限、资源、程序和前置条件检查。玩家不能仅凭自由输入创造权限或资源。

### P-05：人才获取具有过程

发现人才、接触人才、取得合作、正式任用和实际发挥作用是不同阶段，不能一次点击全部完成。

### P-06：人物知识不全局共享

每个人物只依据自己已经知道、相信、误解或有条件获知的信息行动。玩家不能自动获得所有 NPC 的秘密信息。

### P-07：时间由行动驱动

行动具有耗时，时间推进会影响人物日程、身体状态、任务期限和社会事件。动画播放不决定实际时间与业务结果。

### P-08：制度降低风险但不消灭风险

正式程序、审计、分级授权、独立核验和责任追踪可以降低执行衰减，但不能消除能力不足、串通、信息失真或外部阻力。

### P-09：结果必须可追溯

每次关键状态变化都应有原因、行动记录和相关证据。不得通过直接改写结果来掩盖失败或修复不一致状态。

### P-10：玩家保留重大决策权

系统可以解析意图、提供建议、识别风险和提出替代方案，但不能擅自替玩家决定重要人事、政治立场、重大支出或不可逆行动。

### P-11：统一人物内核，避免玩法子系统泛滥

所有人物共享同一套领域模型、行为规则和关系机制。仕途、交涉、用人、结盟、冲突、情报和人物收藏等表现，不因每种玩法而复制出一套互不相通的人物系统。只有在确有独立职责、独立状态与明确接口时才拆分逻辑模块。

### P-12：一个权威世界状态

人物、职位、权限、任务、资源、时间、关系、主线事件和人物卡展示必须引用同一份权威事实。UI 或 AI 生成内容不能形成另一套互相冲突的业务真相。

### P-13：AI 生成不等于规则执行

模型可以解析意图、扮演人物、提出行动计划和叙述结果；权限校验、时间推进、资源扣除、任命、关系变更和因果记账由规则引擎验证并提交。模型不能直接伪造成功或突破制度边界。

### P-14：主线是因果网络，不是线性任务列表

世界级长期矛盾、阶段事件、人物目标和玩家行动相互影响。玩家可以改变推进路径，但关键事件的触发、状态变化与后果必须有可追溯条件。

### P-15：美术资产工业化，人物卡承载成就

人物卡是人物系统的视觉表达和玩家成就载体。原画、布局、边框、动态信息与解锁状态分离；所有卡片遵循统一美术圣经、资产规范、审核闸门和版本追溯，不靠临时手工拼装扩容。

### P-16：决策持续维护，单一文件为准

新的已批准决策必须直接修改本设计总纲的对应章节，并同步更新版本与决策记录。不得另建互相冲突的“最新版”副本；历史版本由 Git 提交记录保留。

## 三、人物模型

### 3.1 人物的六个维度

每个人物至少由以下六类信息构成。

A. 身份与履历

- 姓名、年龄、籍贯、家庭和出身。
- 教育经历、科举经历、师承和曾任职位。
- 当前身份、所属组织、合法任职资格。
- 同乡、同年、师生、姻亲及其他社会关联。

B. 能力与局限

- 行政、财政、司法、工程、交涉、军事、情报、用人等专业能力。
- 经验、执行能力、学习能力和判断能力。
- 当前工作负荷、可用时间与身体限制。
- 专业能力之间的差异和短板。

能力维度不要求所有人物都拥有同样的专长。第一阶段只配置与当前玩法有关的能力，避免过度细化。

C. 动机与人格

- 仕途目标、家族利益、财富、名声、理想和安全需求。
- 风险偏好、处事风格、控制欲、合作倾向。
- 道德底线、压力反应和冲突处理方式。
- 公开动机与可能存在的隐性动机。

人物可以具有相互冲突的目标。例如，某官员既希望河工成功，又不愿承担额外责任；某商人既希望地方安定，又希望获得稳定的商业利益。

D. 关系与社会资本

- 信任、恩情、亏欠、竞争、恐惧、依赖和利益交换。
- 师生、同乡、姻亲、旧部、同僚及其他关系类型。
- 关系建立的原因、持续时间和适用范围。
- 对方是否愿意公开支持，以及愿意承担多大风险。

E. 知识与认知

- 已知事实、传闻、个人判断、错误认知和秘密。
- 信息来源、获取时间、可信程度和传播路径。
- 对其他人物的判断及判断依据。
- 哪些信息可以公开，哪些信息会被刻意隐瞒。

F. 当前状态与行为历史

- 身体状况、疲劳、工作负荷和当前日程。
- 当前任务、承诺、计划、期限和资源占用。
- 过去的关键行动、承诺兑现情况和重要冲突。
- 公开行为、可被观察的行为与需要调查才能发现的行为。

### 3.2 人物状态与隐藏信息

人物信息应区分：

1. **客观状态：**世界规则中的实际事实。
2. **人物认知：**该人物知道或相信的内容。
3. **玩家认知：**玩家已经获知并有依据相信的内容。
4. **社会传闻：**正在传播但尚未确认的说法。

这四者不能混为一谈。

例如，账册实际存在问题，不意味着县令、县丞和粮商都知道问题，更不意味着玩家可以直接看到真实原因。

### 3.3 人物行为原则

人物行动由多个条件共同影响：

- 当前目标与利益。
- 专业能力和现实资源。
- 与相关人物的关系。
- 掌握的信息和主观判断。
- 当前职位、正式权限和风险。
- 当前时间、工作负荷与外部事件。

任何单一属性都不应完全决定行为。

### 3.4 统一人物内核与可互动性

人物系统是共用内核，不为每类人物各造一个独立子系统。人物可对玩家产生的影响，以及玩家对其可采取的特殊互动，由以下条件组合推导：身份与履历、当前职位、正式权限、能力与局限、动机、双方关系、掌握的信息、可调动资源、当前状态、历史承诺、所属组织及当前事件。

每次互动应区分：

- **动作是否存在：**双方身份、关系、知识和场景是否允许发起该动作。
- **动作是否可执行：**权限、资源、时间、前置条件与目标人物状态是否满足。
- **对方是否愿意配合：**动机、风险判断、关系、利益与过往行为共同决定。
- **实际影响是什么：**规则引擎根据成功程度、成本、阻力和后续事件计算，不能由对话措辞直接决定。

常见互动使用通用动作原语（如询问、探查、请求、承诺、交易、委托、推荐、劝说、施压、保护、奖赏、拒绝、追责）。人物专属互动通过身份资格、关系状态和事件条件配置，不为每一种人物身份复制一套执行逻辑。

### 3.5 人物数据与人物卡展示分离

Person 的权威业务数据与人物卡视觉表现分离。人物卡可以读取人物身份、公开履历、已知关系、已确认经历与允许展示的状态，但不能成为业务事实的唯一存储位置。姓名、官职、关系、成就题签、事件纪念与互动按钮由 UI 数据渲染，禁止将动态文字烘焙进人物原画。

人物卡可以有不同视觉等级、卡框和动画，但这些是统一人物系统的展示规格，不是独立的角色养成或业务规则系统。人物卡的解锁、升级或纪念标记必须由真实世界事件触发并进入因果记录。

## 四、社会关系与利益网络

### 4.1 三类社会结构

### 正式组织网络

包括朝廷、地方行政机构、县衙内部组织以及司法、财政、河工等专业体系。

正式组织决定岗位职责、报告链路、审批程序和责任归属。

### 非正式关系网络

包括同乡、同年、师生、姻亲、私人交情、利益合作、债务关系和信息渠道。

这些关系会影响合作意愿、消息传播和执行成本，但不能自动取代正式权限。

### 事件型临时联盟

人物围绕具体事务形成合作或对抗关系。例如，河工治理时可能形成县衙、工程人员、粮商与地方士绅之间的临时合作；事务变化后，联盟也可能解体。

### 4.2 关系记录

每条重要关系至少应记录：

- 关系主体与对象。
- 关系类型和方向。
- 建立原因与相关事件。
- 当前状态和变化历史。
- 关系适用范围。
- 公开程度及可能产生的政治风险。

关系变化必须由具体行为或事件驱动。单纯增加交谈次数，不应自动获得永久信任。

关系至少区分个人关系、正式组织关系和事件型联盟。人物可同时属于多个圈子；同一人物在不同事务上可能支持玩家、保持中立或产生对抗。圈子关系不是全局阵营锁定，其变化必须由利益、事件、信息与人物选择推动。

### 4.3 社交行动

第一阶段支持以下基础动作：

- 询问与探查。
- 交谈与试探。
- 请求帮助。
- 提出承诺。
- 交换利益。
- 委托任务。
- 建立合作。
- 施加压力。
- 调查与核验。
- 保护、奖赏和追责。

每种动作均应具备适用条件、耗时、潜在成本和可能后果。

## 五、人物来源与人才获取

### 5.1 三类人物来源

### 历史人物

用于构建特定历史背景中的真实人物。历史身份、履历与任职信息应有可核查来源；推测内容和虚构行为应与史实区分。

### 预设人物

承担核心剧情、关键制度职能和主要关系网络。预设的是人物背景、动机、能力边界和初始关系，而不是每次行动的必然结果。

### 动态生成的人物

按照时代、地区、出身、教育、职业、家庭、能力分布和社会网络等规则生成。人物履历、身份和关系必须保持内部一致。

### 5.2 人才获取路径

第一阶段建立四条路径：

1. 科举入仕。
2. 上级、同僚或社会关系举荐。
3. 合法聘用幕僚与专业人员。
4. 通过历练、培训和考核培养人才。

后续可以扩展征辟、调任、临时借调、人才流动和其他符合所选历史制度的方式。

### 5.3 人才获取阶段

人才获取统一经过以下状态：

“发现 → 接触 → 评估 → 合作或任用 → 分配职责 → 实际执行 → 考核与发展”

各阶段可能失败、延迟或改变方向。

人才的专业能力、合作意愿、正式身份、任职资格和权限必须分别检查。

### 5.4 仕途、赏识与提携机制

仕途是人物系统的长期结果，不单独建立一套与人物关系割裂的“升官游戏”。人物的仕途状态、上级评价、举荐关系、资格、任职表现和职位竞争由统一人物、关系、制度与事件规则共同驱动。

升迁过程至少区分以下阶段：

1. **具备资格：**是否满足所选时代与官制规定的出身、资历、考核、回避与任职条件。
2. **进入视野：**政绩、声望、信息渠道、上司观察或他人举荐使玩家成为潜在人选。
3. **获得支持：**某位上司、同僚或有影响力者愿意提供信息、评价、引荐、正式推荐或承担担保风险。
4. **进入竞争与审查：**与其他候选人比较，接受程序、考核、审查和政治环境影响。
5. **正式任命：**只有相应职位空缺、程序和最终决策条件满足后，才形成任命事实。
6. **任后表现：**履职结果反过来影响声誉、支持者判断、后续仕途和潜在责任。

上司的“赏识”不能压缩成单一好感值。至少区分：能力认可、私人信任、可靠性判断、价值观/办事风格契合、提携意愿、正式影响力、程序权限、承担风险的意愿，以及当前是否具备可用的职位/机会。

上司赏识会提高玩家进入视野、获得推荐或获得有利评价的机会，但不保证任命。升迁综合考虑资格、实际政绩、职位空缺、推荐人影响力、其他候选人、制度程序、上级政治处境、时机和风险。具体权重须由所选时代和原型测试决定，当前不冻结数值。

提携具有成本和条件：时间、人情往来、资源支出、政治风险、公开声誉及支持者自身利益。关系维护不应成为无限刷取好感的循环；重复寒暄不能无成本增加信任。帮助也可能是有条件的、有限的、延迟的，或因为支持者失势、利益变化、失信与负面事件而被撤回。

关系变化由具体行动和事件驱动。事件记录至少包括支持者、受益者、支持类型、发生时间、依据、公开程度、对支持者的成本/风险、相关承诺和后续结果。私人提携、正式举荐、职位决定和法定任命必须作为不同事实处理。

史料借鉴边界：杜凤治日记及相关研究显示，晚清候补、补缺、调署、上司评价、官场关系、程序次序与现实机会会共同影响仕途；史料中的当事人判断具有主观性，不能直接当作统计规律。游戏要吸收“关系能改变机会结构，但不能替代制度与结果”的机制思想，不把史料个案硬编码为通用概率公式。

## 六、职位、权力与权限系统

### 6.1 四个独立对象

### Person：人物

保存个人身份、能力、动机、关系、知识和行为历史。

### Position：职位

保存岗位职责、组织归属、任职条件、上下级关系和责任范围。

### Authority：权限

保存主体可以合法执行的动作、适用范围、限额、期限、地域、审批条件和禁止事项。

### Delegation：委托

保存具体任务的目标、执行人、资源、时间期限、汇报要求和问责主体。

一个人物担任某职位后，才可以依据任职规则取得相应权限。权限也可以依法被委托或限制，但委托不得超出委托人的权限边界。

### 6.2 权力类别

- 人事权。
- 财政权。
- 行政权。
- 司法权。
- 工程与应急处置权。
- 调查、核验与监督权。
- 上报、举荐与申请批复权。

具体权限应由所选时代、官制、法令、职位和授权文书共同决定。

### 6.3 指令执行检查

任何关键指令都应依次检查：

1. 指令意图是否明确。
2. 执行主体是否具备合法权限。
3. 目标人物是否具备任职资格或相应能力。
4. 所需资金、人员和物资是否可用。
5. 是否需要额外审批或法定程序。
6. 是否存在冲突、截止时间或前置条件。
7. 是否可以安全地提交并记录结果。

检查失败时，系统应说明具体原因，并在可行时提出合法替代方案。

### 6.4 权力与影响力分离

正式权力、实际控制力、社会影响力、信息优势和政治承受力是不同维度。

没有官职的人物可能具有很强的社会影响力，但不能因此获得法定裁判权；拥有正式职位的人物也可能因为资源不足、下属抵制或信息不全而无法有效执行命令。

## 七、自由输入与行政行动系统

### 7.1 设计目标

玩家可以用自然语言描述目标、方向、约束和偏好，不必预先了解所有内部规则。

系统负责把指令转换成可验证的行动计划。

### 7.2 指令解析结构

每项重要指令至少解析：

- 目标。
- 行动方式。
- 执行人员。
- 资源要求。
- 权限要求。
- 时间期限。
- 约束与禁止事项。
- 验收标准。
- 汇报和监督要求。

### 7.3 部分执行

一条指令可能包含多个独立子任务。若部分任务合法、部分任务受阻，系统应尽可能保留可执行部分，并明确显示阻塞原因。

涉及重大支出、人事任命、重大政治承诺或不可逆后果的行动，应在必要时请求玩家确认。

### 7.4 行政结果

行动结果不能只分成功与失败，还应区分：

- 按计划完成。
- 部分完成。
- 延迟完成。
- 因资源不足受阻。
- 因权限或程序受阻。
- 因人员能力不足受阻。
- 因利益冲突或主动抵制造成偏差。
- 因信息错误导致决策偏差。
- 因外部事件改变原计划。

这些结果应进入世界状态和因果记录。

### 7.5 API 与 AI 行动编排

自然语言入口通过统一的 AI 编排层调用模型服务，不由每个功能各自直连不同模型。最小闭环为：玩家输入 → 意图解析 → 生成结构化行动提案 → 规则引擎校验 → 玩家确认（仅在必要时）→ 执行事务 → 状态与因果记录提交 → AI 根据已提交结果生成叙事反馈。

结构化提案至少包含目标、对象、动作、执行人、资源、权限、期限、约束、验收标准、监督方式、待澄清项与风险。信息不足时应提出一个聚焦问题，或给出可撤销的计划预览，不应擅自补全会改变重大决策的关键条件。

模型输出不是可信业务指令。后端必须校验结构、允许的动作类型、世界版本和权限；不合规、越权或超时的响应不能改变世界状态。结果叙事必须引用已经提交的行动结果，不得先写“成功”再倒推规则状态。

统一 AI 网关应负责模型提供方适配、结构化输出、超时、有限重试、速率限制、成本统计、提示词版本、上下文裁剪、错误记录和提供方切换。确定性数值计算和常规 NPC 状态更新不应无必要地调用模型。

人物对话上下文只加载该人物可知的信息、双方可见的关系事实、当前场景、已发生事件和必要记忆。不得把全世界秘密或玩家未发现的信息无差别注入 NPC 提示词。

## 八、行动时间与身体状态

### 8.1 连续时间

世界使用连续时间，行动决定时间推进量，不使用固定回合强制推进所有内容。

每项行动应定义：

- 预计耗时。
- 实际耗时。
- 可能中断条件。
- 是否允许并行。
- 是否可委托。
- 相关截止时间。
- 对人物日程和身体状态的影响。

具体时长先作为可配置参数，不在缺乏验证时冻结数值。

### 8.2 睡眠与作息

玩家可以安排休息时间与次日起床时间。

系统根据实际睡眠时长、睡眠质量、既有疲劳和身体状况计算恢复。计划入睡时间与实际入睡时间必须区分。

### 8.3 身体维度

至少分别记录：

- 清醒度。
- 疲劳。
- 专注力。
- 健康状况。
- 作息规律。

身体状态影响行动效率和风险，但不应无理由地强制禁止玩家升堂、交际或继续工作。

### 8.4 NPC 日程

重要人物拥有自己的日程、目标与任务。其他人物采用低成本的事件驱动模拟，在与玩家、关键人物或重要事件发生关联时再展开详细行为。

玩家休息时，世界仍然继续推进。

## 九、行政执行衰减与制度治理

### 9.1 五类执行衰减

1. 人员能力与工作投入。
2. 组织协调与信息交接。
3. 资金、物资、运输和资源损耗。
4. 信息过滤、延迟、误报与隐瞒。
5. 利益抵抗、拖延、串通和程序性阻力。

系统应区分“不能执行”和“不愿执行”，不能把所有偏差统一归因于腐败。

### 9.2 制度对抗机制

可用机制包括：

- 明确权限与责任。
- 专项预算和分阶段拨付。
- 独立核验。
- 双人复核。
- 阶段性验收。
- 账目追踪与责任追究。
- 多来源信息交叉验证。

制度可以降低风险，但不能保证所有执行者诚实，也不能替代专业能力和现实资源。

### 9.3 统一因果记录

关键行动、拒绝、资源变更、权限判定、任务进度、关系变化和事件结果必须可以追溯。

记录采用追加式设计，不通过覆盖历史记录修正过去。

同一行动重复提交不得重复扣除资源或推进时间。多项状态变化应以一致的逻辑事务提交，避免出现只扣款、不生成任务或只推进时间、不记录行动的半完成状态。

## 十、首个验证场景：黄河河工治理

### 10.1 场景目标

验证人物、社交、权力、人才、时间与执行系统能否共同运行。

### 10.2 初始角色构成

建议配置以下角色原型，姓名和具体数值暂不冻结：

- 县令：玩家，拥有符合职位的正式权限。
- 县丞：协助行政协调，具有自身利益与工作负荷。
- 河工专家：具备专业知识，但未必拥有行政调度权。
- 粮商：掌握采购资源，有自己的商业目标。
- 地方士绅代表：拥有地方关系和社会影响力。
- 主簿或账目相关人员：掌握部分财政信息。
- 工程执行人员：掌握一线进度与实际困难。
- 上级官员或监督人员：拥有不同于县令的审批和监督权限。

具体角色是否采用历史人物、预设人物或动态生成方式，须根据时代与剧情配置确定。

### 10.3 关键验证流程

1. 玩家调查河工现状。
2. 玩家通过交谈和线索判断不同人物的能力与利益。
3. 玩家寻找或接触专业人才。
4. 玩家提出治理方案并分配职责。
5. 系统检查权限、资金、资源和审批要求。
6. 玩家选择正式命令、协商、监督或其他合法方式。
7. 世界时间推进，人物执行各自任务。
8. 系统计算执行偏差、关系变化、资金消耗和实际进度。
9. 玩家根据报告、证据和现场结果调整计划。
10. 任务完成或受阻后，进行验收、问责与后续影响结算。

### 10.4 验收问题

- 玩家能否识别谁有能力、谁有权力、谁掌握资源？
- 玩家能否通过社交获得有效帮助，而不是依赖固定奖励？
- 越权指令是否被识别并说明原因？
- 委托是否具有清晰边界与责任归属？
- 人物是否依据各自的信息和利益行动？
- 时间推进是否影响人物日程和任务期限？
- 执行偏差是否能够追溯到具体原因？
- 同一操作是否能够安全重放而不重复产生结果？

## 十二、架构原则与实现边界

### 12.1 系统职责

建议采用四个核心逻辑模块：

人物与关系引擎

管理人物状态、关系网络、知识、动机与行为选择。

行政执行引擎

管理任务、委托、资源、工作进度、执行偏差和验收。

制度与权限引擎

管理职位、法定职责、审批、权限校验和责任归属。

事件与因果引擎

管理时间推进、事件触发、状态变更、历史记录与结果叙事。

四者必须共享统一、权威的世界状态，不能各自维护互相矛盾的业务事实。

### 12.2 规则与语言模型分工

语言模型可以负责：

- 理解玩家的自然语言意图。
- 生成对话与叙事表达。
- 提出调查方向与策略建议。
- 将复杂状态转化为易理解的报告。

确定性规则引擎负责：

- 权限与程序检查。
- 资源和数值变更。
- 时间推进。
- 人物状态与任务状态。
- 随机判定的执行与记录。
- 事务一致性、幂等性和因果账本。

叙事文字不能绕过规则直接改变业务结果。

### 12.3 单一人物内核与模块拆分约束

人物、关系、身份、能力、动机、认知、社会资本、状态、历史和人物展示数据应围绕同一套人物领域模型组织。交际、人才、仕途、声誉、冲突与人物收藏优先复用同一组人物行为、关系、事件和权限规则；不得仅因为 UI 上出现新的功能入口，就自动新增一个独立业务引擎。

允许将代码划分为人物与关系、制度与权限、行政执行、世界事件/时间、AI 编排、表现层等模块，但模块是职责边界，不是互相重复维护数据的孤岛。所有写入统一经过领域命令与规则校验，重要状态变更使用一致的事务和追加式事件记录。

### 12.4 世界主线与事件网络

主线由世界级长期矛盾、阶段性局势、关键人物目标和可触发事件组成。主线不是只能按固定顺序完成的任务清单，也不应完全交给模型即兴编造。事件应声明前置状态、触发条件、参与人物、可见线索、可能行动、结果分支、时间窗口及因果影响。

玩家可以改变解决方式、联盟构成、人物态度和局部结果；世界主线的核心矛盾继续受既有规则推进。关键剧情可以预设角色背景与事件边界，但不应预设每次行动的唯一结果。

### 12.5 技术选型约束

在检查现有工程环境之前，不冻结具体前端框架、动画库或持久化技术。

新项目应与既有《仙尊悔》业务代码、领域模型和存档体系隔离。只有经过检查并确认通用价值的基础工具链可以复用。

## 十三、待决事项

以下内容属于下一轮设计工作，不应在初稿中擅自定案。

1. **时代背景：**采用明确的历史朝代、架空王朝，还是以历史制度为基础的架空世界。
2. **官制基准：**确定官职、品级、管辖范围、任免程序和上下级关系的规则来源。
3. **人物属性颗粒度：**确定哪些属性直接数值化，哪些使用离散状态或文字描述。
4. **关系数值模型：**确定信任、亏欠、恐惧、依赖等维度的变化与衰减机制。
5. **人才成长规则：**确定科举、举荐、培养、任用和晋升的具体制度。
6. **时间与身体参数：**通过原型测试确定行动耗时、疲劳累积、睡眠恢复和专注力影响。
7. **随机事件治理：**确定随机种子、触发条件、概率配置、日志和重放规则。
8. **模拟规模：**确定重要人物、普通人物和远端社会网络的模拟频率。
9. **长期政治系统：**确定考核、升迁、派系、弹劾、声望和政治风险的开放顺序。

## 十四、版本验收标准

v0.2 文档本身的完成标准：

- 明确项目定位与核心设计原则。

- 指明唯一权威设计源、版本更新与决策记录流程。

- 定义人才获取的阶段流程。

- 能够演示合法授权、越权阻塞和部分执行。
- 能够演示人物信息不对称与关系变化。
- 能够演示行动耗时、睡眠与次日政务的联动。
- 关键状态变更具有可追溯记录。
- 具备自动化测试、界面截图和已知问题清单。
- 未通过验证的内容不得标记为已完成。

## 十五、世界主线与大世界推进

### 15.1 核心结构

世界主线由三层共同组成：

- **世界级长期矛盾：**例如河工失修、财政压力、地方利益争夺、治理政策变化等持续存在的结构性问题。
- **阶段性局势与事件：**例如堤坝险情、工款短缺、上级巡查、乡绅拒绝协作、账册疑点或突发灾情。
- **人物个人经历：**例如玩家获得提携、建立盟友、得罪权贵、发现贪腐、培养人才或因失职承担后果。

三层共享同一世界状态。一个人物事件可以改变利益圈子态度；利益圈子变化影响资源与执行；治理结果再影响上司评价、声誉和后续事件。

### 15.2 事件定义

关键事件至少定义：事件 ID、触发条件、前置状态、参与者、每个参与者掌握的信息、时间窗口、可选行动、执行成本、结果分支、后续事件、可见线索和结束条件。事件可以被延迟、升级、被其他事件打断或因玩家行动改变，但不能无条件重复刷出。

### 15.3 主线连续性与玩家自由

系统应保持主线方向和世界因果，而不是强迫玩家沿唯一通关路径行动。玩家可以选择先调查、先谈判、先休息、寻求上级支援或暂时搁置。每个选择可产生机会成本与后果；世界在玩家休息或离场时仍按时间规则演化。

AI 可以根据状态提出新线索和叙事表现，但不得凭空创造已经生效的任命、资源、证据或关系事实。新内容必须作为候选事件，经规则条件确认后才能写入世界。

## 十六、人物卡与美术工业链

### 16.1 人物卡的产品价值

人物卡既是角色信息入口，也是收藏、纪念和成就载体。它应呈现人物身份、辨识度、与玩家的关系，以及经真实事件形成的共同经历。人物卡不只是静态 NPC 数据面板，也不应沦为只靠稀有度或数值战力刺激收集的抽卡物件。

### 16.2 展示规格

同一人物数据可以有不同展示形态，不建立多套人物业务系统：

- **关系卡：**用于拜访、交涉、请托、任用、考察和冲突处理，突出当前可知信息、关系状态、互动入口和风险提示。
- **人物典藏卡：**用于图鉴、生涯档案、重要人物发现及关系里程碑，突出人物肖像、身份特征、代表事迹和收藏纪念。
- **关键人物特制卡：**为少量主线人物、重要提携者、关键盟友或重大政敌提供专属构图、边框、动效或背景。

三者读取同一人物数据；信息展示应遵守玩家认知权限，不因“收藏”就把尚未发现的秘密暴露给玩家。

### 16.3 视觉方向与美术圣经

建议基调为中国历史人物的文化质感、精致收藏卡的仪式感和现代移动端的清晰信息层级。以纸、墨、绢、印等材质和米白、月灰、青灰、黛蓝、朱砂等颜色形成基础识别，金色仅作为克制的强调元素。避免过量黑金、满屏光效、过度装饰以及让边框压过人物本体的设计。

美术圣经至少规定：画幅比例、肖像占比、姿态/视线、面部安全区、文字留白、光照、色彩、材质、线条/笔触、边框层级、字体与字号、身份符号使用规则、透明边缘、背景复杂度、不同屏幕的裁切区，以及禁止项。风格方向应先由少量样板卡验证，未经样板验收不得批量生产。

### 16.4 分级生产与成本控制

- **A 级关键人物：**主线关键人物、重要上司、重大恩人/政敌；定制原画与专属细节。
- **B 级重要人物：**核心同僚、幕僚、重要乡绅或长期盟友；高质量标准原画，有限定制。
- **C 级普通人物：**一般官员、商人、士绅等；遵循标准模板和风格规范批量生产。
- **D 级临时人物：**短期出现、剧情权重低的角色；采用可控的基础肖像体系。若后来成为玩家经历中的关键人物，可提升展示规格，但不得篡改人物原有事实。

此分级只决定美术资源投入，不代表人物道德价值、玩法价值或对玩家的永久重要程度。

### 16.5 工业化生产流水线

1. **资产盘点：**登记人物 ID、身份、剧情重要性、素材现状、缺失项与使用范围。
2. **人物视觉 Brief：**由已确认的人物设定生成设计说明，包含时代、身份、年龄、性格、标志物、情绪、参考素材和不可改变的特征。
3. **参考与权利检查：**登记参考来源、授权/使用限制；历史人物履历有来源，推测/虚构部分需标明。
4. **草图与构图评审：**先审核剪影、姿态、面部、视觉焦点与信息留白，再进入精绘。
5. **样板精绘与风格锁定：**先完成少量差异明显的人物样板，确定质量、成本和风格边界。
6. **批量生成/绘制：**AI 用于概念探索、变体与生产辅助；重要人物必须人工审核。禁止仅凭模型生成结果直接批量入库。
7. **美术加工：**裁切、清理伪影、透明边缘/背景处理、色彩统一、尺寸导出、缩略图生成。
8. **UI 组装：**姓名、官职、标签、关系、题签和状态由真实数据渲染；原画不内嵌动态文字或 UI。
9. **技术检查：**校验格式、尺寸、透明通道、文件大小、命名、ID 唯一性、资产完整性和授权元数据。
10. **游戏内视觉验收：**检查列表缩略图、详情卡、长姓名、长官职、多种屏幕比例、深浅背景、动效和低性能设备。
11. **归档发布：**保留源文件、导出文件、提示词/模型版本（如使用 AI）、人工改动、审核记录、资产版本和回滚指向。

### 16.6 资产数据契约

每张卡必须有稳定的 assetId/personId 绑定、assetTier、artStatus、sourceFile、runtimeFile、dimensions、format、transparency/background 约定、license/source、prompt/model metadata（适用时）、reviewer、reviewStatus、version 和 change history。UI 不按文件名猜测人物，不允许缺图时静默显示错误人物图；缺失时使用明确的兜底资产并写入诊断记录。

### 16.7 验收闸门

- **G1 设定：**人物身份、时代、服饰与视觉特征一致。
- **G2 构图：**缩略图可辨识，面部/轮廓清楚，信息区留白充足。
- **G3 风格：**色彩、材质、线条、光照和细节密度符合美术圣经。
- **G4 技术：**格式、尺寸、透明边缘、命名、关联 ID、来源和授权信息完整。
- **G5 UI：**真实游戏布局中信息可读，裁切、长文本和响应式状态正常。
- **G6 发布：**自动检查通过、视觉证据存档、源文件可追溯且具备回滚方案。

任一必需闸门未通过，不得把资产标记为 READY 或正式发布。

### 16.8 成就与人物关系联动

人物卡可以通过首次结识、关键合作、上司正式举荐、共同度过危机、兑现承诺或关系破裂等真实事件获得纪念题签、印章、卡面变体或履历记录。每项纪念必须引用事件 ID 与发生时间；不能凭空写入人物经历，也不能单纯靠重复聊天或无成本送礼解锁。

## 十七、API、AI 与沉浸式叙事技术契约

### 17.1 统一编排层

所有模型服务经统一 AI Gateway/Provider Adapter 接入。业务领域不直接依赖某一个供应商 SDK；供应商、模型名称、提示词版本和参数应可配置与审计。模型切换不得改变领域规则的含义。

### 17.2 受控调用流程

每次高影响行动遵循：

1. 读取玩家有权获知的当前上下文。
2. 模型解析意图并产出结构化提案。
3. 校验提案 schema、世界版本、权限、资源与前置条件。
4. 在必要时向玩家展示计划/风险并请求确认。
5. 领域规则计算结果，事务性提交状态和事件记录。
6. 将已提交结果与可见信息交给模型生成叙事反馈。
7. 校验叙事不泄露隐藏信息、不声称未发生的结果。

### 17.3 记忆与上下文

持久化记忆以结构化事件、稳定人物事实、已验证关系、承诺与关键对话摘要为主。原始聊天全文不应无上限塞入每次请求。每条记忆应标明来源、时间、确定性、保密级别与可被哪些人物获知。

### 17.4 可靠性与成本

必须处理超时、限流、提供方故障、无效 JSON、重复提交、上下文过长及模型输出不安全/不合规等情况。重试不得导致重复扣款或重复推进世界时间；同一命令需有 idempotency key。记录请求耗时、token/费用估算、模型/提示词版本、校验失败类型与最终领域结果；不记录不必要的敏感数据。

### 17.5 叙事一致性测试

测试包括：模型是否编造人物知道的秘密、是否将建议写成已经执行的命令、是否无视权限/资源限制、是否把同一事件叙述成不同事实、模型不可用时能否安全恢复，以及多轮对话是否维持人物性格但允许其因真实事件改变立场。

## 十八、设计单与决策治理

### 18.1 唯一权威文件

本仓库以 `docs/design/官员模拟器-人物与官场社会模拟系统设计总纲.md` 作为唯一权威设计单。其他 Word、PDF、截图、原型说明仅作导出物或辅助证据，不得成为互相冲突的平行版本。后续已批准的新决定直接修改此文件对应章节。

### 18.2 决策状态

- **已确认：**用户已明确同意或已明确要求实施，按设计基线执行。
- **建议中：**方案已提出，但尚未获得明确决策；不得标成已批准。
- **待验证：**须经原型、史料核查、性能测试或美术样板确认后才能冻结。
- **已废止：**被更新决策替代；保留简要缘由，完整历史由 Git 记录保存。

### 18.3 每次变更的记录

影响核心规则的变更应记录：决策 ID、日期、状态、修改章节、变更内容、原因、受影响的规则/界面/数据、验证方法及潜在兼容性影响。小型措辞修订不必制造冗长记录，但不得改变已确认语义而不更新决策条目。

### 18.4 变更工作流

新决定 → 判断其属于新需求、澄清、替代还是撤销 → 修改对应正文 → 更新版本号与决策记录 → 检查受影响章节是否矛盾 → 更新验收标准/待决事项 → 生成 Word/PDF 导出（如需要）→ 进入实现/测试。不得只在聊天或附件中留下决定而不更新权威设计单。

### 18.5 版本规则

- **Major：**改变核心体验、领域边界或既有原则。
- **Minor：**新增已确认的系统规则、流程、模型或生产要求。
- **Patch：**澄清文字、修正错误、完善示例而不改变语义。

当前 v0.2 属于 Minor：在既有人物/官场模拟基线上补入统一人物内核、仕途提携、世界主线、AI/API 治理、人物卡与美术工业链，以及设计单持续维护规则。

## 十九、决策清单与待决事项

### 19.1 当前已确认的设计方向

- 以人为核心，社交是核心玩法；人物的立体维度决定其影响方式和玩家可用互动。
- 不按每种玩法建立独立且重复的子系统；以统一人物内核、统一世界状态和事件因果组合功能。
- 玩家自由输入、大方向由玩家决定、合理的小细节可由 AI 承接；重大且不可逆决定仍由玩家掌控。
- 行动耗时驱动连续世界时间；作息与身体状态影响效率但不强制单一道德化玩法。
- 上司赏识、举荐和提携可以提高仕途机会，但不能替代资格、绩效、竞争、职位空缺和正式任命程序。
- 人物卡是独特的收藏/成就表达，必须与动态数据分离，并通过美术圣经和工业链生产。
- API/模型服务可替换，规则引擎对业务结果拥有最终权威。
- 本仓库中的设计总纲是唯一权威设计源；新决策需直接更新此文件。

### 19.2 待决事项

1. 时代背景：明确历史朝代、以史制为基础的架空，或完全架空。
2. 官制基准：官职、品级、权限、考试、考核、调任、任命和回避规则的具体依据。
3. 人物数值化颗粒度：哪些维度使用连续数值，哪些采用离散状态或文本标签。
4. 关系变化模型：信任、恩情、亏欠、依赖、恐惧、政治支持的数值与衰减方式。
5. 仕途细则：考核周期、空缺产生、候选池、推荐书/考语、审查和任命流程。
6. 人物卡美术圣经：具体画幅、颜色令牌、字体、边框样式和动效时长，需由样板验收冻结。
7. 生成模型与预算：API 提供方、模型组合、预算上限、隐私策略与本地/远端模型边界。
8. 时间与身体参数：行动耗时、睡眠恢复和疲劳阈值通过原型校准。
9. 模拟规模：重要人物、普通人物、远端社会网络的模拟频率与性能预算。
10. 随机事件治理：随机种子、可重放性、概率配置和事件触发审计。

### 当前版本结论

本项目的核心不是官职收集、单一好感度、互不相连的功能面板或无限即兴剧情，而是一个由独立人物、动态关系、正式制度、有限时间、组织执行和事件因果共同构成的社会模拟世界。人物系统提供统一的行为内核；大世界主线提供长期矛盾和事件结构；规则引擎维护事实；AI 负责把人物与世界状态转化为连贯、可沉浸的交互；人物卡与美术流水线将真实人物经历转化为可收藏、可回顾的视觉成就。

第一阶段仍以县令治理黄河河工为验证场景。只有当玩家能够完成“理解人物 → 获得合作 → 依法行权 → 组织执行 → 处理偏差 → 获得反馈并承担后果”的完整循环，且状态一致、AI 输出受控、人物卡资产可追溯，才进入更大规模的人物网络和仕途/朝廷政治扩展。
