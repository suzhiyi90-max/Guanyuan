## 二、设计规格

### 6.3 S-03 人物/三问

- **成长页预览（FE-044 / FE-004）：** 人情页新增第 4 个内嵌工作面「成长 · 预览」（不新增一级入口、不新增叠层），以 C-60 五轴纸只读既有 `capability` / `needs` / `reputation` / `tokens` 与 `GameState` 派生事实：能力（既有称号与动机）、仕途（志向 / 题销 / 回文）、关系（问话、共事、三栏债）、世俗（私囊 / 礼簿 / 家用）、继承（M3 未启用 · 留白）。页眉固定「规则未启用 · 仅预览 · 非 S-12 规则层」，不挂依何条小签；不新增成长数值、等级、经验条、进度条或名望刻度，不写存档。人物卷与 S-23 人情簿各挂同一组件的 `slip` 小签。390px 四签改 2×2 两行、标题单行。
- **人情簿入口（FE-037）：** 人情页标题右侧加「人情簿 · 债与把柄」，打开 S-23；只把既有 `tokens`（owesYou/youOwe/hook）与 `hookNote` 并到一处，不新增债务、好感或可用筹码。

```
┌──────────────────────────────────────────────┐
│ [肖像] 县丞 · 正八品 · 管河佐贰               │
│ 他想要：保河厅关系 / 不出事                   │
├──────────────────────────────────────────────┤
│ 能不能做？ 能协调，但不能定工法                │
│ 愿不愿做？ 愿，若你先报河厅                    │
│ 敢不敢做？ 不敢单独担责                        │
├──────────────────────────────────────────────┤
│ 债：你欠他 1（接风宴）                         │
│ 秘密：他知道县丞与士绅往来（未证实）           │
│ 接触：第2日 席上 · 第3日 河堤（亲见）          │
│ 最近：第 2 日在席上劝你“先报河厅”              │
├──────────────────────────────────────────────┤
│ [问] [请] [托] [压] [保] [查看关系]            │
└──────────────────────────────────────────────┘
```

**规则：** 三问必须给依据（最近 3 条）；不显示单一好感数字；未知秘密显示“？”而非内容；**接触记录只显示玩家可知的接触（c-23），不自动推出结论，也不把「接触」写成「知道」**。

**人情名目（FE-065）：** 谱面点选先查验右栏，名目只读既有 tokens；闻名者不展开，人物卷仍由右栏入口进入；详见 6.32。

**谱面记忆（FE-090 · v0.88）：** 关系谱查验人、名册选中与图鉴卷次走既有 `viewMemory`，只存会话内、刷新即散；`focusRequest` 仍优先，跨屏回查不会被旧焦点覆盖。只改看哪一页，不改接触深度、债务、秘密与收藏深度。

### 6.3.1 人情谱谱纸、聚光与方位键（FE-126 · v1.24）

关系谱的底材改由专图承担（`paperArt.netstage` → PS-20 人情谱底纸）：图未到时保留旧网格作降级并标「谱纸待补」，图到位整幅覆盖，界面不再画方格。谱面三条规则不变：**只连你与对方**、**线型表接触深度**、**名帖尺寸不表亲疏**。

- **线：** 六条接触线改极轻手绘弧（中点垂推 16%，圆头），深度仍是闻名虚线 / 相识黛线 / 共事朱线；不新增箭头、权重或方向。
- **聚光：** 悬停或聚焦某人物时，其余名帖压到 `saturate(.82) opacity(.74)`、其余线 `stroke-opacity .12`，移开即撤。只压不藏——谱面不是筛选器，也不改查验人以外的任何状态。
- **键盘：** 六枚名帖只留查验人一个 `tabIndex=0`，方向键按方位评分移动、Home / End 到首末；点选、窄屏把右栏带入视野的逻辑与 `focusRequest` 优先级一条未动。
- **纸底：** 名帖、中心「知县」卡与右侧查验栏补 `--paper-grain` multiply，和谱纸同一质感；查验栏仍是唯一展开名目的地方。

### 6.3.2 接谈纸与人物侧口径（FE-145 · v1.48 · 已施工）

场景里的「在场名帖」点开后是一张**接谈纸**，不是第二个人物卷。屏幕与视觉规格以 [`06` 6.1.12](06-场景与案头.md) 为准；本节只定人物侧的口径，防止实现时把「问」做成「命令」，或把公开度做成新的关系数值。

- **寒暄一句：** 0 费、读，只展开 `person.quote` 或一句中性应答；不入台账、不入回声、不改关系。给「闻名」人物一个能开口的最低门槛。
- **三问照旧：** 只能展开既有 `person.questions` 的 answer / basis；不新增台词、不改写措辞，不把「能不能 / 愿不愿 / 敢不敢」改名成好感或信任。
- **正式问一回照旧：** 仍走 `askPerson`，首次耗一段、重复 0 费；台账只记「问过」，不记原话。当众 / 独对只改 toast 说明，不改写入内容。
- **私话门槛用既有投影：** 「问一句私话」用 `revealDepthOf !== '闻名'`，「把话挑明」用 `person.tokens.hook > 0`；分别展示 `fear` 与 `hookNote`。**不新增把柄、不推断未写秘密、不把私话写进 `asked` 或 `giftEntries`。**
- **先公开、后私下：** 正式问会推进一段，而私话要求已相识；因此自然路径是「白天当众问过 → 暮 / 夜独对再谈」。不提供「问完立刻私话」的捷径，也不因私下谈过而回写关系。
- **公开度不折算：** 「当众 / 独对」只解释谁听得见，不改 `tokens`、不改接触深度、不抬高风评、不生成新回声行。S-22 仍是回声的唯一表面，且只读既有事实。
- **不做命令：** 请托、调夫、签押、弹压等命令动词仍只在委牌 / 权界纸 / 六房值房；接谈纸不提供第二入口。

**边界：** 零新增人物、零新增名目、零新增关系值；`PersonPanel` 签名与人物卷三条页签不动；接谈纸的「看人物卷」只调既有 `openPerson(id)`。

### 6.3.3 人物详情全貌档案（FE-164/165 · 已施工 v1.64/v1.65）

人物详情定位为**玩家认知视角下的完整人物档案**，不是人物互动菜单。正式信息架构、系统联结与验收要求见 [人物详情档案面板设计-v0.1.md](../design/人物详情档案面板设计-v0.1.md)。

- **主页：** 采用「综合主页 + 深入子页」，人物肖像、身份信息、关键数据三者均衡；主页快速呈现身份履历摘要、能力/性格/身体状态、关系与政治位置、目标和近期行动、玩家关系、已知信息与资源摘要。**原有三问（能不能做、愿不愿做、敢不敢做）必须保留为核心判断模块**，继续读取 `person.questions` 的 answer / basis 与最近三条依据；不改成好感或服从数值。
- **子页：** 身份与履历；能力/性格/身体；人际关系网络；派系与政治关系；目标与行动；玩家关系；信息与秘密；财政/产业/社会资源；历史事件与公文档案。
- **认知边界：** 只显示玩家当前可认知的全部信息；不泄漏 NPC 私有认知或玩家未知事实。无需每条信息强制显示来源与可信度；底层 Exposure/Belief/Evidence 仍按总纲执行，必要时才用轻量标签区分传闻、怀疑或未证实。
- **只读边界：** 面板负责查看、分析、关系浏览、履历/证据查阅与关联跳转；三问是既有认知信息，不属于行动命令。交谈、拜访、宴请、书信、请托、委托、举荐、施压等具体互动仍由当前场景入口发起，不在数据面板内放置行动按钮。原示意图中的「问 / 请 / 托 / 压 / 保」属于场景互动入口，不迁入人物档案。
- **联结边界：** 复用统一人物模型、官制/仕途、关系/派系、Goal/Intention/Task、认知/情报、财政资源、Event/Evidence/Document、考成与行状；UI 只读投影，不新增人物总分、总忠诚、独立好感、平行资产或档案专属业务状态。
- **施工纪律：** 先审查现有 S-03 / PersonPanel 与路由，再决定主页/子页复用方式；不预设新增一级入口、OverlayId、存档字段或独立页面体系。M1 先呈现已具备数据的核心信息，未启用系统按阶段留白，不伪造数据。

### 6.3.4 品秩卡面四轴与卡框口径（FE-151 · v1.51 · 设计定稿）

人物卡面**不做抽卡稀有度**，不设星级、SSR、爆率或品级数值换算。卡面只回答四件事，且都从既有状态投影：

- **身份：** 姓名、职掌、在谁门下；沿用人物卷现有字段与文案，不新造头衔。
- **品秩：** 只读既有 `person` 职掌 / 品级字段与静态映射（如县衙三人有品级、绅商幕役不排品级）；**不新增 schema、不把品级折算成战力或好感**。品秩只决定卡框档位（官 7-9 / 4-6 / 1-3）与边制，不决定数值。
- **爵封：** 特殊标识，只在已发生爵封时由界面叠一枚角标或字印；空则留白，不预刻、不推断、不改任何判定。
- **荣誉：** 卡面留一条荣誉槽，只列已发生的荣誉名目；空态留白，不写「暂无」，不补写未发生的事。

**卡框口径：** 卡框图只提供底材，内部完全留白；肖像、题名、爵封、荣誉槽全部由界面按 `slotMap` 叠加。`slotMap` 用**相对纸心百分比**表达（见 `05` C-157），各族只登记自己的 `inset`，这样六族边宽漂移（实测 5.1%–6.4%）不会把槽位压到绫边上。爵封与荣誉**不进图**，与「卡框留槽、物象单独生成」的分层原则一致。

**边界：** 不新增 OverlayId、不新增一级入口、不新增存储 key；首版只作为既有 `PersonPanel` 肖像区的装裱升级，不新开人物卷第二入口；卡框与肖像图未接入前，保留既有素框降级。

### 6.24 S-23 人情簿（FE-037 叠层）

**目的：** 把散在六个人物卷里的「谁欠谁、握着什么」收到一张折子上，让债可读、可回查，但不变成可刷的资源。

```
┌──────────────────────────────────────────────────────┐
│ S-23 人情簿 · 只记名目与来源              [依 4.3] [×]│
│ 欠与不欠，都要有个名字。                               │
├──────────────┬──────────────────┬────────────────────┤
│ 人欠我 (1)   │ 我欠人 (3)        │ 把柄 (2)            │
│ 顾逢源 ●●    │ 林绍棠 ● 阮裕丰 ● │ 王慎之 ●● 桑鹤龄 ● │
│ hookNote     │ 桑鹤龄 ●          │ hookNote            │
│ 回人物卷 →   │ 回人物卷 →        │ 回人物卷 →          │
├──────────────┴──────────────────┴────────────────────┤
│ 礼簿往来 · 与 S-07 同源（既有 giftEntries）            │
└──────────────────────────────────────────────────────┘
```

- **入口：** 人情页标题右侧按钮；不新增一级入口。
- **只读：** 三栏分别按 `tokens.owesYou / youOwe / hook` 取数，逐条用朱点表示笔数、以 `hookNote` 作说明、`claimId` 作来源；底栏只列 `giftEntries`。不合并成好感或人情值，不新增「讨/还/用」动作。
- **空态：** 某栏无人时写「尚无人欠你 / 你也不欠人 / 尚无可用把柄」，并注明没有来源就不补写。
- **响应式：** 1440 三栏、≤980 纵向三节、390 全屏单列；入退场接减少动效。
- **书签带（FE-084 · v0.82）：** 人情簿三栏比屏高时，右缘挂一条窄丝带（C-95），随滚动定位、点拖键可移；只读滚动位置，不改债务、接触深度与来源。
- **回跳复原（FE-082 · v0.80）：** 从人情谱点开名目、再经回跳纸签返回时，谱面与折子各自回到离开时的滚轴位置，只复原滚动，不改接触深度、不重算债务、不写存档。

### 6.24.1 人物表面空态纸签（FE-123 · v1.21）

人情谱「尚未正式接触」与人情簿「礼簿往来」空栏套 `.empty-slip`：`--paper-scroll` 底纸、左 2px 朱砂刻口、虚线边与悬停深浅。**句子逐字未改**，不新增关系值、债务或礼数；人情簿三栏若某栏无条目，同一装裱自动生效（本局基线三栏皆有条目，实测验的是礼簿空栏）。图鉴整幅空册不套小签，避免把「展开人物卷」入口装进纸签里。

### 6.8 S-08 内宅（M2 完整，M1 只家人事件）

M1 不开放完整内宅；家人事件用 S-11 模态呈现，只给请求/代价/选择，不做家人列表与家用账。

- 家人卡：关系、需求、最近请求、秘密（已知才显示）。
- 家用：月度开销、婚嫁/丧葬/疾病大额。
- 仆役：门房/管家/厨子；门包/虚报/泄密。
- 规则：镜头停在门外；不显示私密细节；家人请求必须给“拒绝的代价”。
- **门外与家用归属（FE-041 / FE-043）：** C-58 内宅门外画境与门禁条之后，内宅空间挂 C-59 `strip` 体面线，家用只写「入私囊 · 大额另记」这一既有账位，不预设金额、不生成家人事件；镜头仍停在门外。

### 6.9 S-09 街市（M2）

- **场景（FE-035）：** 生活页街市空间先给一张街市画境（借用青石镇街市图，标「借用」），六处地点以纸签标在画上，仅作索引、不作精确定位；当前选中以墨底纸签标出，有来源处以朱点区分。画境下方仍是原来的六行地点索引，控制层未变，回城郭/回图路径保持。
- **今日市面：** 右侧纸只读 `log.rumor` 与当日公开日程（接风宴/委员到县/暴雨/洪峰/验收），无日程写「今日无公开市面之事」，不生成街头事件、人物或消费。
- **场合与门禁：** 同屏给 C-51 门禁条（身份/门/座/称/随从），依据 6.7.2/6.7.4，标「非本局判定」，可查则例；青石镇与桑家庄复用同一条，桑家庄为「宾客 · 需请通传 · 不带衙役入席」。

- 地点：茶楼、酒肆、戏园、商号、当铺、码头；六处索引与县治城郭共用同一投影。
- 人物：粮商、牙人、班主、讼师、脚夫；未接触者不显示姓名、秘密或“可结识”。
- 动作：吃茶、听戏、买卖、借债、打听；现有原型只保留来源查验与原夜宴入口。
- 规则：信息有来源；传闻沿关系边传播；不显示全知地图；城郭回查不耗时段、不伪造抵达。
- **最近看过入分节（FE-091 · v0.89）：** 生活页底部复用 C-96 / C-102「刚才」三签，只记表面与小节，当前表面不重复；点签回既有表面，只存内存、刷新即散，不生成街头事件、家人内容或消费。
- **三向对读窄条（FE-092 · v0.90）：** 礼簿空间底部复用 C-103「账 / 疑 / 礼」窄条，礼列置为当前页，账 / 疑列点回账房 / 情报台账；只读既有 `giftEntries` / `privateFunds` / `clues` 与三数，不新增礼数、人情值或结论。
- **风闻行迹与今日动线（FE-094 / FE-095 · v0.93）：** 街市「今日市面」纸底部先给 C-105 三站窄条（茶楼转述 → 情报听说 → 章末风评），当前站茶楼，只放行情报一站；再给 C-106 驿路签（今日动线，只记去过），随街市场景记录一次街市并列出最近三站，点站回既有场景 / 舆图 / 街市。两条都只读既有 `log.rumor` 与会话内到过的场所，不生成新人物、传闻、消费或好感。
