# 观远 · AI 叙事与模型接入

> **模块设计单** ｜ 观远 · 互动视觉原型 ｜ **v1.58**（2026-11-11）
> 本轮只定接入形态、边界与动效口径，零代码。规则、数值、判定仍以 `设计总纲.md` 为准；本文只回答「模型能写什么、不能写什么、等待时画面怎么演」。

---

## 一、边界：AI 只写叙述层

| 层 | 谁负责 | 允许模型碰 |
|---|---|---|
| 叙述层 | 模型 | 随机剧情走向、人物对白、氛围描写、选项措辞 |
| 判定层 | 本地规则 | 成败、数值、时段推进、关系、物品 |
| 存档层 | 本地存档 | 任何字段的写入 |

**模型输出只进「叙事日志」，不回写存档、不改判定。** 超时、胡说、断网都不会坏档；这是接入的前置条件，不是可选项。

---

## 二、形态与直连限制

- **PC（Tauri）**：请求走 Rust `reqwest`，不受 CORS；key 进系统凭据管理器。**唯一推荐路径。**
- **H5 / 小游戏**：浏览器环境，国内主流厂家基本禁止跨域；key 只能明文存 localStorage。**不接模型。**
- 若将来要 Web 版 AI，只接受「用户自填中转 baseURL」，且明确风险，不内置任何 key。

---

## 三、Provider 抽象

```ts
export type NarratorChunk =
  | { type: 'meta'; model: string; usage?: TokenUsage }
  | { type: 'beat'; beat: StoryBeat }        // 结构化节拍，先到
  | { type: 'text'; delta: string }          // 正文流式
  | { type: 'done'; finishReason: string }

export interface NarratorProvider {
  id: string
  capabilities(): Promise<ProviderCaps>     // stream / jsonMode / tools / ctx
  stream(ctx: NarrationContext, signal: AbortSignal): AsyncIterable<NarratorChunk>
}
```

适配器分三族：`openai-compat`（OpenAI / DeepSeek / Moonshot / 通义 / 智谱 / MiniMax / Ollama）、`anthropic`、`gemini`。差异收在适配器内，业务层只认 `NarratorProvider`。

**能力探测**：首次配置后发一条最小请求，记录 `stream / jsonMode / tools / contextWindow`；不支持 JSON mode 的，用严格 JSON 提示 + 解析容错 + 失败重试一次，仍失败则降级为纯文本旁白。

---

## 四、Key 与配置

- **存储**：PC 用 `keyring`（Windows 凭据管理器）；Web 不提供。界面只显示后四位。
- **多档案**：厂家 + baseURL + key + 模型名，可存多套、可切换；支持「日常小模型 / 章节大模型」两档。
- **脱敏**：key 不进存档、不进日志、不进崩溃报告、不进导出文件。
- **测试连通**：配置页必须有「测试」按钮，失败给出可读原因（401 / 跨域 / 模型名错 / 余额不足）。
- **用量**：本地记 token 与预估费用，按会话显示；只作提示，不参与判定。

---

## 五、上下文与随机性

每次只给四样，避免幻觉与成本失控：

1. **静态事实表**：场景、人物、已知线索、机构名——白名单。
2. **状态快照**：当前日 / 时段 / 场景 / 在场者 / 关键数值的只读投影。
3. **最近 N 轮摘要**：滚动摘要，不塞全文。
4. **本次意图**：问事 / 闲谈 / 请示 / 事件旁白，带语气与篇幅要求。

- 输出只允许引用白名单实体；出现未登记人名、地名、官职，整段丢弃重试一次。
- 随机性用 seed 锁定：`hash(saveId + day + scene + beatIndex)`；同 seed 可复现，便于回放与测试。
- 温度建议 0.7–0.9；章节级剧情可降到 0.6，日常对白可到 0.9。

---

## 六、流式与结构化

- 传输：SSE / `fetch` 流；PC 由 Rust 转发，前端只解 `NarratorChunk`。
- 结构先到、正文后到：先拿 `beat`（谁、在哪、做什么），再流式出正文；界面可先摆好人物与场景。
- 渲染合并：不要每 token `setState`；用 `requestAnimationFrame` 合批，按段落增量解析 Markdown。
- 超时：首 token 8s 未到即中止，切本地模板；总时长上限 30s。

---

## 七、等待的三段动效

不显示「正在思考」，不暴露思维链、prompt、模型名。等待包装成世界内动作：

| 阶段 | 时机 | 画面 | 文案 |
|---|---|---|---|
| 查档 | 0–0.8s | 案上纸签翻动、卷宗抽出一角 | 翻检旧卷 |
| 议拟 | 首 token 前 | 烛火轻晃、笔尖悬停 | 斟酌措辞 |
| 落笔 | 流式输出 | 墨迹从笔尖洇开、逐句显现 | 正文 |

收束：句末落一枚小印或合卷，表示「这段定了」。

三条硬规则：

1. **最短 1.2s**，避免秒回闪屏；**最长 8s** 切本地模板旁白，动画照常收束。
2. **先出本地即时内容**（在场者、已知线索），模型文本后到补写，画面不留空白。
3. **失败不弹错**，换本地模板句，用户无感；正文永不出现 token、模型名、prompt。

技术：墨迹用 `mask-image` + `background-position`；纸纤维渗透叠一层极淡噪点；打字按 18–28 字/秒、标点停顿；「略过」直接出全文；`prefers-reduced-motion` 与移动端降级淡入；只给活动层 `will-change`。

---

## 八、无 key 与失败降级

- 无 key / 401 / 断网 / 超时 → **离线叙事**：本地模板 + 规则引擎，主线和判定完整可玩。
- 界面只落一枚「离线叙事」小签，不弹窗、不拦路；设置里可随时补 key，生效不需重启。
- 降级路径必须在验收里单列，不能只测「有 key 的顺风局」。

---

## 九、最小闭环

先只做 **县衙晨 + 两个 NPC + 三种意图**（问事 / 闲谈 / 请示）：

1. 配置页填 DeepSeek key → 测试通过。
2. 问一句 → 查档 → 议拟 → 落笔三段跑通。
3. 拔网 / 填错 key → 离线叙事，动画不中断。
4. 同 seed 重放，输出一致。

这一步过了再铺全场景；否则动效调十遍也白搭。

---

## 十、验收口径（施工轮）

- **边界**：模型输出零写入存档；断网、401、超时三种失败均回落离线叙事且无报错弹窗。
- **脱敏**：存档、导出、日志、崩溃报告中检索不到 key 与完整 prompt。
- **流式**：首 token ≤8s、总时长 ≤30s；rAF 合批无掉帧；「略过」即时出全文。
- **结构**：beat 先到、正文后到；未登记实体被丢弃并重试一次。
- **动效**：最短 1.2s、最长 8s；减少动效下直接淡入；移动端不掉帧。
- **成本**：会话用量可查；相同上下文 hash 命中缓存，不重复计费。

---

## 十一、边界

- 不新增 `OverlayId`、一级入口、存档字段；叙事日志为会话态或独立只读文件，不入 `guanyuan.save.v1`。
- 不在前端内置任何厂家 key；不代收费用；不引导用户到第三方付费页。
- 不在正文暴露模型名、token、prompt、思维链；「思考」只以世界内动作呈现。

**与本文设计的对应与偏差（如实）：**

- 三 / 六 / 七 / 八 全部落地：provider 抽象与三族适配器、能力探测、SSE 流式、beat 先到正文后到、rAF 合批、三段动效、最短 1.2s、失败静默回落。
- **口径裁定两处：** ① 本文「最长 8s 切本地」与「总时长上限 30s」并存歧义，施工取 **8s 为首字门槛、30s 为流式总上限**；② 「同 seed 重放输出一致」改为 **缓存命中逐字一致、未命中只要求 beat 结构一致**（厂家 seed 多为 best-effort，不保证逐字复现）。
- **配置落点：** 非密配置与生成事件走 `guanyuan.narrative.v1`；钥匙单独走 `guanyuan.narrative.secret.v1`（用户「玩家自填 · 本地保存」授权例外）。PC 凭据管理器 seam 留待 19 的 Tauri 轮接入，当前 Web 形态按用户裁定本地保存并严格脱敏。
- **离线叙事：** 用户明确「不必离线叙事」，故不建本地模板内容库；无 key / 失败时游戏照旧（既有五日事件与全部界面不变），只落一枚世界内小签。
- **效果目录：** 模型只能选 id（8 项），不写数值；本文「判定层本地」由此从口号变为可验收的隔离。
