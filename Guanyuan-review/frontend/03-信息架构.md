## 五、信息架构

### 5.1 五个一级入口与章节边界

**界面三层：** 案卷（公事）、人情（关系）、生活（世俗）。

**玩法三层与界面的对应（v0.6）：**

| 玩法层 | 界面落点 | 频率 |
|---|---|---|
| **宏观人生** | S-14 章首志向 / 章末尾声（目标复盘、机会、退路、长尾） | 章首 / 章末，不占每日时段 |
| **中观策略** | S-15 事务盘（Case ≤3、生命周期、任务与偏差）；S-16 政令牌（M2） | 每章常驻，随案推进 |
| **微观行动** | S-01 案头、S-02 案卷、S-03 人物、S-04 委托、S-07 礼簿 | 每个时段 |

**五个一级入口：**

1. **今日** — 案头：时段、三钟、待决、三行日志、志向印。
2. **案卷** — 文书、案件、任务、证据；第二标签「事务」进入 S-15。
3. **人情** — 人物、三问、债、秘密、传闻、接触记录。
4. **账房** — 五本生活账、三个数字、审计。
5. **生活** — 礼簿、内宅、街市、享受。

**两个叠层：** 情报台账（右侧抽屉/全屏）、事件暂停（模态）。
**章节边界：** 章首立志（S-14）/ 章末考语·行状·尾声（S-10 + S-14），不占一级导航。
**时间表达：** 顶栏只显示日期、时段与期限；不显示行动点；长动作显示「占用至 第 N 日·晨」。S-16/S-17 是 M2/M3 候选，M1 不出现入口。

### 5.4 导航规则

1. **任何页面两步内回到“今日案头”。**
2. **任何决策页都有“为什么不能/缺什么”入口**（C-08 / FE-032 的 C-45 依何条、C-46 为什么不能条）；点开只到 S-12 条文与「本局对应」，不产生新规则。
3. **不出现死胡同**：空状态必须给下一步。
4. **不自动跳转**：事件暂停后由玩家选择；不抢焦点。
5. **不隐藏当前时间**：顶栏永远显示时段与最近期限；显示「本时段已用/未用」，**不显示行动点**。
6. **不隐藏志向**：章节内至少一个角标可回看当前 Goal；章末必须回到 S-14 对账。
7. **不假装全知**：接触记录只显示玩家可知的接触；未知显示「？」。

## 九、响应式、可访问性与性能

### 9.1 可访问性

- WCAG 2.1 AA；正文对比 ≥4.5:1；大字 ≥3:1。
- 键盘可达；焦点环 2px 朱砂；不依赖 hover。
- 屏幕阅读器：文书提供横排释文；表格有表头；图标有 `aria-label`。
- 200% 字号不破版；不用 `overflow: hidden` 切字。
- 状态不只靠颜色：文字 + 图标 + 纹理。
- 动效遵循 `prefers-reduced-motion`；不做闪烁/快速缩放。

### 9.2 性能

- 首屏（中端移动 4G）< 2s；主交互 < 100ms；动画 60fps。
- 纸纹用 CSS/SVG 微噪点，不用大图；人物图懒加载；文书文本不预渲染全部页。
- 不用持续粒子/视差；不在主线程做长任务。
- 关闭 AI 时无额外网络请求。

### 9.3 平台默认

- M1：响应式 Web（桌面 1440 / 移动 390），浏览器优先；不做原生 App。
- M2：如需 Steam/桌面封装，再评估 Tauri/Electron；UI 不绑定平台。
- 不做横屏强制；移动竖屏优先；文书可全屏横排。
