## 十、前端架构与数据边界

### 10.1 分层

```
tokens → primitives → components → screens → flows
```

- `tokens`：颜色/字体/间距/动效；唯一来源。
- `primitives`：Paper、InkLine、Seal、Text、Stack、Grid。
- `components`：C-01..C-25（C-24 仅 M2）。
- `screens`：S-01..S-18（S-16/S-18 仅 M2 预览，S-17 仅 M3）。
- `flows`：委托、对勘、礼簿、夜结算、考语、章首立志、事务盘、章末尾声。

### 10.2 数据边界

- UI 只读 `WorldView` 投影；不直接读世界真相。
- 所有命令走 `CommandBus`；UI 不做权限/数值判定。
- `DocumentView`、`PersonView`、`LedgerView`、`ClaimView`、`GiftView`、`GoalView`、`CaseView`、`ExposureView`、`TokenView`（M2）、`LegacyView`（M3）等 view model 由规则层生成。
- **结算顺序（10.6）：** UI 不自行排序同刻事件；只渲染规则层提交后的阶段结果；提交中有 pending，失败可重试，**不做乐观更新**。
- **时间（9.1）：** UI 只读 `worldTime（day, period）` 与动作占段；不维护行动点，不在前端推算「还能做几件事」。
- **认知（3.5）：** `ExposureView` 只给玩家可知的接触；`Belief`/`Rumor` 不得显示成事实；未知一律遮罩。
- AI 文本是 `NarrativeBlock`：`text + factRefs + flavor`；UI 不把 flavor 当事实。
- 事件溯源：UI 状态由事件流/快照派生；不覆盖历史。
- 幂等：重复点击只提交一次；按钮有 pending 态。

### 10.3 目录建议

```
src/ui/tokens/
src/ui/primitives/
src/ui/components/
src/ui/screens/
src/ui/flows/
src/ui/content/
src/ui/testing/
```

### 10.4 测试

- 单元：格式化、状态映射、权限提示。
- 时间：长动作跨段、0 费动作不耗段、等待/模型延迟不推进、无行动点泄漏。
- 因果：结算顺序、幂等重放、pending/失败重试、不做乐观更新。
- 认知：接触记录不泄露未接触事实；四档状态与来源分开。
- 视觉回归：组件/屏幕/长文本/缺失图/空状态。
- 可访问性：axe + 键盘 + 200% 字号。
- 内容压力：20 个长姓名/官职、10 个缺图、5 份矛盾文书。
- 性能：首屏、交互、动画帧率。
- 规则一致性：UI 显示的数字/状态与 view model 100% 一致；不显示玩家未知秘密。
