### 6.80 FE-132 回那处滚轴复原（v1.30）

遗留单写「回跳不恢复滚动位置」，实况核得 `returnToSpot`（FE-082）早已复原滚轴；真正缺的是 C-108「回那处」一路：`backToReviewOrigin` 只换表面与焦点，focusOn 还会把落点滚到焦点件，来处滚轴丢失。本轮在 `openDocumentAt` 记一枚来处滚轴（会话 ref），回来时复用既有 `restoreScrollTo` 轮询复原，并落归位纸角告知「已归位 · 来处」。

### 6.93 FE-145 在场名帖与接谈纸（v1.43 · 设计定稿 · 未施工）

「此刻在场」原来是 FE-033 的一行字：只读当日公开日程的 `present`，没日程就写「未详 · 不补写」。这条纪律本身是对的——不补写门子、书办、过路人；但它把「常驻的人」也一起抹掉了：县衙签押房明明有主簿，东堤明明有堡夫头，夜书房明明有幕友，画面里却一个人也没有。玩家想说话，只能先离开场景，进「人情」页，再从名册进人物卷——场景成了布景，人物成了目录。

这一节把两件事拆开：**在场是投影，不是日程模拟**；**接谈是问，不是命令**。

在场只由「代码内当值表（具名 + 未具名）× 时段」与「当日公开日程」两项决定。当值表只写六个有姓名的人：县丞晨/午在签押房、主簿晨/午/暮在签押房、堡夫头全日驻堤、幕友东堤晨/午与书房夜、县丞会勘时午/暮在堤。日程只在**同名场景**并入，且日程优先、同人去重。衙役、书办、堡夫、船帮一律不列名——这条沿用了 FE-033 的「不补写」；二稿进一步把他们按当值人数计入公开度（见下），但仍不给他们姓名、面目与立场。

接谈纸只做三种谈法：问三句（读既有 `questions`）、正式问一回（既有 `askPerson`，首次耗一段）、私下说（仅独对，门槛用既有 `revealDepthOf` 与 `tokens.hook`）。**刻意不做请托 / 调夫 / 签押**：这些是命令动词，已有委牌、权界纸、六房值房三个正式表面；在场景里再开一个，等于绕过 `confirmPlan` 和权界判定。接谈纸的定位是「开口」，不是「办事」。

「人多的场合别人可能知道」这件事，最后落在**公开度带**上，而不是新的关系数值。当众只解释「他们听得见」，独对只保证「不出此室」；公开度不写 `echoesOf`、不加回声行、不折算风评。原因是存档 schema 里没有「谁听见了哪句话」这一层；要加就得改 schema，那是另一件事，本节点明确列为停止条件。私话只存组件内会话态，卸载即失——它本来就不该成为可刷的资源。

**二稿修订（最佳改法）：** 初版只把「有姓名的人」计入公开度，结果县衙暮间只剩主簿一人就被判成「独对」——门外书办还没散，这不真实，也让「当众」太容易成立。二稿把在场拆成两层：**具名名帖**（可点、六人）与**未具名当值**（书办 / 衙役 / 夫役 / 堡夫，只计人数、不列名、不可点、不推断身份）。县衙晨午 书办 2–3 人、东堤晨午 夫役与堡夫 3–5 人、暮后归零、书房夜无外人；于是白天当众、暮后县衙独对、夜里东堤与书房独对。这个「白天当众、暮夜独对」的节奏不是装饰，而是把正式问（耗一段）与私话（要求已相识）串成一条自然路径：**先当众问过，暮 / 夜再来私下谈**。同时补一个 0 费「寒暄一句」，让闻名人物也能开口，不用一上来就耗一段。

**取舍：** 不做 NPC 移动模拟，因为一旦模拟，就得回答「他为什么不在」「他什么时候回来」，会把一个纸面原型拖进日程系统；当值表与未具名表都是显式、可审、可改的，符合这个项目「事实闭环」的口径。名帖用单 Tab 停靠而不是全 Tab，沿用 C-136 / C-152 的既有纪律；接谈纸不新增 `OverlayId`，避免把「场景内开口」升成第七个入口。

**覆盖 7 模块：** 06 / 08 / 11 / 05 / 17 / 03 / 13。

**状态：** 设计定稿，**未施工**；实现方按 06 6.1.12 与 15 #fe-145 施工，完成后补推进后结果。
