## 主理裁定纪律（用户口径，必须照做）

- **实况重核在前**：每项任务动工前先现查仓库状态（HEAD / 文件头 / 资产 / 代码 / 上轮台账），与施工单不一致时**当场报「指令未执行 + 理由」**，不做事后合账、不自行脑补补齐。
- **bounded execution**：严格按指定 scope 执行，**禁止擅自扩大范围**。每个执行单必须写清「**不做**」「**禁动**」「**停止条件**」三段；越界的事一律先问。
- **破腿纪律**：`induce failure → 观察到 red → 清除残留 → 恢复 green`，绝不「修了就发」。缺图 / 缺状态 / 缺探针的降级路径必须实测，不能只验成功路径。
- **崩 ≠ 红**：未就绪 / 未测到必须返 `code-2 'not measured'` 或 `BLOCKED`，不可用随机 PASS/FAIL 冒充；probe 必须轮询可验证的 readiness；旧结论必须**同路径复测**再引用。重复性实验连跑 5 次以上才可定性，单次结果不算稳定证明。
- **事实与推测分离**：报告里已证事实、推测机制、未决事项显式分开写；验证数字给具体值与产物路径。
- **编号与封板**：编号工单 / 封板记录 / 施工单；交付格式「**审查报告 + 施工单**」，报告按分层结构（节点→接口→验证→备案→遗留→美术）写，不堆长句。
- **外部写操作**：涉及索引 / 云文档 / 上传等外部写入，先给变更清单获批再写。
- **提交纪律**：本轮**不 commit / reset / clean**。若将来明确授权提交，**禁止 `git add -A` 与裸 `git commit`**，必须 `git commit -- <显式路径>`，避免裹入他线在途改动；提交后按「补引 → `git log -1 --oneline` 校验 → 刷新 bundle」收口。
- **他线在途污染检测**：HEAD 对照 → 撤回对照 → 污染确认，用控制变量法；发现 in-flight 变更即停。
