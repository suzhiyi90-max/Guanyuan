## 0. 执行摘要

观远的目标不是把现有河工原型扩成更多页面，而是建立一个持续运行的古代社会人生模拟世界：

- **全人物完整生命：** 玩家、官员、士子、家属、商人、农户、差役、工匠等共享统一人物内核，具有出生/既往经历、年龄、身体、心理、能力、身份、家庭、经济、关系、认知、目标、日程、位置、衰老、疾病和死亡状态。
- **官员人生为主题主轴：** 科举、入仕、任职、考成、升降、调任、失势、致仕与身后评价构成核心体验，但不是唯一人生。
- **自由古代人生可持续：** 落第、不入仕、改途、经商、游学、婚姻/不婚、成家/不成家、迁徙、经营家业等都能继续推进，不被强制拉回官场主线。
- **AI 驱动动态世界：** AI 提出人物行动、事件、关系和叙事候选；确定性规则检查资格、时间、位置、认知、资源、制度和因果；事件账本提交事实。AI 不直接写世界事实。
- **前端预览继续复用：** 保留已有场景、文书、账房、证据、人物档案、舆图和视觉资产，逐步把静态/场景专用数据替换为正式引擎投影。

**施工总原则：先完成规则与数据契约，再建时间/事件/人物底座，再接 NPC 自主模拟与 AI，最后用科举空白开局纵切片证明整套系统。** 河工七人十日场景保留为中期任官压力测试，不作为新存档的预置人口。

app/README.md 将其定义为 React 19 + Vite 6 + TypeScript 的“可玩原型”，并明确设计权威不在 app 目录。当前 UI 已有六个主导航区：今日、案卷、事务、人情、账房、生活；场景包括县衙、河堤、书房；组件覆盖场景、文书、人物、事务、账房、证据、人物档案、舆图、章末、则例、因果纸、人情簿与 AI 叙事。

可复用资产：

2. 人物 UI：PersonPanel、PersonArchive、ProfileFolio、PeopleSection。
3. 世界/制度 UI：AtlasDrawer、RuleBook、PowerLedger、WorldEventCard、EpilogueCard。
4. AI 叙事：app/src/narrative/ 的 provider、schema、context、store、effects、useNarrator 和叙事组件。
5. 美术：app/public/assets/ 现有场景底图、人物肖像、纸面底材和地图资源；继续使用已有资产清单与 fallback 纪律。

当前边界/技术债：

- app/src/data.ts 仍提供原型静态人物和内容；人物档案是从已有数据聚合的只读投影，不是完整生命实体。
- GameState 含大量河工十日专用字段（day、periodIndex、clues、plan、material、officialActions、pendingEvent 等），不是通用世界状态。
- game/people.ts 中能力、需求和关系深度投影仍含固定原型/人物 ID 规则，不是可扩展的全人物模型。
- useGame.ts 通过本地 guanyuan.save.v1 序列化当前场景状态；这不是完整事件溯源、快照重建和多年存档迁移体系。
- narrative/store.ts 独立保存 AI 配置/生成叙事；当前 AI 叙事接入不等于 AI 世界驱动器。
- styles.css 仍是大体量单文件。应在对应 UI 模块施工时渐进拆分，不得把全量 CSS 重写设为引擎开工前置条件。

**处理原则：** 不推倒现有前端；把它作为 View / Interaction Prototype。正式数据来自领域模型和事件投影，组件只消费 ViewModel；场景按钮提交 Command，不直接修改领域事实。

## 2. 设计权威与施工纪律

### 2.1 权威层级

1. 已批准并进入 main 的根目录《设计总纲.md》是当前正式规则权威。
2. v0.16 PR #8 是本计划目标架构的重要设计依据；在 PR #8 审阅/合并前，相关条款仍标记为候选基线。
3. 专项设计规范展开对象边界和验收，但不得形成第二套规则。
4. M0 纸面验证包用于验证设计，不等于代码实现或玩家验收。
5. 前端专项单只约束信息架构、交互、视觉、可访问性和数据投影，不定义正式世界状态上限。
6. G1 施工台账记录已实现内容和工程验收，不得反向修改设计规则。

### 2.2 不可破坏的产品约束

- 全人物都是完整生命实体；不能只给玩家或关系圈人物完整状态。
- 年龄由出生时间和世界时间推导；出生、衰老、疾病、婚育、迁徙、任免、死亡等变化有事件来源。
- 死亡保留人物历史；职位、债务、产业、亲属、组织成员和未竟承诺分别处理。
- 官员人生是主题主轴；不入仕和非仕途人生必须能持续推进。
- 玩家开局关系矩阵为空；关系由实际接触、科举、通信、共事和人生事件逐步形成。
- 河工七人只作为中期任官规则压力测试夹具，不注入科举空白开局。
- AI 只能提出候选；规则层验证；事件账本提交事实；叙事只表达已结算事实。
- L0–L3 只降低模拟频率/细节，不改变人物事实、规则结果和因果；升级精度不得重新随机生成一段人生。
- 任何重大不可逆玩家决定必须由玩家确认；沉默不等于同意。
- 不新增平行 Person / Relation / Economy / Evidence schema；先映射既有对象再扩展。

### 2.3 工程施工纪律

每个施工任务都必须依次提供：

1. 设计依据与对应规则 ID；
2. 当前仓库状态、受影响文件和依赖检查；
3. 明确的接口契约与数据权威；
4. 至少一个改前失败测试（适用时红→绿）；
5. 最小实现，不夹带未授权数值/文案/范围变化；
6. 单测、集成测试、场景测试和回归；
7. 构建、差异检查、分辨率截图及人工眼审；
8. 更新施工台账、Changelog、索引和验收证据；
9. 独立分支 / Draft PR；未经明确批准不合并 main。

## 3. 系统依赖总图

基础依赖关系：

- 正式设计总纲 + 史实/制度配置 + M0 纸面验证
  → 领域对象与规则契约
  → 统一时间引擎 + 事件/命令/事务底座
  → Person / LifeState
  → 家庭与经济、身份/职位、关系/组织/认知
  → NPC 日程 / 自主行动 / L0–L3
  → AI 世界驱动器（候选层）
  → 规则校验与事件提交
  → 状态投影 / 玩家认知投影
  → 现有前端组件 + 新增人生场景 UI。

依赖方向必须保持单向：**基础契约 → 领域规则 → 命令/事件 → 状态投影 → UI / AI 叙事**。UI 不得直接写领域事实；AI 不得绕过命令和事件提交器。

### P1｜领域契约与状态权威定稿

**目标：** 在扩代码前确定对象边界，避免后续产生多套人物、关系、账目和事件模型。

依赖：P0。

施工项：
- 统一 Person、LifeState、BodyState、MindState、Capability/Knowledge、IdentityAssignment、Office/Authorization、Household、Economy、Relation、Organization、Membership、Exposure/Belief、Schedule/Location、Item/Property、Event 的责任边界。
- 审查当前 Person、GameState、Goal、Exposure、Relation、Debt、Household、Economy 等已有对象；只扩展或迁移，不平行新建。
- 区分客观事实、历史事件、人物认知、玩家认知、叙事文本和 UI 派生视图。
- 定义未知、不适用、尚未生成、已失效、不可见等状态的表达，避免都用 null/空数组。
- 定义规则版本、事件版本、人物稳定 ID、关系有效期和数据迁移策略。
- 对行动成本、命令原子性、事件排序、期限边界、随机可复现、证据/认知边界形成最终契约；任何未裁决项不得由施工者自行补规则。

交付：
- 领域对象映射表；
- 数据权威与写入权限矩阵；
- 命令/事件/状态投影契约；
- 存档迁移方案；
- 规则未决项清单。

验收门槛：
- 每个核心字段有唯一权威来源；
- 每个状态变化可追溯到开局事实或事件；
- 无重复 Person / Relation / Economy / Evidence 模型；
- 命令拒绝不产生部分写入；
- 未决规则明确阻断对应功能，而不是静默猜测。

### P2｜核心运行时：时间、命令、事件账本与存档

**目标：** 从十日场景状态机提升为支持日内、日/月/年和代际推进的统一世界运行时。

依赖：P1。

施工项：
- 保留现有纯函数引擎与统一命令层的有效实现，拆出通用世界运行时接口；不得直接把河工字段搬成全局字段。
- 统一世界时钟：微观互动、日内时段、日/旬/月、季/年、多年和代际结算。
- 统一命令管线：意图解析 → 资格/权限/状态校验 → 成本预估 → 原子提交 → 时间推进 → 事件调度 → 投影刷新。
- 建立 append-only 事件账本：稳定 eventId、commandId、occurredAt、recordedAt、actor、target、source、ruleVersion、seed、payload 和因果引用。
- 建立快照、重放、幂等、并发版本校验、失败恢复和事件顺序稳定性。
- 设计从 guanyuan.save.v1 到正式存档版本的迁移；保留用户已有原型存档的安全读取/导出路径，禁止无提示清空。
- 随机使用可重放 seed；随机结果写入事件，不允许不可追踪的 UI 随机数直接改变事实。

交付：
- WorldClock / Scheduler 契约；
- CommandBus / EventLedger / Projection 接口；
- 快照与回放；
- 存档迁移和兼容测试。

验收门槛：
- 同一初始状态、规则版本和 seed 重放得到相同事实状态；
- 同一 command/event 重放不重复扣成本、不重复产生关系/账目；
- 事务失败不会留下半提交状态；
- 事件排序稳定，跨日/跨年边界可解释；
- 快照重建结果与连续运行结果一致；
- AI 服务关闭时核心世界仍能推进。

### P3｜全人物生命内核

**目标：** 让所有人物成为持续存在、有生命周期和历史的独立个体。

依赖：P2。

施工项：
- 建立统一 Person 生命周期：出生/既往经历、年龄、人生阶段、存活状态、衰老、疾病、伤害、康复、死亡。
- 身体状态：体质、健康、疲劳、营养、伤病、慢性病、恢复和医疗；NPC 与玩家使用同一规则。
- 心理与性格：情绪、压力、恐惧、欲望、稳定性格倾向和心理负荷分开建模。
- 能力与知识：能力、教育、技艺、知识来源和学习经历；经验变化与身体衰退分离。
- 身份资格与履历：社会身份、制度资格、职位、实际授权、当前角色和历史有效期分离。
- 家庭与代际：亲属、婚姻、扶养、监护、生育、收养、继承、分家、丧亲；允许不婚、无子和家族断绝。
- 经济与生活：收入、支出、财产、债务、生活维持、破产和迁徙；重要人物精算，远端人物可汇总。
- 死亡处理：保留人物历史，分别处理职位、债务、产业、亲属、组织成员、物品和未竟承诺；继承人不自动继承死者全部能力、关系和秘密。

交付：
- Person / LifeState 领域模型；
- 生命周期事件目录；
- 身体/心理/能力/身份/家庭/经济状态规则；
- 死亡与继承处理规范；
- 生命状态测试夹具。

验收门槛：
- 任意人物均能表达完整生命状态，不因 LOD 或是否在场降格；
- 年龄由出生时间与世界时间推导；
- 出生、疾病、伤害、婚育、迁徙、任免、死亡均可追溯；
- 死亡后历史保留，职位/债务/财产/亲属/组织按各自规则处理；
- 玩家与 NPC 没有主角免死或特权生命规则；
- 未校准的寿命、疾病率和医疗参数不得伪装成史实常量。

### P4｜人物关系、组织、认知与远距通信

**目标：** 把人物关系从静态联系人列表提升为有来源、有方向、有时间和认知边界的社会网络。

依赖：P3；P2 事件/时间接口。

施工项：
- 身份多轴：社会职业、制度资格、家庭出身、组织归属、当前处境可并存且有有效期。
- 关系多重：亲属、婚姻、师承、座师门生、同年、同乡、上下级、同僚、债务、合伙、私交、政治关系等。
- 方向不对称：A 信任 B 不等于 B 信任 A；事实关系与双方认知分开。
- Organization / Membership：组织目标、规则、资源、成员角色、加入/退出和义务；组织标签不自动等于成员服从。
- 统一社交行动：接触、拜访、问话、宴饮、馈赠、请托、举荐、协商、冲突等沿统一意图/权限/渠道/成本/回应管线结算。
- 远距通信：草拟、发出、途中、送达、阅读、理解、回应、回复送达；支持延迟、拒收、遗失、截获、转交和泄露。
- 信息认知：Fact / Claim / Evidence / Exposure / Belief / Memory / Rumor 分工；玩家只看到自己可知的信息。
- 消息沿真实接触、组织渠道、亲属/师承/交易关系或正式文书传播；关系边不自动广播。

交付：
- 关系/组织/认知/通信领域模型；
- 关系形成与终止事件；
- 通信状态机和成本接口；
- 玩家认知投影；
- 社交回归测试。

验收门槛：
- 同一人物对之间可存在多条并存关系；
- 关系事实、双方认知和玩家认知分别存储；
- 同年不自动等于相识/私交/互信；
- 联系发起不等于送达，送达不等于阅读，阅读不等于相信；
- 关系网络不泄漏未知边，不自动全局传播；
- 所有关系确认和变化均有事件来源。

### P5｜NPC 自主行动、日程和 L0–L3 世界模拟

**目标：** 让 NPC 有独立人生与行动动机，玩家不操作时世界仍合理推进。

依赖：P2、P3、P4。

施工项：
- NPC 目标与意图：生存、身体、家庭、经济、学习、仕途、名声、情感、组织责任、承诺、恐惧和机会。
- 日程：工作/学习、休息、饮食、照护、社交、出行、家庭责任和个人目标；计划可被事件打断。
- 行动调度：按位置、时间、资格、资源、认知和承诺选择行动；允许等待、犹豫、拒绝、休息和无显著事件。
- NPC-NPC 社交、交易、通信、求助、冲突、合作、婚姻/家庭和组织行动。
- L0 近场：细粒度人物状态、场景行动和见证。
- L1 关系圈：周期性更新已知人物、近期通信对象和重要关系人。
- L2 地域圈：县域/府域按日程、目标和重要事件更新。
- L3 远端世界：跨地域普通人口按汇总状态、组织统计和重大事件推进。
- LOD 升降级必须继承既有状态、历史和待办事件，不得重置人生。
- 建立性能预算与模拟频率观测；参数经压测后再定。

交付：
- NPC Intention / Schedule / WorldTick；
- L0–L3 调度器；
- NPC 自主事件和模拟回放；
- 性能采样与降级策略。

验收门槛：
- 至少一条 NPC 自主行动链可回放并说明动机、成本、风险和结果；
- 玩家连续不行动时世界仍按人物目标推进，但允许平静时段；
- LOD 升降级前后人物状态与关键决策连续；
- 远端汇总升级到近场时不重新生成履历；
- 超预算时降低表现细节/更新频率，不丢失关键事实。

### P6｜AI 世界驱动器与叙事分层

**目标：** 让 AI 参与世界动态生成，同时严格保持规则和事实权威。

依赖：P2–P5。

施工项：
- 统一 AI World Driver 输入快照：时间、制度、环境、人物状态、关系、组织、认知、日程、资源、已提交事件和观察者视角。
- 候选输出结构化：行动者、目标、动机、前置事实、时间地点、渠道、成本、风险、预期影响、来源、可见性和置信度。
- 规则校验器：存活、位置可达、资格/权限、时间冲突、认知条件、资源成本、因果前置、事件竞争和玩家授权。
- 候选队列：接受、拒绝、延迟、补充信息、无事件；所有拒绝原因可审计。
- 事件提交器只接受已验证候选，生成唯一事件 ID 并更新状态投影。
- AI 叙事只读取结算结果和当前观察者可知信息，不反向补造事实。
- 模型超时、401、网络失败、结构不合规和预算超限时，回落规则模板/本地意图/延迟队列。
- 建立防注入、越权、伪造身份/文书、泄露秘密和不可逆决定红队测试。

交付：
- WorldDriver API；
- Candidate schema / Validator / Event submitter；
- Narrator 与 WorldDriver 分离接口；
- 离线降级和预算监控；
- AI 红队与评估套件。

验收门槛：
- 未通过校验的 AI 候选对世界状态零写入；
- 同一候选重试幂等；
- AI 无法越权改变生死、婚姻、继承、任免、债务和玩家重大决定；
- 模型关闭时规则世界仍可推进；
- 叙事只表达已提交事实，不泄漏观察者未知信息；
- “本轮无新增人物/关系/事件”是合法结果。

### P7｜首个正式人生纵切片：科举空白开局

**目标：** 第一次证明正式引擎能够从空白人生开局，推进人物、时间、事件、关系和自由选择，而不是只跑通某个 UI 页面。

依赖：P0–P6。可在 P2–P5 先用确定性规则和模板完成骨架，P6 接入 AI 后完成最终动态性验收。

纵切片链路：

1. 新存档建立读书人角色：可配置或按规则确定家世、籍贯、家境、教育、年龄和初始身体状态。
2. 初始个人关系矩阵为空；不预置座师、同年、同窗、故交、盟友、政敌或人情债。
3. 生活与准备：读书、休息、谋生、拜访、准备应试等行动按时间、身体、经济和地点结算。
4. 报名/资格核验/入场/考试：制度条件真实可检验；允许资格不足、迟到、疾病、资源短缺等失败分支。
5. 同场人物与 NPC 自主行动：人物可相遇、交谈、竞争、求助、拒绝或离场；不能为剧情强制结交。
6. 考试结果/放榜：成功、失败、延误或其他制度允许的结果均有规则依据。
7. 关系形成：同榜只产生客观同年关系；相识、私交、师承、举荐和债务必须由实际事件形成。
8. 人生分支：中举后继续仕途；落第可再试、游学、教读、谋生或改途；玩家可不入仕。
9. 存档、读档、回放：完整恢复人物状态、关系、认知、事件历史和世界时间。
10. AI 动态性：AI 可提出考场/社交/NPC 行动候选，但必须经过规则验证和事件提交；AI 不可用时仍能完整通关。

交付：
- 可玩的科举开局场景；
- 人物生命与社交状态实际运行；
- 至少三条差异化结果路径（成功、失败、放弃/改途）；
- NPC 自主行动和关系生成；
- 存档/读档/事件回放；
- 三档界面和关键流程截图。

验收门槛：
- 三条人生路径均可继续，不强制回归仕途；
- 新档无预置玩家关系；
- 所有关系变化有实际形成事件；
- 至少一条 NPC 自主行动、一条拒绝/延迟、一段无显著事件时段；
- 时间、身体、资源、认知、事件和关系在存档/读档后一致；
- AI 关闭仍能完成核心链；AI 开启不能绕过规则；
- 玩家重大不可逆决定必须明确确认。

### P8｜官员人生与河工治理纵向整合

**目标：** 将现有河工原型提升为正式世界中的中期任官案例，并接入仕途主轴。

依赖：P7；P1–P6 的底座稳定。

施工项：
- 科举功名、座师/同年关系、举荐、候补、任命、任期、考成、升降、调任、处分、致仕和身后评价。
- 官制配置、职位空缺、权力/权限、审批、上下级、责任和制度流程。
- 复式财政账本、公帑/私囊/人情/身体/风评生活账、账面/实收/报部和审计。
- 公文证据链：文书版本、持有人、流转、批答、揭报、题销和来源。
- 委托与执行：发起、预算预留、执行、进度、偏差、验收、报告义务、失败恢复。
- 河工七人十日场景接入正式 Person / Relation / Event / Economy / Evidence / Time 模型；固定七人仅作测试夹具或场景配置，不作为世界人口上限。
- 保留现有前端案卷、账房、证据、事务、上宪批答和章末界面，改为正式状态投影。

交付：
- 官员职业生命周期模块；
- 河工治理正式场景；
- 财政/公文/委托/考成闭环；
- 历史事件与责任链回放。

验收门槛：
- 河工场景能从正式人物与世界状态加载；
- 复式账目可对账、事件可回溯；
- 公文版本/流转/签批和证据来源连续；
- 委托执行与发起分离，失败、延误和部分完成可追踪；
- 上司赏识/同年/座师关系影响机会但不保证升迁、不越过制度资格；
- 结算与前端展示同源，不能由 UI 另算结果。

### P9｜自由古代人生与长期生活循环

**目标：** 让玩家脱离官场后仍有完整、长期、可变化的人生。

依赖：P3–P6；P7 的人生时间与存档稳定。

施工项按依赖逐步开放：
- 教育、著述、游学、旅行、地方交往；
- 商贸、经营、雇佣、债务、产业、土地和家计；
- 婚姻/不婚、家庭成员、照护、生育/不育、扶养、继承与分家；
- 地方公益、幕友/师爷、专业服务、诉讼、迁徙和社会组织；
- 疾病、伤害、衰老、医疗、丧亲和人生转折；
- 家族/组织的长期变化和代际传承。

交付：
- 可持续的非仕途目标与行动；
- 家庭/经济/身体循环；
- 旅行和远距通信；
- 失败后恢复与长期后果；
- 代际与继承的阶段性版本。

验收门槛：
- 不入仕、落第、离任等路径有持续目标、行动、收入/支出、关系和事件；
- 婚姻、生育和继承不是强制剧情；
- 破产、疾病、关系破裂和失势不默认结束人生；
- 家庭成员具有自己的状态与行动，不是装饰字段；
- 长期推进可回放，死亡与继承保留历史连续性。

### P10｜前端正式接入与视觉/交互整合

**目标：** 让现有预览 UI 成为正式引擎的只读投影与命令入口。

施工项：

- 人物档案继续只读，人物互动从当前场景/通信入口发起。
- 人情谱、人物档案、社会关系网络三种视图职责分离。
- 逐步拆分 styles.css，保留现有设计令牌、底材、响应式、可访问性和 print 规则。
- 美术资产沿用资产清单、命名、hash、来源署名、fallback 和截图验收流程。

交付：

### P11｜规模化、平衡、性能和发布门禁

**目标：** 从可玩纵切片走向可持续运行的长期世界。

依赖：P2–P10。

施工项：
- 对 L0–L3 人物数量、世界 tick、事件积压、存档体积、AI 调用和缓存进行基准测试。
- 以压测和玩家体验数据校准寿命、疾病、出生、生活成本、人口更新、交通、通信和 AI 预算参数。
- 建立历史事件回放、存档迁移、规则版本兼容、备份/导出/恢复。
- AI 质量评估：人物一致性、因果一致性、年代/地域约束、信息边界、越权拒绝和离线降级。
- 建立长时间运行、断网、模型故障、超预算、重复请求、旧档迁移和异常恢复测试。
- 发布前完成隐私、凭据管理、AI 生成披露、性能与可访问性审查。

交付：
- 性能基线和预算；
- 长期世界回放集；
- 参数校准记录；
- 存档迁移与恢复演练；
- 发布候选验收报告。

验收门槛：
- 性能阈值由实测后批准，不在未压测前编造；
- LOD 降级不丢事实、不改变关键规则结果；
- 长期运行后仍可回放和解释关键人物行动；
- AI 故障时核心玩法完整可用；
- 旧档迁移、导出和恢复可验证；
- 所有发布门禁有实际运行记录，不能只引用台账文字。

## 6. 第一条必须完整跑通的工程验收链

**科举空白开局 → 读书人与生活状态 → 报名/资格 → 考试场景 → NPC 自主行动 → 放榜 → 关系生成 → 人生分支 → 世界继续推进 → 存档/读档/回放。**

这条链是正式世界的第一个端到端证明，不是单页面验收。每一步都必须检查：

- 人物状态是否由统一 Person 模型承载；
- 时间和资源是否通过统一命令/时钟结算；
- 事实是否进入事件账本；
- 玩家认知是否只接收合法信息；
- NPC 是否按自己的目标行动；
- AI 是否只提出候选而不写事实；
- 失败路径是否可继续；
- 读档后状态、关系、认知和事件历史是否一致。

河工十日场景作为另一条中期压力测试链，待科举人生底座稳定后接入；不能把它当成新存档开局的替代品。

## 7. 全局验收门禁

每个模块都必须通过适用门禁：

1. **规则门禁：** 对应总纲条款明确；未决规则有阻断标记。
2. **数据门禁：** 唯一权威来源；状态变更有事件或开局来源。
3. **因果门禁：** 命令、成本、时间、事件顺序、结果和认知链一致。
4. **幂等门禁：** 重放、重试、重复点击不会重复结算。
5. **AI 门禁：** 不合规候选零写入；离线可玩；不泄漏未知信息。
6. **生命周期门禁：** 出生/衰老/疾病/死亡/继承保留连续性。
7. **自由度门禁：** 成功、失败、拒绝、不行动和改途都能继续产生有意义的人生。
8. **UI 门禁：** 只读投影、正式命令入口、三档截图、焦点/触控/减少动效/打印回归。
9. **存档门禁：** 版本迁移、重建、导出、恢复和旧档兼容。
10. **证据门禁：** 测试输出、CI run、截图、人工眼审、差异和台账相互一致。

任何阶段都不得用“页面看起来完成”“AI 对话能聊”“单测通过”代替整条因果链验收。

## 11. 完成定义

本计划不是“所有功能做完”的承诺，而是把整个项目拆成有依赖、有证据、有退出条件的施工路径。最终完成必须同时满足：

- 正式世界拥有统一、持续、可回放的时间与事件系统；
- 所有人物都有完整生命状态和历史，不因模拟层级而降格；
- 官员人生主轴完整，非仕途人生同样可持续；
- NPC 有自主目标与行动，世界不围绕玩家单点停摆；
- AI 动态生成候选，但规则与事件账本始终掌握事实权；
- 前端只是正式世界的可理解投影，不是系统上限；
- 关键选择、失败、关系、经济、制度与身后处理均有因果证据；
- 自动测试、场景测试、视觉审查和存档回放均有实际证据。

**最终产品验收看“人生和世界是否真实连续地运行”，不看页面数量或代码行数。**
