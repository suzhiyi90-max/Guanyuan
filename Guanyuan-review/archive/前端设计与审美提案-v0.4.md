# 前端设计与审美提案 v0.4 · S-13 知府审查节点单

> 只写本节点；基线与决策记录见 v0.3，令牌与屏幕规格见 v0.2。
> 远端总纲已至 v0.8，本机仍无法拉取（直连与镜像均失败），本节点取自 v0.2 §6.12 与总纲 §6/§7 的既有条款，属 M1 硬指标。

## 节点目标

把「上面能卡我 但不能替我办」做成可操作的界面，而不是多读几份公文。

## 交付

1. **上宪来文叠层**：知府批（准 / 驳 / 查 / 饬 / 存，当前为「查」），批语「委员覆勘 料价再核」；来文原文、他知道什么（只依据呈文与册，不全知）、批语入卷。
2. **五动作卡**：批驳、委员覆勘、调卷传询、考语、揭参压案。每张明示三行——他能做 / 不能做 / 改变什么（工期、定性、料源、责任、考语）。
3. **两类真实生效**（M1 底线）：
   - 委员覆勘：耗 1 时段；得「委员勘报」E-008；事务由「办」转「验」；定性由「尚待定性」转为「闸底淘空已复核」；对账随之改写。
   - 调卷传询：耗 1 时段；调得「河厅旧修造册」E-004；并置页新增一条待核问题；主簿口径进入「被调卷」状态。
4. **揭参**：高风险，二次确认；留揭参稿，风评与考语措辞改变。
5. **压案**：不耗银不耗时，留把柄；三行日志「有人在传」改写，对账记一笔「改」。
6. **权限边界写死在界面**：不能批银、不能改委河厅、不能直接革职；每项显示缺什么、需谁批。
7. **入口**：第一日暮起，今日案头出现「上宪来文」待决卡；事务页侧栏同入；已读未办有红记。

## 不做

- 不做大计三年周期、不做升迁牌局、不做知府全知视角、不做 AI 生成批语。
- 不新增美术依赖；批红公文以纸墨朱印完成。

## 验收

- 覆勘与调卷两类动作各产生可见的县级变量变化（阶段 / 证据 / 定性 / 考语），不是新增阅读量。
- 揭参必须二次确认；压案必有把柄留痕。
- 已行动作显示「已行」且不可重复耗时段；刷新后保留。
- `npm run build` 通过；`npm run smoke` 全绿，新增覆勘与调卷断言。
