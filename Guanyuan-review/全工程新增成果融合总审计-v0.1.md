## 5. 嘉靖二年历史基准专项融合

### 5.1 已明确的项目决定

- 时代基准：明世宗嘉靖二年，即 1523 年。
- 禁止虚构县名、府州县建置、县治、河段、闸座、官署和职官名称。
- 史料不足时明确标记待考，不以合理想象补齐。
- 不得把清代河厅、清代知县体系、康熙以后夫役制度、雍正财政阈值或清代司法程序直接套入 1523 年。

### 5.2 PR #83 可用研究成果

PR #83 已提供以下重要线索：

- 南直隶徐州为直隶州，不得称“徐州府”。
- 沛县为目前研究中证据较强的候选区域，但尚不能仅凭候选研究稿宣布玩家县域已冻结。
- 嘉靖二年《明世宗实录》卷三十二记载沛县以南湖陵城至黄家八闸受黄水涌入、闸座淹没，以及裁革沽头主事和相关闸官、每闸留夫看守等事项。
- 《重修大明会典》卷一百九十八可用于核对河务机构调整，但须区分议准设置、实际到任与日常管辖。
- 后出方志与汇编资料不能未经年代校验就作为 1523 年现场地图。
- 嘉靖二十一/二十二年城垣信息不得倒填到嘉靖二年。
- 徐州卫、徐州左卫、州县民政和漕运闸务必须分开建模。
- 相关闸名、异文、距离、县界归属与日常权限链仍有待逐项核实。

### 5.3 M1 规则迁移四分法

每一条现行清代规则必须标注以下一种处置：

- **保留结构**：通用程序结构可保留，但必须证明不依赖清代制度前提。
- **明代重建**：制度主体、职官、审批链、财政来源、夫役制度或法律依据需要按 1523 年重新考证。
- **明确排除**：年代晚于 1523 年，或与明代建置不符，不进入本场景。
- **待考隔离**：史料不足，不进入硬规则、不触发模拟、不作为玩家可见确定事实。

任何清代数值阈值、官职权限或河务制度，在完成迁移审计前不得作为嘉靖二年规则运行。

## 6. 设计与技术边界映射

### 6.1 领域边界

沿用 PR #75 的模块责任矩阵作为治理底稿，并补充以下融合约束：

- Person/LifeState 是人物统一底座；职业路径不能分裂成平行人物系统。
- Identity、Role/Status、Office、Authority 必须分离；人物身份、官职、品级、爵封和权限不可相互冒充。
- Household、Relation、Organization、Membership 是不同关系对象；空白个人关系矩阵不等于没有有来源的家庭事实。
- SocialAction、Contact、InformationFlow、Claim、Evidence、Belief、Verification 不得合并成单一“关系/消息状态”。
- Economy 的所有权、保管权、控制权、处置权必须分开；W6 已实现的保管转移不得改变所有权。
- AI 只产生候选或表达；只有确定性校验和正式事件提交才能改变世界事实。
- UI/人物档案/日志/地图是玩家认知视图，不得直读世界聚合或创建第二事实源。

### 6.2 W5 内核冻结保护

继续保护以下边界：

- EventLedger 追加式事实账本；
- Registry / Schema 校验；
- Reducer 的确定性状态投影；
- Replay 从 genesis 重建；
- Save/Restore、IndexedDB 与存档兼容；
- Runtime Orchestrator 的恢复和提交语义；
- AI 候选不直接写事实。

新功能必须通过已定义的应用命令端口和事件提交路径接入。不得以“统一架构”为由整体替换 W5。

- WorldAggregate 只读投影与跨域引用校验；
- application command/query/snapshot ports；
- 世界时间推进事件与适配器；
- 复合任务源与调度预算；
- 人物生命状态事实与维护任务源；
- 资产保管权转移；
- 显式 L0–L3 模拟策略门控；
- 玩家命令授权策略 resolver；
- 可信 principal 解析与提交 actor 绑定；
- 异步授权前请求快照；后续审查又补齐嵌套 JSON payload 的递归快照与冻结，防止调用方在授权查询期间改变最终提交内容。最新 W6 head `a8d7a865` 的 Push 与 PR 两条完整 CI 均通过，包括授权门控、身份/授权契约、生产构建、Playwright smoke/archive regression 和截图上传。
