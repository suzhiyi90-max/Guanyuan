# 官员模拟器｜网页端生图美术资产生产标准

- **版本：** v0.1（2026-10-30）
- **状态：** 生产流程提案；待主设计人确认样板后冻结 Art Bible
- **适用范围：** M1 前端纵切片的背景、人物肖像、场景物件、文书纹理与 UI 装饰资产
- **权威关系：** 本文件是美术生产流程，不是玩法规则；审美方向以《前端设计与审美提案-v0.2.md》为准，规则以仓库根目录《设计总纲.md》v0.6.4 为准
- **工具假设：** 生图工具通过网页端人工操作；不假设有 API、批量任务、自动化下载、图层工程文件或可靠透明背景能力

---

## 0. 本轮生产原则

1. **先做可用素材，不先做海量素材。** M1 先满足首个河工场景和核心人物，不提前生产 M2/M3 内容。
2. **先冻结样板，再批量生成。** 先完成 1 张场景背景、1 张人物肖像、1 组文书/物件样板；主设计人确认后才扩展同类资产。
3. **图像不承载规则。** 图片不得烘焙按钮文字、数值、状态、导航、可变文案或交互提示；这些全部由前端排版。
4. **一图一职责。** 背景、人物、物件、纹理分开生成与交付；不得把人物、文字、按钮和场景合成一张无法拆分的图。
5. **来源可追溯。** 每张资产记录生成工具、日期、提示词、参考图来源、授权/使用条款、版本、审核人和用途。
6. **原图不覆盖。** 原始下载件只读保存；裁切、去背、调色、压缩均生成新版本并记录派生关系。
7. **不把生成结果当史实。** 服饰、建筑、器物、官署空间均需按晚清州县语境审查；不确定的细节先留白，不以 AI 猜测补齐。

## 1. 视觉基线（继承现行前端提案）

- 题材：架空晚清州县；不是皇宫、王府、仙侠门派或泛古风拼贴。
- 材质：纸、墨、朱印、木、布；强调旧、克制、有人使用过。
- 主色：纸白/米纸、墨色、少量朱砂、黛蓝/青灰；暖金只作极少量分隔，不做土豪金大面积装饰。
- 构图：文书与交互信息优先；背景不能抢文字；人物不能遮挡主要操作区。
- 禁区：龙椅、金龙凤纹、黄瓦宫殿、飞鱼服/锦衣卫、日式障子门、民国霓虹、现代办公用品、游戏 HUD、按钮、文字、水印、签名、伪汉字。
- 统一要求：同一场景的光向、季节、时间、天气、建筑材质和人物服饰保持一致；避免每张图像来自不同画风。

## 3. 各类资产技术规格

> 以下为交付基准建议值；前端负责人确认实际容器比例后，允许按同一构图规则调整，不允许无记录地随意拉伸。

### 3.1 场景背景 BG

- 推荐母版：横向 16:9，建议 2560×1440；若工具仅支持较低分辨率，先生成最大可用尺寸，再做质量检查，禁止用低清图直接放大冒充母版。
- 格式：PNG 优先；JPEG 可作为压缩预览，不作为唯一母版。
- 不透明背景；不需要透明通道。
- 必须提供：完整画面、无文字/无 UI、明确前中远景、至少一个可供人物站立的区域。
- 构图需标注安全区：标题/顶栏区、主内容区、人物站位区、底部操作区；不得把重要物件放在前端文字覆盖位置。
- 不要在背景中生成清晰可读的书本文字、牌匾文字、印章文字；需要文字时由前端或单独文书资产处理。

### 3.2 人物肖像 POR

- 推荐母版：竖向 2:3 或 3:4；建议 1536×2304 或工具可用的最大竖图尺寸。
- 构图：半身/胸像；头顶、肩部、衣袖完整，不贴边，不切头；人物居中但预留裁切余量。
- 背景：纯净低干扰背景；优先透明 PNG。若网页工具不能稳定输出 alpha，使用纯色/浅灰绿幕式背景并单独去背，保留原图。
- 同一角色所有变体必须锁定年龄感、脸型、发式、胡须、服装、配饰和色调；禁止不同批次换脸。
- 表情变体只改变表情/视线/轻微姿态，不改变人物身份与服装。
- 服饰必须符合角色身份、品级与场景；不能把所有男性都做成官服，商人、士绅、工头需有身份区分。

### 3.3 物件 OBJ / 纹理 TEX

- 物件建议 1:1 或 4:3；主体完整，边缘留白 8–12%。
- 透明底 PNG 优先；不支持透明时使用纯色背景并记录后期去背。
- 纹理建议 1:1、无缝平铺；对比度低，不得干扰文字阅读。
- 印章、文书等若需真实汉字，禁止依赖生图工具生成；交由排版/矢量方式后制。

## 4. 网页端生图工具适配检查

每个新工具/账号首次使用前，人工完成以下检查，并把结果登记在工具卡中：

| 检查项 | 怎么验证 | 结果记录 |
|---|---|---|
| 最大输出尺寸 | 查看可选比例/尺寸，生成一张测试图 | 实际像素，不记录营销宣传值 |
| 画幅比例 | 分别生成 16:9、2:3 测试 | 是否裁切、是否改变构图 |
| 透明背景 | 生成单物件并下载 PNG，检查 alpha 通道 | 真透明 / 假棋盘格 / 不支持 |
| 参考图一致性 | 同一角色上传参考图，生成 2 次 | 脸、衣服、年龄是否稳定 |
| 局部编辑 | 对测试图修改一个局部 | 是否保留其余区域 |
| 下载方式 | 下载原始文件并查看文件属性 | 是否被二次压缩、是否带水印 |
| 商用/公开使用条款 | 查看当前服务条款、生成内容许可与输入图权利要求 | 记录链接、日期、限制 |
| 隐私与保留 | 查看上传图是否用于训练/公开图库 | 禁止上传未获授权的人像/私密材料 |
| 版本复现 | 保存提示词、参考图、参数与结果编号 | 能否复现近似结果 |

**适配结论只允许三种：** 可直接生产 / 限制条件下可生产 / 不适合本项目。未检查授权和下载质量前，不进入正式资产包。

## 5. 标准生产流水线（网页端人工操作）

```
需求卡 → 风格/史实审查 → 提示词卡 → 网页端生成
      → 候选筛选 → 主设计人选样 → 后期处理
      → 技术检查 → 资产登记 → 前端接收
      → 页面截图验收 → 版本冻结/回滚
```

### Gate 0：需求卡

每张图先回答：资产 ID、对应屏幕/场景、叙事用途、是否影响交互、画幅、主体、必须出现、禁止出现、留白位置、交付格式、验收人。缺任何关键项，不生成。

### Gate 1：风格与史实审查

对照《前端设计与审美提案》3.1–3.4；先确认时代、身份、空间、材质和色彩。史实未确认的细节标记“艺术化待审”，不写成史实定论。

### Gate 2：提示词卡

每个资产建立独立提示词卡，包含：
- 正向提示词：主体、时代、身份、空间、材质、光线、镜头、构图、安全区、画幅。
- 负向提示词：文字、伪汉字、水印、Logo、现代物件、错误服饰、错时代建筑、额外肢体、重复人物、UI、按钮、边框。
- 参考图：只使用有权使用的图；记录来源和许可。
- 固定项与可变项分开；角色身份特征写入固定项，不在每次生成时自由改写。

### Gate 3：网页端生成

- 每个资产先生成 2–4 张候选，不用一次生成几十张。
- 每轮只改变一个变量（构图/光线/服饰/背景），避免无法判断改进原因。
- 保存网页任务链接或任务编号、完整提示词、参考图、生成时间、下载原件。
- 不把网页预览截图当交付原图；必须下载原始文件。

### Gate 4：候选筛选

先做硬淘汰：错时代/错身份、文字乱码、水印、明显结构错误、主体被裁切、留白不足、画风不一致、授权不明。通过后再按构图、材质、光线、可用性评分。

### Gate 5：主设计人选样与风格冻结

P0 样板至少包含 BG-001、POR-001、OBJ-001。三类样板通过后，冻结基础风格卡（色调、光向、笔触/写实度、镜头、材质、背景复杂度）；后续资产偏离样板必须解释，不得自行另起风格。

### Gate 6：后期处理

允许：裁切、缩放、去背、轻微色彩统一、清理瑕疵、压缩派生。
不允许：擅自改角色身份、服饰制度、关键场景结构；不允许把文字/按钮烘焙进图；不覆盖原始母版。
所有处理输出新文件并记录工具、操作者、日期和操作。

### Gate 7：技术验收

逐项检查：
- 文件能正常打开；尺寸、比例、格式正确。
- 透明资产确有 alpha 通道；棋盘格不是图像内容。
- 边缘无白边/黑边/残影；缩放后不糊、不锯齿。
- 背景没有伪文字、标志、水印、错误器物。
- 与同组资产光向、色调、比例一致。
- 在真实前端容器中预览，不只看单张大图。

### Gate 8：资产登记与交付

通过验收后才进入正式资产目录；保留原件、生产件、预览件和 manifest。未通过资产放入 rejected，不允许前端引用。

### Gate 9：页面验收与回滚

前端接入后检查桌面/移动裁切、遮挡、文本对比度、加载体积、首屏性能。若资产导致构图或可读性失败，回退到上一版；不得用 CSS 叠加大量补丁掩盖素材问题。

## 6. 提示词模板

### 6.1 场景背景模板

> 架空晚清州县，具体空间：[县衙签押房/黄河堤岸/夜间书房]。场景主体：[明确建筑与物件]。材质：[旧木、米纸、灰砖、素布、河泥]。时间天气：[明确]。镜头：[平视/略俯视/广角建立镜头]。画面比例 16:9，横向环境概念图，真实空间结构，克制的历史题材美术，低饱和纸墨色调，柔和自然光/明确单一光源。画面[左/右/中央]预留干净安全区供游戏 UI 排版；前景/中景/远景层次清楚；无人物（如需人物另做独立图层）。不要文字、伪汉字、牌匾字、水印、Logo、UI、按钮、边框、现代物件、宫殿、龙纹、日式建筑、民国元素。

### 6.2 人物肖像模板

> 单人角色肖像：[角色身份]，架空晚清州县背景，[年龄段/体态/身份特征]，[符合身份的服饰、发式、配饰]。半身像，竖向 2:3，人物完整不贴边，正面或轻微 3/4 视角，表情：[克制/谨慎/疲惫/精明]，背景简洁低对比，统一柔和侧光，纸墨低饱和色调，历史写实插画风格。必须保持角色可识别特征；不出现其他人物、文字、水印、Logo、UI、现代物件、错误官服、戏服化夸张装饰。透明背景优先；若不支持则使用单色干净背景。

### 6.3 物件模板

> 单件物品：[账册/封套/算盘/印章/河工工具]，架空晚清州县日常使用状态，材质与磨损真实，主体完整，居中，边缘留白，柔和统一光线，透明背景 PNG 优先。物件表面不得生成可读文字、数字、印文、Logo、水印；需要文字后期排版。

## 7. 命名、目录与版本

建议正式资产目录：

```
art/
  source/                 # 网页端下载的原始母版，只读
  production/
    backgrounds/
    portraits/
    objects/
    textures/
  preview/                # 联系表/缩略图
  rejected/               # 淘汰样本及原因
  manifests/
    art-assets.csv
    prompt-cards/
  style/
    art-bible-v0.1.md
```

命名格式：

`[类型]-[编号]_[简短语义]_v[主版本].[扩展名]`

示例：
- `BG-001_yamen-desk_v1.png`
- `POR-001_county-magistrate_v1.png`
- `OBJ-001_account-book_v1.png`

禁止使用“最终版.png”“新图2.png”“真的最终.png”等不可追溯名称。角色肖像如有表情变体，使用 `POR-001_EXPR-neutral_v1.png`。

## 9. 验收评分与淘汰条件

每项 1–5 分；P0 资产平均 ≥4，且无硬性淘汰项才可批准。

| 维度 | 5 分标准 |
|---|---|
| 题材准确 | 一眼符合架空晚清州县身份与空间 |
| 构图可用 | 主体完整，安全区满足真实 UI 排版 |
| 风格一致 | 与已冻结样板的色调、光向、材质一致 |
| 细节质量 | 无明显结构错误、伪文字、水印、伪影 |
| 技术质量 | 分辨率、格式、透明边缘、文件大小合格 |
| 可维护性 | 有源文件、提示词、许可记录、版本关系 |

**硬性拒收：** 授权不明；含水印/Logo；生成可读性伪文字；错误时代/身份；透明底实际为棋盘格；主体裁切不可修；与样板明显不一致；前端容器中影响正文阅读。

## 10. 明日前端交接包

前端开始前必须收到：

1. 《前端设计与审美提案-v0.2.md》及本文件；
2. S-01/S-02/S-03/S-04 的页面范围和对应规则来源；

5. Manifest 与缺失项列表；
6. 资产使用方式：背景 cover/contain、人物裁切锚点、透明图层层级、移动端替代裁切；
7. 前端截图验收清单：桌面/移动、窄屏、文字覆盖、人物遮挡、加载体积、缺图回退。

**前端不得自行补画、重绘、用文字模拟图像资产，或把未审资产当正式素材。** 若缺资产，按 manifest 标记占位并列为阻塞项。

## 11. 本轮执行顺序

1. 明确网页生图工具名称与当前可用模式，完成第 4 节适配检查。
2. 先产出 BG-001 / POR-001 / OBJ-001 三张样板候选。
3. 主设计人审样，冻结 Art Bible v0.1。
4. 再批量生产其余 P0 背景和六名核心人物。
5. 完成去背/裁切/统一色调与技术 QA。
6. 生成 manifest 与前端交接包。
7. 前端接入后进行真实容器截图验收；不通过则回退素材版本。
