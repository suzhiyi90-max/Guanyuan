# 人物详情全貌档案面板设计 v0.1

> **项目：**《观远》古代官员与官场社会模拟器  
> **设计状态：** 用户已确认的界面设计基线；待后续前端施工  
> **归属：** 人物系统 / S-03 人物与人情  
> **权威关系：** 本文件规定人物详情的展示结构与交互边界；人物事实、规则、权限、认知和数值仍以仓库根目录《设计总纲.md》及对应领域模块为准。本文件不创建第二套人物数据或规则。

---

## 一、设计定位

人物详情是玩家在任意可查看人物身上点击「查看人物」后打开的**完整人物档案**。它回答：这个人是谁、处于什么身份与处境；他有什么能力、性格、身体状态和现实资源；他与哪些人、组织、派系存在关系；他正在追求什么、计划什么、最近做了什么；玩家与他之间积累了什么关系、恩怨与共同经历；玩家目前已经掌握了关于他的哪些信息、误判、秘密和把柄；他的履历、政绩、过失与相关历史记录是什么。

**产品定位：玩家认知视角下的实时人物全貌。** 它是理解、查看、分析和追溯人物的档案入口，不是人物属性卡、收藏卡，也不是人物互动菜单。

## 二、已确认的设计裁决

| 项目 | 确认方案 |
|---|---|
| 信息深度 | 展示玩家当前可认知的全部信息；不泄露玩家尚未知晓的客观事实 |
| 人物维度 | 身份履历、能力性格身体、亲属师生同年、派系利益政治立场、目标计划行动、玩家关系恩怨、信息认知误判、已知秘密把柄、财政产业社会资源、历史事件功过与公文记录 |
| 信息组织 | **综合主页 + 深入子页**；主页总览，模块点击后进入详情 |
| 视觉重心 | **人物肖像、身份信息、关键数据三者均衡** |
| 面板职责 | 查看、分析、关系浏览、履历与证据查阅、近期行动与动向查看 |
| 互动边界 | 具体交谈、拜访、宴请、请托、委托、施压等互动，仍在当前场景及其对应互动入口中发起；不把这些操作塞进人物数据面板 |
| 来源展示 | 不要求每条信息都强制展示来源和可信度；不把面板做成逐条证据审查表。底层仍遵循既有认知、Exposure、Belief、Evidence 规则，只有在理解信息所必需时才做简洁状态提示 |

## 三、综合主页结构

主页采用均衡式档案布局。人物肖像承担识别与情绪连接；身份区提供人物定位；关键数据区帮助玩家快速判断人物当前状况。主页不追求把所有细节挤在一屏，而是让玩家先形成整体判断，再按需深入。

### 3.1 顶部人物身份区

- 人物肖像 / 立绘，优先使用完整、可识别的人物形象。
- 姓名、字号、年龄（已知时）、籍贯、出身。
- 当前身份、官职、品级、任职机构；非官员人物显示其真实社会身份，不强行套官阶。
- 身份履历摘要：最重要的前职、科举/师承/家世信息（玩家已知部分）。
- 当前人物状态提示：在任、候补、离任、在场、外出、病休等，仅显示现有事实。

### 3.2 核心数据总览

采用紧凑、可读的卡片或数据带，不创造新数值：

- **能力：** 沿用现有人物能力维度与称号；不扩展成新的综合战力分。
- **性格与行为倾向：** 以既有性格标签、动机、恐惧和行为记录归纳；不得凭单次事件给人物贴永久标签。
- **身体状态：** 疲劳、健康、负荷、疾病或恢复状态，按既有状态投影。
- **政治与社会位置：** 派系/利益关联、政治立场、声望或风评标签；不同概念分开呈现，不合并成总影响力条。
- **目标与动向：** 当前主要目标、已知计划、最近行动和可观察的下一步安排。
- **玩家关系摘要：** 认可、信任、惧、欠、恩怨、承诺、共同经历等，保持方向性，不压缩成单一好感度。
- **资源摘要：** 玩家已知的俸禄、产业、资产、控制资源、人脉和可调动资源；明确人物所有、控制、经手与可支配不是同一概念。

主页模块建议按「身份 → 人物特征与状态 → 关系与政治位置 → 目标动向 → 玩家关系 → 资源与历史摘要」组织。桌面可采用肖像与数据并列的多栏布局；窄屏改为纵向分组，保持模块顺序与层级，不缩成不可读的密集表格。

## 四、深入子页结构

主页各模块点击后进入对应子页。子页共享人物标题栏与返回主页路径，避免用户在深层查阅后丢失当前人物上下文。

| 子页 | 内容范围 | 主要关联对象 |
|---|---|---|
| 1. 身份与履历 | 姓名字号、籍贯出身、科举、师承、亲属背景、任职机构、官职品级、任免迁转与履历时间轴 | 官制、仕途、科举、家族、师生 |
| 2. 能力、性格与身体 | 能力分项与称号、专业经验、性格与动机、恐惧、健康、疲劳、负荷、疾病与恢复 | 人物模型、成长、日程、身体状态 |
| 3. 人际关系网络 | 亲属、姻亲、师生、座师门生、同年、同僚、上下级、恩主门生、政敌、合作与债务关系；关系具有方向和类型 | 关系、人情、家族、科举、组织 |
| 4. 派系与政治关系 | 所属/关联派系、利益集团、政治立场、利益诉求、盟友与冲突、在组织中的位置 | 派系、组织、官僚层级、利益网络 |
| 5. 目标与行动 | 当前目标、计划、承诺、正在执行的事务、近期行动、已知未来安排与行动变化 | Goal、Intention、Task、世界时间、日程 |
| 6. 玩家关系 | 玩家与该人物之间的关系变化、恩情、亏欠、承诺、共同经历、冲突、可知把柄与关系节点 | Bonds、Debt、Secret、Hook、事件记录 |
| 7. 信息与秘密 | 玩家已掌握的事实、听闻、推测、误判、传闻、已发现秘密和把柄；未知信息不展示内容 | Exposure、Belief、Memory、Rumor、Evidence |
| 8. 财政、产业与社会资源 | 已知俸禄、田产、商号、借贷、产业权益、资金与物资、可调用人手、社会资源及控制关系 | 财政、复式账本、产业、资源、社会网络 |
| 9. 历史事件与公文档案 | 重要事件、政绩、过失、处分、奖叙、奏折/批文/禀帖/契约/账册等相关记录；按时间与主题查阅 | Event、Evidence、Document、案卷、考成、行状 |

子页可按信息量分节、折叠和筛选。不要为了填满页面而制造空字段；没有可展示事实时使用克制的空态，明确「尚无可查记录」或直接留白，不生成虚构内容。

## 五、信息边界与认知呈现

### 5.1 玩家认知是唯一展示门槛

- 只展示玩家当前已接触、已掌握或有依据形成的认知。
- 人物客观存在但玩家未接触的秘密、资产、关系、计划，不得因打开档案而自动曝光。
- 玩家知道某人「可能在谋划某事」，可以展示为未证实的线索；不能把推测改写成确定事实。
- 人物自己知道的内容，不等于玩家知道；NPC 的 knows / believes 不得直接泄漏到玩家面板。
- 关系图谱只能显示玩家当前认知到的关系边；未发现的关联不应被全知式补齐。

### 5.2 不强制逐条展示来源与可信度

本次明确不采用「每条字段都附来源、时间、置信度」的审查台账式布局。来源、证据与认知状态仍保留在底层领域模型中，供规则、调查和证据链使用；UI 仅在必要时以轻量方式区分：

- 已掌握 / 已确认；
- 听闻 / 传闻；
- 怀疑 / 推测；
- 尚未证实。

这些标识是信息表达，不构成新的可信度数值，也不要求所有条目都出现。已经发现的秘密可以展示其内容；尚未知晓的秘密不显示内容，不以「隐藏属性列表」提示玩家存在多少未知秘密。

## 六、系统联结与数据权威

人物面板是统一人物模型的只读投影，不是独立业务系统。每个模块应复用对应领域的权威数据，不复制维护另一套状态。

| 面板信息 | 权威系统 / 既有对象 | 联结约束 |
|---|---|---|
| 身份、履历、官职品级 | identity、office、官制与仕途记录 | 人物与职位分离；官职变化来自任免事件，不由面板编辑 |
| 能力、性格、动机、身体 | capability、needs、fear、state、身体与日程规则 | 不创建人物总评分；身体状态随时间和行动变化 |
| 亲属、师生、同年、上下级 | 关系图谱、家族、科举、师承、组织任职 | 关系有类型、方向、时间与状态；不合并为单一好感值 |
| 派系与利益 | 组织、派系、利益集团、政治立场与事件关系 | 不能把关系推定为正式成员身份；不能把立场等同忠诚数值 |
| 目标、计划、行动 | Goal、Intention、Task、NPC 日程与世界时间 | 面板展示已知投影；不直接推进时间、不触发 NPC 行动 |
| 玩家关系与恩怨 | bonds、Debt、Secret、Hook、Exposure、事件流 | 双向关系分别记录；不因查看而改变关系，不可凭空生成筹码 |
| 信息、误判与秘密 | Exposure、Belief、Memory、Rumor、Evidence | 不跨人物共享知识；UI 不把传闻改成事实，不泄漏 NPC 私有认知 |
| 财政、产业、社会资源 | 复式财政账本、私囊/公帑、产业权益、资源与委托记录 | 区分所有权、控制权、经手权、调度权和可用额度；不把账面金额当可自由调用现金 |
| 历史事件、公文、功过 | Event、Evidence、Document、考成、行状 | 历史记录追加，不覆盖；人物档案只聚合引用，不复制生成第二份历史 |

### 6.1 跨系统一致性要求

1. **单一事实源：** 人物面板只消费统一人物模型与领域状态的只读投影；禁止在 UI 层另算能力、关系、资产、派系或事件结果。
2. **同源一致：** 人物详情、场景名帖、关系谱、人情簿、文书档案、账房、考语和行状对同一人物事实必须一致；展示粒度可以不同，事实不能冲突。
3. **时间一致：** 近期行动、身体状态、职位、资源和关系变化随同一世界时钟更新；打开面板本身是零费读取，不推进时段。
4. **权限一致：** 面板查看不赋予玩家任免、调度、查封、签押等权限；身份权利束仍由规则层决定。
5. **认知一致：** 任何入口打开同一人物，都遵守同一玩家认知边界；不得出现「场景中未知、详情页却可见」的穿透。
6. **证据一致：** 历史档案链接回已有公文、账册、证据和事件；面板不复制证据，不替代案卷或调查系统。
7. **资源一致：** 人物名下资产不自动等于玩家可支配资源；调用资源仍走既有协商、委托、授权和财政流程。
8. **AI 边界：** AI 可帮助归纳已知信息、润色人物描述，但不能生成新的事实、秘密、关系或行动状态；模型输出不得直接写入业务状态。
9. **不建平行系统：** 不新增人物总战力、综合忠诚、总影响力、万能好感、隐藏属性揭示、关系刷取或人物档案专属资源。

## 七、面板与场景互动的边界

人物详情只承担「看、读、查、跳转」：查看人物关系网与关联人物；查看近期行动、已知未来动向；查看身份履历、历史事件、公文与证据；在人物之间、关系节点、事件记录和公文档案之间导航；对可查记录进行筛选、折叠和时间排序。

人物详情**不提供**交谈、试探、宴请、送礼、书信、请托、委托、举荐、拉拢、施压、保护、赏罚等实际互动按钮。玩家要互动时，应返回当前场景，在场人物名帖或对应场景锚点中，按人物在场、渠道、身份权力、时间、资源与关系条件发起。

人物详情可以保留「返回当前场景」或「回到该人物所在场景」的导航，但不能把导航按钮伪装成互动，也不能因返回场景而自动执行动作。

## 八、视觉与交互基线

### 8.1 视觉语言

采用明亮、精致的明清官府档案美学：米白宣纸、浅月灰为主底色；灰青、淡墨、浅木色为辅助；朱砂用于印记、重要状态和已确认事项；鎏金只作少量身份与装饰点缀。人物立绘清晰、有层次，避免肖像压缩成小头像。信息区使用档案页、题签、印记、细线分隔和克制的纸张层次。

避免黑金暗黑风、厚重金属边框、过度发光、廉价古风手游按钮和大面积装饰挤占信息。

### 8.2 信息密度

- 主页让玩家快速识别「是谁、有什么本事、处于什么状态、与我什么关系、最近在做什么」。
- 复杂信息进入子页，不在主页堆长文本。
- 数值、标签、关系图、时间轴、资源清单混合表达；每种信息采用适合它的可读形式。
- 关系图谱突出关系类型和人物节点，不做装饰性蜘蛛网；节点可点击跳转人物主页。
- 历史事件采用时间轴/档案列表；公文和证据打开既有阅览表面。
- 不只用颜色表达状态；重要状态同时有文字、图形或形状标记。

### 8.3 交互品质

- 主页与子页之间有清楚的层级、返回路径和当前人物标识。
- 关系节点、事件条目、公文引用可点击，跳转后可回到原人物与原位置。
- 长列表支持按时间、关系类型、事件类别筛选；折叠状态不丢失当前阅读上下文。
- 悬停提示只补充解释，不藏关键事实；触屏设备通过点击或长按获得等价信息。
- 键盘焦点顺序清晰，支持 Escape/返回；焦点不能在关闭子页后丢失。
- 动效克制、短促、服务于层级变化；不让动画改变时间、状态或业务结果。

## 九、阶段与范围控制

- **设计阶段：** 本文件锁定信息架构、展示边界、系统联结和视觉方向。
- **后续施工：** 在现有 S-03 / PersonPanel / 人情模块内演进；是否需要子页路由、叠层或局部状态，由前端架构审查后决定。不得先验新增一级入口、OverlayId、存档字段或平行业务状态。
- **M1 范围：** 先保证人物主页的身份、能力/性格/身体、三问与玩家关系摘要、已知信息、近期行动及可回查关联；完整派系、资产产业、长期行动时间线和全量档案按既有阶段与数据可用性渐进开放。不得为了面板看起来「全」而提前模拟尚未启用的系统。
- **M2/M3：** 随派系、家族、完整产业、跨局履历等领域系统成熟，再开放对应子页深度；空态不等于伪造数据。
- **施工前置：** 先核对现有 S-03 和 PersonPanel 结构，复用已有入口、状态、数据模型与导航；禁止推倒重做或用静态图片替代可交互 UI。

## 十、验收标准

| 维度 | 验收要求 |
|---|---|
| 定位 | 玩家能明确区分「查看人物档案」与「在场景中和人物互动」 |
| 信息深度 | 展示玩家当前可认知的全部相关信息；不泄漏未知事实 |
| 主页可读 | 3 秒内能识别人物身份、核心能力/特征、当前状态、玩家关系与近期动向 |
| 子页完整 | 十类人物维度均有明确归属，不重复造数 |
| 关系联结 | 关系节点能跳转人物，方向/类型正确；未知关系不显示 |
| 事实一致 | 同一人物在名帖、人物详情、关系谱、人情簿、案卷、账房和行状中的事实一致 |
| 证据回查 | 相关公文、事件、证据跳转到既有阅览面，不复制档案 |
| 时间边界 | 打开、翻页、筛选、返回均不推进世界时间 |
| 互动边界 | 详情页没有实际行动入口；互动仍从当前场景发起 |
| 视觉 | 肖像、身份、数据三者均衡；明亮档案美学；窄屏可读 |
| 无虚构 | 空字段不编造；AI 不得将推断写成事实 |
| 无平行系统 | 不新增人物总分、总忠诚、好感度或独立资源系统 |
