# 人物分类与社会关系网络系统设计规范 v0.1

> 状态：设计候选稿，等待评审；不是代码实施说明，不改变当前运行版本。
> 权威关系：规则以仓库根目录《设计总纲.md》为准。本文件展开人物、身份、关系、组织、社交行为与信息传播；若与总纲冲突，以总纲为准。
> 目标：把人物从有限联系人名单提升为可扩展的社会实体网络，同时保持 M1 一县七人纵切片的范围纪律。


## 0. 核心裁决

1. **七人是首个验证场景的关键人物样本，不是世界人口上限，也不是人物分类总表。**
2. 人物分类不是单选枚举。一个人物可同时具有多个社会身份、制度身份、家庭出身、组织成员资格和当前处境。
3. 人物、身份、关系、组织、行动、信息认知是不同领域对象，不得压成一个人物标签或一个关系总分。
4. 人物关系允许多重、方向不对称、认知不对称和随时间变化；同一对人物可以同时有多条关系。
5. 人情债、信任、畏惧、名望、政治支持、合法性、利益依赖必须分开，不得合成为好感度/忠诚度。
6. 人物档案是认知范围内的只读视图；交往行为从场景、渠道或事务入口发起。
7. NPC 不只响应玩家；在可承受的模拟层级内，NPC 必须能够自主联系 NPC、与组织互动并改变关系。
8. AI 只负责意图理解、候选表达与叙事呈现；身份、关系、组织成员、消息送达和状态变化由确定性规则校验并写入。

## 0.1 社会关系驱动器：从空白人生持续生成

本系统的核心交付不是静态关系图，而是一个由事件驱动的**社会关系生成与演化引擎（Social World Driver）**。它负责让接入的 AI 在统一规则下，伴随玩家人生进程发现人物、形成接触、建立关系、加入组织、产生事件，并持续更新关系矩阵。

### 开局状态

- 玩家以初入科场的读书人身份开始，第一段可玩人生从科举流程启动；具体年龄、家世、籍贯、家境等由开局构筑或时代规则确定，不等于预先拥有社会关系。
- **玩家个人社会关系矩阵为空。** 不预置座师、同年、同窗、故交、盟友、政敌、门生、同僚或人情债；不得为了让界面有内容而塞入虚构联系人。
- “空白”指玩家尚未建立/获知的个人关系，不代表世界上不存在其他人、组织或历史。NPC 可以有自己的既往关系，但这些关系必须有独立来源、并受玩家认知隔离；不能直接当作玩家关系。
- 玩家在科举场景中第一次遇见、听闻、同场、同榜、受教、受荐的人，按事件逐步进入个人经历与社会网络。认识一个人、知道一个人的存在、与一个人形成关系，是不同状态。

### 驱动器职责

驱动器不是让 AI 自由编造人物关系，而是为 AI 提供受约束的世界运行接口。每次世界推进按以下顺序工作：

1. **读取上下文：** 当前时间、地点、玩家身份与状态、已发生事件、玩家已知信息、有效制度规则、活跃人物及其日程。
2. **生成候选：** AI 根据玩家行动、NPC 目标、制度流程和世界状态，提出可能出现的人物、接触、行动、回应、关系变化或新事件；候选必须说明动机、对象、渠道、时间、资源和依据。
3. **规则校验：** 确定性规则核对时代制度、人物身份、地点可达性、行动权限、关系形成条件、信息边界、时间成本、资源与因果前置条件。
4. **结算事件：** 合法候选进入事件排序与结算；不合法候选被拒绝、改为待定或给出替代路径。AI 不得越过此步直接写世界状态。
5. **提交事实：** 通过校验的结果生成唯一 Event ID，写入事件账本；人物、身份、关系、组织成员、Exposure、通信、义务和认知变化都必须引用该事件或既有来源。
6. **更新投影：** 从事件账本重建/更新玩家关系矩阵、人物档案、人情簿、组织成员表、人物行状和玩家认知视图。投影不是第二事实源。
7. **生成叙事：** AI 只根据本次事件结果与当前观察者可知信息，生成对话、场景描述、人物反应和日志；叙事不能反向创造未结算事实。

### 关系形成不是一个按钮，而是类型化规则

每种关系类型必须有自己的形成条件、证据要求、方向、有效期和终止条件。例如：

- **同年：** 同一科次、同一榜单的客观制度关系，在放榜事件确认后建立；但“同年”不等于彼此见过面、相互熟悉或互信。
- **座师/门生：** 必须由对应时代、科举层级和考官制度规则确认；只有正式师承事实成立后才建立，不能把所有考官都自动称为玩家座师。
- **同窗/同场：** 同场应试或同一书院只能先生成共同场景/Exposure；是否构成长期同窗关系，按持续共学、相互识别或明确设定判断。
- **师徒：** 需有授受行为、双方角色和时间范围；单次请教只形成一次互动事件，不自动成为师徒。
- **同僚/上下级：** 由实际任职、同署共事或正式委任事件建立，任职结束后保留历史并更新当前有效状态。
- **朋友/盟友/政敌：** 不能由一次对话、同榜、共同目标或 AI 文案直接生成；须有持续互动、承诺、共同利益/冲突和可追溯事件支撑。
- **亲属/婚姻：** 由家族履历、婚姻事件或开局明确设定建立，不得由模型随机配对后直接写入事实。
- **债务/恩情/把柄：** 必须有具体给予、受益、约定、见证或掌握秘密的事件，主体、标的、义务和偿还状态分开记录。

### 驱动器必须维护的状态层

1. **人物库：** 世界中已存在的人物实体与稳定 ID。
2. **玩家接触簿（Exposure）：** 听闻、见过、同场、交谈、书信往来、正式接触等经历，记录来源与深度。
3. **关系矩阵（Relation）：** 已确认、传闻、推测、争议、终止的类型化关系边；允许空矩阵。
4. **组织网络（Organization/Membership）：** 师门、同年网络、官署、家族、商帮等集体关系，不能用个人关系边冒充。
5. **认知矩阵（Knowledge/Belief）：** 每个人知道、相信、误信、怀疑和不知道什么；玩家视图只取玩家认知子集。
6. **事件账本（Event Ledger）：** 关系生成、变化、终止、人物加入世界、身份变化、通信和传播的唯一事实来源。

### 防止 AI 关系污染的硬约束

- AI 只能提交候选事件/状态变更请求；只有规则校验和事件提交器可以确认事实。
- 每条关系必须有 source_event_id 或可核查的开局来源；没有来源的边不得进入 confirmed。
- AI 不得为了对话自然而补写“早已相识”“曾经共事”“私下有交情”等过去事实。
- 不允许重复生成同一人物；人物实体需通过姓名/别名、履历、地点、时间和既有 ID 做实体消歧，合并也必须留事件。
- 相同事件重试必须幂等：不得重复增加人物、关系、债务、声誉、资源或时间。
- 关系矩阵为空是合法状态；人物数量少、关系稀疏或某类关系暂缺，不得触发模型自动补齐。
- AI 生成候选失败或超时，规则世界仍可通过模板/确定性流程推进；AI 不是世界状态的单点依赖。

### 人物生命周期

未进入世界 → 被听闻（Rumor/Awareness）→ 真实接触（Exposure）→ 相识（Recognized）→ 发生关系形成事件（Relation Formed）→ 持续交往/共事/组织成员变化 → 关系转化、疏远、终止或重新建立。

这些阶段不是必须线性经过：例如同榜关系可在放榜时成立，而双方尚未见面；一封书信可先建立接触，再在往复互动后形成私人关系。每次跃迁都必须有自己的事件和证据。

## 0.2 与全人物生命模拟系统的关系（v0.16）

本专项不是完整人物系统的上限。所有 Person 均受《世界生命与自由人生模拟系统设计规范-v0.1.md》约束，必须具有完整生命连续性与全人物状态域：生命、身体、心理、性格、能力、教育知识、身份资格、人生阶段、家庭亲属、关系、组织、经济、认知、目标计划、日程位置、名声评价、法律风险和物品生活。

社会关系只是人物状态域之一。关系生成、身份变化、家庭事件、疾病、衰老、死亡、迁徙、任免、破产和继承均由事件账本驱动；不能把人物只建模为玩家关系图中的节点。人物离开玩家活动圈后仍然存在，死亡后仍保留历史记录。

社会世界驱动器与全人物世界驱动器采用同一候选—规则校验—事件提交链：
1. AI 读取人物当前生命、身体、目标、家庭、认知、关系、组织、日程和世界规则；
2. AI 提出人物行动或事件候选；
3. 规则检查人物是否存活、是否可达、是否具备资格、是否有时间/资源、是否掌握必要信息；
4. 规则结算并提交唯一事件；
5. 人物、生命、关系、家庭、组织、经济、认知等状态由事件投影更新；
6. AI 只能基于提交事实和观察者认知生成叙事。

全人物统一模型不要求全人口逐时段执行完整大模型推理。L0 近场、L1 关系圈、L2 地域圈、L3 远端世界按精度分层；人物升降级必须继承历史与状态。预览 UI 只呈现玩家可知状态，不定义底层状态域和模拟规模。

## 1. 术语与对象边界

| 对象 | 回答的问题 | 不应承担的职责 |
|---|---|---|
| Person | 谁是这个独立的人？ | 不直接等同官职、职业、派系或好感 |
| Identity | 此人具有什么社会身份、职业或制度资格？ | 不代表此刻必然能行使某项权力 |
| Role / Status | 此人在当前时间、地点、场合处于什么角色/状态？ | 不覆盖其历史身份 |
| Relation | 两个人之间存在什么具体关系？ | 不以单一分数替代多条关系 |
| Organization | 哪些人围绕共同目标、规则或资源形成组织？ | 不等同松散的关系标签 |
| Membership | 某人在何时以何种身份加入组织？ | 不把成员身份自动推导为组织领导权 |
| SocialAction | 谁通过何种方式向谁做了什么？ | 不直接由叙事文本判定成功 |
| ContactChannel | 行动通过什么渠道到达目标？ | 不把发出等同送达或理解 |
| Information / Exposure | 谁知道什么、从何得知、相信到什么程度？ | 不全局广播 |
| SocialEvent | 哪个行动或变化形成了可追溯事实？ | 不覆盖历史记录 |

Person 是持续存在的个体；Identity 是可多选且有时效的身份声明；Role 是当前情境中的有效角色；Relation 是两人之间带类型的边；Organization 是具有边界和集体行动能力的实体。

## 2. 人物分类体系

### 2.1 五个分类轴

分类轴可以并存，不互斥；每个具体标签必须有定义、适用时代/地域、有效期、来源和是否可被玩家认知。

| 分类轴 | 典型类别 | 用途 |
|---|---|---|
| 社会身份/职业 | 官员、吏员、差役、幕友、士绅、读书人、商人、农户、佃户、地主、工匠、船户、医者、讼师、僧道、仆役、军人 | 描述谋生方式、社会位置与常见能力/资源 |
| 制度身份/资格 | 官职品级、科举功名、候补/在任/致仕、军籍/民籍等时代适用身份、机构任职资格 | 决定制度门槛、程序与法定权能 |
| 家庭/出身 | 宗族、嫡庶/亲疏、婚姻姻亲、家世、籍贯、师承出身 | 影响社会资本、义务、继承与声誉 |
| 组织/政治归属 | 衙门机构、家族、师门、同年网络、商帮、行会、乡约、地方团体、政治集团 | 描述集体利益、约束、协作和冲突 |
| 当前处境/社会角色 | 在任、候补、失势、被参、受审、避居、外出、病休、流亡、当事人、证人、调停者、代理人 | 决定当下可用行动、风险与场景表现 |

### 2.2 分类规则

- 一个 Person 可有多个标签，但每个标签必须注明分类轴，不能只存一个含混的 type。
- 区分事实身份、社会称谓、玩家推测和他人评价；称谓不等于制度资格。
- 身份有 valid_from、valid_to 或等价时态；身份变化新增历史，不覆盖既往记录。
- 同一身份可以有正式、非正式、名义、实际控制等不同状态；实际影响不得冒充法定权限。
- 身份影响互动门槛、称谓礼仪、可接触场所、资源可及性、风险和社会预期，但不能单独决定人物性格或行为。
- 不以身份类别预设善恶、忠奸、能力高低或必然立场。
- 历史人物和随机人物共用同一分类框架；历史原型不享有绕过规则的特权。

### 2.3 初期人物类别目录（开放字典）

首批字典至少覆盖：皇室/宗室与勋贵、中央官员、地方正印官、佐贰官、幕友、书吏、差役与门役、军官与兵丁、士绅与乡贤、科举士子、宗族成员、地主与佃户、农户、商人/牙人/行会成员、工匠与工头、船户/脚夫、医者、讼师、僧道、仆役/家人、妇女与家庭成员、无业游民及其他边缘处境人物。该目录是可扩展词表，不要求 M1 全部实现。

对历史语境敏感的身份（如良贱、籍贯、性别、年龄、科举资格、主仆关系）必须按具体时代和地域配置，不以现代职业分类简单套用。

### 2.4 M1 裁剪

M1 保留七人河工场景作为验证样本，并按需要出现正印官、佐贰、书办、差役/工头、士绅、粮商、专业人士等人物原型。不得把七人写成七种互斥类别，也不得为证明分类完整而扩张首局人口、UI 或随机事件。未启用类别只登记字典和接口，不生成假人物、假关系或空壳系统。

## 3. 人物关系模型

### 3.1 关系分类

| 关系族 | 关系类型示例 | 典型作用 |
|---|---|---|
| 血缘/宗族 | 父母子女、兄弟、叔侄、族亲、同宗 | 家族义务、互助、继承、族规 |
| 婚姻/姻亲 | 夫妻、岳婿、翁媳、姻亲 | 家庭联结、社会资本、利益协商 |
| 师承/学术 | 座师门生、师徒、同门、授业 | 举荐、提携、学术声望、门生网络 |
| 科举/地域 | 同年、同榜、同乡、同窗 | 交游、仕途协助、乡缘 |
| 官场/职务 | 上下级、同僚、属官、前任继任、会办关系 | 行政协作、责任、制约 |
| 政治/立场 | 盟友、对手、政敌、依附、竞争者、共同请托者 | 政治支持、对抗、风险 |
| 经济/契约 | 债权债务、合伙、雇佣、交易、担保、庇护/受庇护 | 资源交换、信用、依赖 |
| 私人交往 | 故交、至交、泛交、恩人、仇怨、失和 | 私人信任、情感、冲突 |
| 社会/地方 | 邻里、同行、会馆、乡约、共同社团 | 地方互助、舆论与社会动员 |
| 组织关联 | 同一组织成员、上下级成员、派驻/代表 | 集体协作与组织约束 |

关系类型词典可扩展，但每个类型必须说明是否有方向、是否可并存、是否需要证据、是否对称、是否有起止时间，以及它能影响哪些规则。

### 3.2 关系记录最小字段

每条关系至少包含：稳定唯一标识；from_person_id、to_person_id；relation_type；status（传闻/推测/确认/争议/失效）；valid_from、valid_to；形成或变化的事件来源；公开/私下/秘密程度；哪些人物知道或相信；可选的关系类型专属强度；可选的义务、契约或约定。

### 3.3 方向、不对称与多重性

- A 对 B 的信任、依赖、敬畏或评价不自动推出 B 对 A。
- 互为夫妻、同年等客观关系可以共享同一事实来源，但双方对其意义、感情和公开程度仍可不同。
- 同一对人物允许多条并存关系，例如同僚 + 同年 + 债务人 + 私交疏远。
- 关系边不等于关系双方都知情；秘密关系、单方认定和误认必须可表达。
- 关系变化通过事件追加；不得直接覆盖历史。结束关系应标记失效/终止并保留时间线。
- 关系强度不能取代关系性质；不得设计统一亲密度/好感度/忠诚度作为所有关系的裁判。

### 3.4 关系状态与可见性

事实状态（是否真实）、人物认知状态（谁知道/相信）、玩家展示状态（玩家能否看到）是三个不同维度。关系可真实存在但玩家未知；也可只有传闻或误判。展示时区分已确认、据称、推测、关系已断等，且不得展示超出玩家认知的信息。

## 4. 组织与集体行动

### 4.1 组织类型

家族/宗族、师门/门生网络、官僚机构、衙门内部职房、政治集团、商帮/行会/商号、乡约/保甲/地方社团、宗教团体、军队/营汛、临时协作团体。

### 4.2 组织最小模型

组织至少具有：组织 ID、名称、类型、目标/利益、有效期、活动地域、成员关系、领导/代表规则、资源、内部规则、公开程度、对外关系、历史事件。组织成员通过独立 Membership 记录，包含成员角色、加入/退出时间、加入依据、义务、权限和可见性。

### 4.3 组织不是标签

- 组织必须存在共同目标、规则、资源或集体行动能力中的至少两项。
- 同属某派不能自动推出所有成员互信、同意每项行动或无条件服从领袖。
- 组织内部可以有派别、竞争、背离、观望和退出。
- 组织与组织之间可合作、竞争、依附、冲突、互保或交易；关系同样要有来源和时间。
- 组织领导权、代表权、资源控制权与成员身份分开记录。
- 临时宴席、偶然同场或一次共同事件不自动形成组织。

### 4.4 与既有关系系统的分工

个人之间的亲属、师承、债务、私交由 Relation 表达；某人属于某家族/师门/衙门由 Membership 表达；组织间协作由组织关系或有来源的组织事件表达。避免用关系边重复模拟组织成员表，也避免组织标签代替具体人际关系。

## 5. 统一社交行为框架

### 5.1 社交动作族

1. 接触与引入：偶遇、拜见、登门、候见、引荐、递帖。
2. 沟通与探询：寒暄、问话、私谈、商议、辩论、书信、传话。
3. 关系经营：宴饮、馈赠、回礼、拜访、联络、结交、修复关系。
4. 请托与交换：求助、请托、举荐、担保、借贷、合作、回报、拒绝。
5. 权力与政治：劝说、协商、施压、召见、任用、弹劾、结盟、调停。
6. 冲突与破裂：质问、揭发、威胁、背叛、断交、追债、上控。
7. 组织行为：召集、议事、派遣代表、动员、分工、退出、解散。

这是一套规则动作词典，不是 UI 按钮清单。具体动作可由玩家自由表达，经意图解析映射到既有动作族，再由规则判断可执行性。

### 5.2 统一行动管线

意图 → 目标与对象识别 → 身份/权限/关系前置检查 → 场景与渠道选择 → 时间/资源/风险估算 → 目标人物认知与判断 → 回应（接受/拒绝/拖延/转交/条件接受/欺骗/未送达）→ 确定性结算 → 事件留痕 → 关系/义务/认知变化 → 信息传播与世界回声。

必须区分：玩家意图 ≠ 已发起行动；已发起 ≠ 渠道送达；已送达 ≠ 对方已读；已读 ≠ 对方理解；理解 ≠ 相信；相信 ≠ 同意；同意 ≠ 实际执行；执行 ≠ 达到预期结果。

### 5.3 统一判定

沿用总纲四段式互动判定与能/可/该身份权利束，不另建第二套成功率体系。判定至少考虑主体能力与资源、制度资格/授权、场景与对象、关系和承诺、目标人物自身目标/风险/认知、第三方见证与传播风险。三问继续作为人物判断界面，不折算成好感度。

### 5.4 结果类型

至少区分：成功；部分完成；附条件接受；拒绝；拖延；转交/引荐；误解；欺骗；未送达；被截获/泄露；行动无法发起。结果必须说明原因和后续可选路径，不允许 UI 把拒绝显示为成功。

## 6. 渠道、位置与远距通信

### 6.1 渠道类型

同场面对面、登门拜访、宴席/公共场合、私人书信、正式公务文书、差人/仆役传话、中间人引荐、商号/会馆网络、组织会议。渠道可按时代、地域、身份与世界状态启用，不假定现代即时通信。

### 6.2 渠道状态机

草拟 → 已交付/已发出 → 途中 → 已送达 → 已阅知 → 已理解（可选）→ 已回应 → 回复途中 → 回复送达。

旁路状态：未发出、拒收、地址不明、无人接收、延误、遗失、截获、转交、泄露、伪造。状态变化需有事件依据；不得用一个发送成功覆盖全流程。

### 6.3 成本与风险

成本包括时间、银钱、差遣资源、礼仪成本、机会成本；风险包括路途、门禁、身份不合、第三方旁听、截获、泄密、曲解、延误和中间人私利。成本和风险由具体渠道与情境决定，不为每次社交机械扣相同数值。

### 6.4 位置与认知

人物真实位置、玩家所知位置、消息中的声称位置分开。玩家不能因地图上有一个节点就知道人物当前所在；目标不在场时，应给出查找、预约、拜访或通信替代路径。

## 7. NPC 自主社交与社会模拟

### 7.1 决策输入

NPC 的社交行动由其当前目标、身份与处境、能力、资源、关系网络、组织成员义务、已知信息/信念、日程、位置、承诺、风险偏好共同约束。不得仅因玩家需要剧情就强迫 NPC 联系或配合。

### 7.2 自主行动类型

联系熟人、拜访、传信、求助、请托、回报、协商、交易、组织议事、拉拢、疏远、隐瞒、散布消息、调停、拒绝合作、退出组织。行动必须有动机、对象、渠道、成本、预期收益/风险与可观察后果。

### 7.3 模拟 LOD

- 近景/当前场景：具体到场景、在场者、对话与见证；严格结算时间和行动。
- 中景/同一县域：按日程、目标与关系触发可追溯的关键社交事件，不模拟每句对话。
- 远景/跨区域：只推进重要通信、组织决策、职位变动和有影响的事件；普通日常用抽象时间步进。
- LOD 只能降低表现细节，不得改变因果、公平性、资源成本和关键人物决策结果。

### 7.4 反玩家中心原则

玩家不行动时，NPC 仍可按自身目标行动；NPC 之间可产生合作、竞争、误解、交易和关系变化。自主行为不等于随机噪声：必须可追溯、可解释、受资源与认知约束，且不能无缘无故惩罚玩家。

## 8. 信息传播与社会回声

### 8.1 消息对象

消息至少记录来源人物/事件、内容事实引用、产生时间、传播渠道、接收者、送达/接收/理解/相信状态、保密等级、转述链、失真变体、可信依据和有效时效。

### 8.2 传播规则

- 消息沿真实接触、组织渠道、亲属/师承/交易关系或正式文书路径传播；关系边只是可达条件，不代表自动传播。
- 每次转述生成新的传播事件，保留上游来源，不覆盖原始消息。
- 传播可能延迟、遗漏、夸大、曲解、伪造或被有意隐瞒；变化必须有行动主体或机制解释。
- 接收者可不信、误信、暂存、核验或采取行动。
- 私密消息不得自动进入公共风评；公开行为也不等于全县所有人立即知晓。
- 传播到组织层面时，须说明由谁代表、通过何种会议/文书/成员渠道形成组织立场。

### 8.3 回声联动

消息被不同受众知晓后，可影响态度、行动、交易条件、组织决策、舆论、考语与政治风险；影响沿总纲 13.5 的曝光—解释—态度—行动—记录链运行。不得新建全局影响力数值。

## 9. 人物档案、关系视图与交互入口

### 9.1 三种不同视图

- 人物档案：以单个人物为中心，显示玩家已知的身份、履历、能力、关系、组织、目标、行动、资源、历史与证据；只读。
- 人情谱/人情簿：保留玩家中心视图，展示玩家与其他人的往来、债、把柄、礼簿和可追溯来源；不冒充全局关系网。
- 社会关系网络：新增全局（但受玩家认知过滤）关系探索视图，可从人物进入其已知关系，再进入关联人物档案；支持按关系族、组织、时间、地域过滤。未知关系不显示，传闻/推测须标注。

### 9.2 视图边界

视图不能写入关系、组织成员或消息事实；点击节点只导航。所有行动仍从当前场景、接触纸、事务或通信入口发起。视图不新增好感总分、忠诚总分、人物战力或关系评分。

### 9.3 人物信息呈现

人物主页显示最有用的当前身份和处境；深入子页展示完整的已知信息。多重身份按制度有效性、当前场景相关性和玩家认知排序，不用标签云淹没核心身份。关系列表同时标明关系类型、方向、状态与必要来源。

## 10. 数据契约草案

以下是逻辑字段建议，不是要求立即采用同名数据库表。应由现有 Person/Relation/Exposure/Event 模型审查后映射，避免平行 schema。

- Person：稳定 ID、姓名/称谓、基础属性、当前状态、来源。
- IdentityAssignment：person_id、axis、identity_code、valid_from/to、source_event_id、visibility、certainty。
- Relation：relation_id、from/to、type、status、valid_from/to、source_event_id、visibility。
- Organization：org_id、type、name、purpose、region、valid_from/to、resources、rules、visibility。
- Membership：org_id、person_id、role、valid_from/to、source_event_id、visibility、obligations。
- SocialAction：actor、target、intent、action_type、scene、channel、cost、risk、status、result_event_id。
- Contact：sender、recipient、channel、location/address knowledge、sent/delivered/read/replied timestamps、failure state。
- InformationFlow：message_id、source_event、sender、recipient、parent_message_id、channel、content_refs、distortion、belief_state、secrecy。
- 所有变化均通过事件追加；快照可重建，但不能成为第二权威源。

| 现有领域 | 关系 |

| 统一人物模型（总纲第 3 章） | Person 是唯一人物实体；身份与状态作为扩展维度 |

## 12. 分阶段实施与范围门槛

### 驱动器原型：先验证“从空白到关系生成”的完整链

在既有 M0 河工固定人物样本之外，增加一条独立的**人生开局纸面链**。河工七人是关系规则的压力测试夹具，不是新人生的初始存档；两种测试不得混用。

建议首条链：开局无玩家关系 → 入场应试 → 同场人物接触/听闻 → 考试结果 → 放榜 → 同榜人物关系生成 → 庆贺/拜见/引荐/落第后再应试等分支 → 真实交往 → 后续师承、举荐、任官与共事关系。每一步都由事件驱动，不保证玩家必然中举、必然结交或必然获荐。

驱动器每次运行必须产出：候选人物/行动、规则校验结果、事件 ID、关系矩阵差异、玩家认知差异、AI 叙事输入。没有状态变化时必须明确返回“本轮无关系变化”，不得补边。

### M0：纸面验证（零代码）

在原有七人河工场景中，增加关系网络视角：至少覆盖县丞、主簿、粮商、士绅、专家、工头之间的既有利益与协作关系。主持人必须能回答谁与谁是什么关系、谁知道、谁不知道、消息如何传到。测试玩家能否从关系中推断行动，而不是只记人物标签。

### M1：最小可玩纵切片

只实现支撑河工核心循环的少量身份、关系和渠道：现有七人及必要影子人物；亲属/师承/同年若未进入内容，不虚构；同场交谈、正式公务联系、必要的远距书信/中间人可按场景启用；NPC 自主行动至少覆盖既有 Intention 表中的人与人互动；消息传播至少有一条可回查链。

### M2：社会网络扩展

扩展家族、师门、同年、商帮、地方团体和跨区域通信；开放关系网络浏览、组织成员与组织间行动；引入更丰富的人物来源、身份变化和社会流动。

### M3：长期社会模拟

扩大到府省、中央与多任期人生；模拟组织兴衰、代际关系、名声与政治网络的长期演变。不得在 M1 提前实现全社会人口级模拟。

## 13. 验收用例

| ID | 场景 | 通过标准 |
|---|---|---|
| PS-01 | 一人多身份 | 同一人物可同时拥有官职、师承、家族、组织身份；身份有时效且保留历史 |
| PS-02 | 身份与权力 | 社会身份不能自动获得法定权限；有效职位/授权仍由权力系统判定 |
| PS-03 | 关系不对称 | A 信任 B 不自动推导 B 信任 A |
| PS-04 | 多重关系 | 同一对人物同时存在同僚、同年、债务等关系且互不覆盖 |
| PS-05 | 未知关系 | 玩家未知的关系不出现在档案、关系图和 AI 提示上下文 |
| PS-06 | 关系来源 | 关系变化可追溯到事件、文书或明确来源 |
| PS-07 | 组织成员 | 加入/退出组织有时间、角色和依据；不自动等于领导权 |
| PS-08 | 组织内部冲突 | 同一组织成员可立场不同、拒绝行动或退出 |
| PS-09 | 同场交谈 | 旁听者、场合、身份和关系会影响回应与传播 |
| PS-10 | 远距通信 | 发出、送达、阅读、理解、回应分阶段，不可瞬时成功 |
| PS-11 | 中间人 | 中间人可拒绝、延迟、泄露或曲解，结果可追溯 |
| PS-12 | NPC-NPC 自主社交 | 玩家未介入时，NPC 按自身目标联系其他 NPC 并形成事件 |
| PS-13 | 信息传播 | 消息只沿有依据的渠道传播，转述保留来源与失真链 |
| PS-14 | 玩家认知隔离 | NPC 私有信息不泄漏；推测与事实区分 |
| PS-15 | 世界持续推进 | 玩家不主动社交时，世界仍按日程和目标推进，不无故惩罚 |
| PS-16 | UI 分工 | 人物档案、人情谱、全局关系网络三种视图职责不同，不出现重复业务入口 |
| PS-17 | 事实一致性 | 同一关系在人物档案、组织页、人情谱、行状和事件记录中来源一致 |
| PS-18 | 规则确定性 | AI 文本不能直接创建身份、关系、组织成员或消息送达事实 |
| PS-19 | 空白开局 | 新存档玩家关系矩阵为空；无预置座师、同年、同僚、盟友、政敌或人情债 |
| PS-20 | 科举生成关系 | 同榜关系只在放榜事实成立后生成；同榜不自动生成相识、互信或私人交往 |
| PS-21 | 人物生成幂等 | 同一考试/事件重放不会重复创建人物、关系或经历 |
| PS-22 | AI 候选与事实分离 | AI 可以提出人物/关系候选，但未通过规则校验和事件提交不得进入事实矩阵 |
| PS-23 | 关系空缺合法 | 没有发生关系形成事件时矩阵保持空或稀疏，不自动补齐关系 |
| PS-24 | 人生持续生成 | 科举、师承、举荐、任官、共事、交易、婚姻、冲突等不同事件可按各自条件增量扩展人物与关系 |
| PS-25 | 玩家认知隔离 | NPC 既有关系不自动暴露给玩家；必须通过接触、传播、文书或调查获得 |
| PS-26 | 全人物状态域 | 玩家、官员、百姓、家庭成员和远端 NPC 共用统一生命与状态模型；未知/不适用/未生成可区分 |
| PS-27 | 年龄连续性 | 年龄由出生时间和世界时间推导；不得按回合任意加龄 |
| PS-28 | 死亡留史 | 人物死亡后停止普通日程，但人物、关系史、文书和事件记录不删除 |
| PS-29 | 身后处理分离 | 死亡后职位、债务、产业、亲属扶养、组织成员和承诺分别按规则处理，不整体复制 |
| PS-30 | 身体状态一致 | NPC 疾病、疲劳、衰老会影响日程、行动与工作能力，不只对玩家生效 |
| PS-31 | 自由人生退路 | 落第、离任、不入仕、破产或疾病后仍存在可继续的人生行动，不强制回归仕途 |
| PS-32 | LOD 连续性 | 人物在 L0–L3 模拟层级间切换时，状态与历史连续，不重新随机生成 |
| PS-33 | AI 事实边界 | AI 不得直接决定生死、疾病、婚姻、继承、任免等不可逆事实；必须通过规则与事件提交 |

## 14. 未决事项

1. 具体朝代/年份下身份字典的粒度与史料来源。
2. 关系类型是否需要强度字段，以及哪些关系允许量化。
3. 组织的最小成员数、形成条件与解散条件。
