## 3. 前端图位

### 3.1 场景背景

`app/src/sceneArt.ts` 的 `ScenePlateId` 与 `scenePlates` 已预留：

- `exam-registration-yard`：科举报名与候场院落
- `exam-hall`：科举考场
- `audience-hall`：正式拜谒厅堂

这三项使用 `ScenePlate` 背景层，遵循现有图片适配、加载状态、署名和空白回退。不得把人物、榜文、文字或 UI 烘焙进背景。

### 3.2 独立道具 / 装裱叠层

`sceneObjectAssets` 是独立透明资产注册表，不得作为整幅背景使用：

- `exam-results-board-frame`：放榜文书装裱层，`contain`，比例 2:3；中央空白榜纸由前端动态排版。
- `exam-desk`：考生桌案前景道具，`contain`，比例 4:3；必须有真实 Alpha 通道。
- `court-gavel`：惊堂木前景道具，`contain`，比例 3:2；必须有真实 Alpha 通道。

图位先行不代表功能场景已实现。正式科举与拜谒 UI 施工时再将这些图位放入明确的场景层级；不得在没有玩家流程的情况下把静态展示误报成可玩功能。

## 4. 白底道具自动分离记录

用户明确要求优先由工具处理，而不是因生图工具无法直接输出透明背景就放弃资源。本轮对两件用户原图执行自动前景分割，未重绘、未手工描边、未改变主体造型。

### 4.1 考生桌案（34444.png）

- 输入：1536×1152 RGB，白色背景。
- 工具流程：OpenCV GrabCut 前景分割；保留面积超过 90 像素的连通区域，避免遗漏笔架、桌腿和围屏小构件；闭合微小孔洞并轻微羽化轮廓；放入 1600×1200 RGBA 画布。
- 保留策略：桌面白色宣纸属于道具内部，必须保留；桌腿下原图蓝灰色接触阴影保留，不应误删。
- 交付：`exam-desk.png`（透明母版 1600×1200）；`exam-desk.webp`（运行版 900×675）。
- 复核：棋盘格预览检查通过，桌面、围屏、笔架、砚台、墨锭、宣纸及桌腿完整，白色背景已移除。

### 4.2 惊堂木（34448.png）

- 输入：1536×1024 RGB，白色背景；画风与项目工笔淡彩场景相容。
- 工具流程：OpenCV GrabCut 前景分割；保留最大主体连通域；闭合微小孔洞并轻微羽化轮廓；按原比例置于 1500×1000 RGBA 画布。
- 交付：`court-gavel.png`（透明母版 1500×1000）；`court-gavel.webp`（运行版 900×600）。
- 复核：棋盘格预览检查通过，木纹、雕花和外轮廓完整，白色底板已移除。
- 原版 `34447.png` 不再使用；新图 `34448.png` 取代旧图。无需再次生图。

### 4.3 自动分离限制

本次是基于原图与背景色差进行的自动分割，不等于无损的源文件 Alpha。两件图像都已做可视化边缘检查；若之后在深色或高对比背景下发现浅色边缘，应对局部透明边缘做针对性去白边处理，不得重画主体。

本轮资源包：`FE-170-art-assets-for-repo-validated.zip`，含四张场景背景、两张透明 WebP 运行图、两张透明 PNG 母版和两张道具原始图。该包已于 2026-11-17 解压、逐项校验并入库，提交 `3641a02`：10 个文件的 git blob SHA 与本地文件逐字节一致，目标路径入库前均为空、无覆盖冲突。

## 5. 后续接入验收

二进制已入库。以下逐项验收中，第 1 项（路径与大小）已完成；第 2–8 项需运行环境，尚未执行：

1. 文件路径和大小与台账相符，Git LFS / 仓库体积策略符合项目约定。
2. 浏览器能从 `/assets/<filename>` 读取；不得只在开发机可见。
3. 背景使用 `cover` 语义，分别核对桌面、平板和窄屏构图，不裁掉院门、号舍通道或拜谒行礼空间。
4. 透明道具使用 `contain` 语义，实际检查 Alpha 边缘、抗锯齿、阴影和缩放。
5. 放榜框内的榜文由 DOM/前端排版绘制，不在图中生成字；桌案内的空白纸同样由前端呈现后续内容。
6. 保留用户源图；若另有 WebP/JPEG 优化版，必须同时记录源图与衍生文件、转换参数和质量检查。
7. 图像接入不改已有交互节奏、键盘操作、焦点管理和 reduced-motion 行为。
8. 场景页面真正接通后，再做 1440、1024、390 三档截图回归。
