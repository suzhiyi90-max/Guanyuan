## 3. 前端图位

### 3.1 场景背景

`app/src/sceneArt.ts` 的 `ScenePlateId` 与 `scenePlates` 已预留：

- `exam-registration-yard`：科举报名与候场院落
- `exam-hall`：科举考场
- `audience-hall`：正式拜谒厅堂

这三项使用 `ScenePlate` 背景层，遵循现有图片适配、加载状态、署名和空白回退。不得把人物、榜文、文字或 UI 烘焙进背景。

### 3.2 独立道具 / 装裱叠层

`sceneObjectAssets` 是独立透明资产注册表，不得作为整幅背景使用：

- `exam-results-board-frame`：放榜文书装裱层，`contain`，比例 2:3；中央空白榜纸由前端动态排版。
- `exam-desk`：考生桌案前景道具，`contain`，比例 4:3；必须有真实 Alpha 通道。
- `court-gavel`：惊堂木前景道具，`contain`，比例 3:2；必须有真实 Alpha 通道。

图位先行不代表功能场景已实现。正式科举与拜谒 UI 施工时再将这些图位放入明确的场景层级；不得在没有玩家流程的情况下把静态展示误报成可玩功能。

## 4. 两项返修描述词

### 4.1 考生桌案：补真正的透明背景

优先使用上传的 `34444.png` 作为唯一参考图，保持主体不变：

> 以用户提供的桌案图为唯一造型参考，保持木桌、围屏、笔架、砚台、墨锭与空白宣纸的造型、比例、位置、色彩和材质完全一致。只将外围白色摄影背景及白色地面干净分离为真正的透明背景；主体边缘、细木纹、纸张、砚台和自然接触阴影完整保留，不重绘、不新增、不删除、不改色。四周保留约4%安全边距，主体完整不裁切。输出带真实 Alpha 通道的 RGBA PNG，4:3，建议 1600×1200。禁止白底、灰格假透明、黑底、文字、水印和 UI。

### 4.2 惊堂木：统一画风

> 清代州县衙门案前使用的单件惊堂木，扁厚、方正的硬木拍板，略带长期使用后圆润的棱角与细微磨损，清楚表现顶部平面和正面厚度；三分之四侧前方视角，主体完整居中。画风必须与项目中的古代县学、县衙场景一致：工笔淡彩、绢本旧画、细腻手绘木纹、低饱和赭石与深木褐、柔和自然光。禁止写实 3D 渲染、塑料高光、黑色摄影棚背景。背景必须是真透明 Alpha 通道，保留极轻微自然接触阴影但不带底座或桌面。不要锤柄、不要第二件物体、不要人物、文字、印章、UI、边框或水印。透明 RGBA PNG，3:2，建议 1500×1000。

## 5. 后续接入验收

二进制文件入库后必须逐项确认：

1. 文件路径和大小与台账相符，Git LFS / 仓库体积策略符合项目约定。
2. 浏览器能从 `/assets/<filename>` 读取；不得只在开发机可见。
3. 背景使用 `cover` 语义，分别核对桌面、平板和窄屏构图，不裁掉院门、号舍通道或拜谒行礼空间。
4. 透明道具使用 `contain` 语义，实际检查 Alpha 边缘、抗锯齿、阴影和缩放。
5. 放榜框内的榜文由 DOM/前端排版绘制，不在图中生成字；桌案内的空白纸同样由前端呈现后续内容。
6. 保留用户源图；若另有 WebP/JPEG 优化版，必须同时记录源图与衍生文件、转换参数和质量检查。
7. 图像接入不改已有交互节奏、键盘操作、焦点管理和 reduced-motion 行为。
8. 场景页面真正接通后，再做 1440、1024、390 三档截图回归。
